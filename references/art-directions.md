# 美术方向库（按内容选，不固定一种风格）

来源：Anthropic/Claude 公开设计 token（designlang / awesome-design-md 抓取）、Apple Human Interface Guidelines、
`op7418/guizang-product-video-skill`、`whyubel1eve/promo-film-skill`。
**原则：方向由内容决定，不由作者偏好决定。**

---

## 一、两个底层原则（先记这两条，比任何配色都重要）

1. **负空间优先**（Apple HIG）：留白不是"没东西"，它带来平静、让重点可辨认。
→ 先考虑用空白区分组，再按内容决定是否需要框、线或底色；复杂画面也可以有清晰秩序。
→ 同类元素的间距应有可理解的关系；不强制对称或要求所有场次使用相同起点。
2. **让颜色简化，而不是装饰**（Apple HIG + Claude 不设第四种表面色）：
   → 初稿可从一个主要强调色开始，其余退后；数据分类等内容需要多色时，以区分关系和可读性为准。
   → 画布、卡片和深色内容面按实际需要取舍，不为了数量机械增删。

---

## 二、方向 A：暖纸编辑部（默认，适合讲解 / 知识 / 心理 / 人文）

出处：Claude / Anthropic 品牌系统（token 级）。

| 角色 | 值 | 说明 |
|---|---|---|
| 画布 | `#FAF9F5` | 暖白，**刻意不是纯白**（纯白显廉价、刺眼） |
| 墨 | `#141413` | 近黑，用于标题与正文 |
| 次墨 | `#5E5D59` | 次级文字 |
| 三级 | `#87867F` | 脚注、来源、页码 |
| 强调 | `#D97757`（珊瑚） | 唯一"说话"的颜色，用于关键词/重点数字 |
| 柔强调 | `#F5E3C7`（琥珀） | 高亮底色，不用于文字 |
| 描边 | `#E8E6DC` / `#F0EEE6` | 极淡，**能用留白就不用描边** |
| 卡面 | `#FFFFFF` | 只在需要"纸片浮起"时用 |
| 深面 | `#181715` | 代码块 / 终端窗口 |

排版纪律：
- 标题用衬线（宋体），**负字距**；正文用无衬线，**行高 1.6**（书感，不是仪表盘的 1.35）。
- 字号阶梯少而大跨度：大标题 → 小标题 → 正文 → 标签，**最多三档同屏**。
- 标签/眉标用大写或加字距（0.12em）来区分，不靠加粗。
- 圆角：卡 16–24，小块 8–12。（圆角不统一 = 不高级，比配色更致命）

适合：机制讲解、心理、人文、教程、访谈提炼。
不适合：需要"硬核科技感"的产品发布、数据密集的对比。

## 三、方向 B：暗色舞台（适合产品 / 工具 / 发布 / 性能对比）

| 角色 | 值 |
|---|---|
| 舞台 | `#0E1512` → `#16211A` 渐变 |
| 主体 | 银白 `#E9EDEA`，文字纯白 |
| 强调 | 荧光绿 `#7BE3A4` 或品牌亮色，**加性发光** |
| 深卡 | `#0F1A13`（代码/面板） |
| 描边 | `rgba(255,255,255,.08)` |

可选手法（来自 guizang `fx-lab`，已移植进 `FX`）：粒子汇聚 `streaksInto`、字符场 `glyphField`、
发光地平线 `horizon`、环绕 `orbit`。只在帮助讲述或建立焦点时使用；暗色场也可以安静静止，不为颜色添加运动。
适合：产品发布、性能对比、开发者工具、数据可视化。

---

## 四、方向 C：纪实纸本（适合新闻整理 / 事实核查 / 争议话题）

| 角色 | 值 |
|---|---|
| 画布 | `#F4F1EA`（略黄，像旧报纸） |
| 墨 | `#1A1A18` |
| 强调 | `#B4471F`（砖红，用于"注意/存疑"） |
| 辅助 | `#4A5240`（橄榄，用于"已核实"） |

纪律：结构与来源必须可见——引用原句用**引号+缩进**，不美化；证据不足处打**「待核」标记**（本 harness 已支持）。
适合：事实核查、争议话题、多来源对比。

---

## 五、方向选择表（先问内容，再选方向）

| 内容特征 | 选 |
|---|---|
| 讲机制 / 心理 / 人文 / 教程；观众要"读懂" | **A 暖纸编辑部** |
| 讲产品 / 工具 / 性能 / 版本更新；观众要"惊艳" | **B 暗色舞台** |
| 讲事实 / 争议 / 多方说法；观众要"可信" | **C 纪实纸本** |
| 数据对比为主 | A 或 B + 条形/表格（数字用等宽字体，**同类元素同字号**） |

混合时先明确主体方向，再检视借用元素是否帮助理解；不要只为增加变化混搭。多个强调色或组件样式可以有明确分工，但不应争夺焦点、破坏可读性。

---

## 六、落地方式

```bash
node vh.mjs theme --list          # 看有哪些方向
node vh.mjs theme warm-paper      # 应用到当前项目（改 engine.tpl.html 的 :root，先备份）
node vh.mjs theme dark-stage
node vh.mjs theme documentary
```

应用后需要 `node vh.mjs build` 重新生成 `scene.html` 才生效；场景代码不用改（全部读 CSS 变量）。
`vh jitter` 与 `vh stills` 用来验收：改配色后仍应零抖动、且静帧要看一遍对比度是否够。
