# 画面质量手册 —— 从归藏 / 言溪两个 promo skill 提炼，适配本 harness

两份参考：`op7418/guizang-product-video-skill`（真实组件 + GSAP/Three.js + fx-lab 手法库）
与 `whyubel1eve/promo-film-skill`（Remotion，全面片=一份代码，每帧是全局帧号的纯函数）。
第二条与本 harness 的引擎哲学完全一致；下面是把它的硬约束翻译到「`renderAt(t)` 纯函数引擎」上的做法。

## 一、三条会毁掉整支片子的坑（先记这三条）

### 1. 停死原则（唯一「时间轴上看不出」的坑）
每帧位移 < 0.02px 的「缓慢运动」必须删。理由：字每帧按新的亚像素边界重新光栅化，
单帧挑不出毛病，连起来是**每个字在微微发抖**（"有时候抖"最难查——因为抖动取决于
该场是否漏了保持点）。

本引擎的做法：
- 运镜/推近用 `FX.dolly(el, {from, dur, k, x, y})`——`dur` 结束后**停死**，不再逐帧写 transform；
- 想要画面「活着」，靠入场动画和内容变化，不靠看不到的缓慢缩放；
- 全片跑 `node vh.mjs jitter`：对每场中点两帧做逐像素 PSNR，非 `inf` 就是漏了保持点。

### 2. 一套颜色、一套字体、一条缓动
颜色只从 `:root` 的品牌色板取（var()），字体只用引擎的字号阶梯（--fs-*），
缓动全片只允许一条幂曲线（`FX.eOut/eInOut`，指数统一 3）。混三条缓动 = 观众读到
「三只手」，不是一个产品的性格。

### 3. 摄影机没停稳，文案不进场
开场走位的 0.6s 里不要让文字同时入场——观众的眼睛正在追画面，读不进去。
`FX.dolly(...)` 返回的 `moving` 归零之前，让 `pop/l1.set(...)` 的进度参数从 0.15 之后才开始。

## 二、可注入的画面资产（`vh enhance`）

```bash
node vh.mjs enhance --dir <项目>            # 注入 fx 手法库到 engine.tpl.html（幂等、先备份）
node vh.mjs build --dir <项目>              # 通过编排器重新生成并登记构建基线
```

| 助手 | 用途 | 纪律 |
|---|---|---|
| `FX.fxCanvas(root, {fps, draw})` | 确定性画布层（粒子/网格/波形） | 每帧整块重画 = t 的纯函数；粒子 30fps、颗粒 20fps |
| `FX.grain(ctx, t)` | 纸感颗粒 | 20fps：三帧换一格。60fps 颗粒读出来是"沙沙抖" |
| `FX.breathe(ctx, {...})` | 无边缘光斑呼吸 | 允许 ≤0.1px/帧 慢漂——那是"活着"，不是"在动" |
| `FX.dolly(el, {...})` | 微运镜（推近/平移） | 停死；终值固定，不逐帧重算 |
| `FX.camBlur(moving, arrive)` | 运动模糊 | 停稳时恰好 0 且退回 `none`（`blur(0px)` ≠ `none`，会常驻滤镜层恒糊） |
| `FX.mulberry(seed)` | 确定性随机 | 勿用 `Math.random`——破坏逐帧可复现 |

## 三、节奏与收口

- **节拍为内容服务**：条件、变化、结果不必被强塞进每场；讲解需要阅读时允许更长的静止，强调与休止都可以有意义。
- **动作之后留足阅读时间**，不规定全片统一的收口秒数；静帧外用 preview 核对运动过程、落点和场尾。
- **首帧即完整画面**（平台抓第一帧当缩略图）：开场段落的完成态要先立住，再开始动。

## 四、验收清单（发布前逐条过）

1. `node vh.mjs jitter` —— 全部 PSNR = inf
2. `node vh.mjs stills` —— 分镜页毎场一帧，逐一对照脚本：能看出"条件→变化→结果"
3. preview 里静音看一遍：**关掉旁白画面自己讲不听的话**——字幕在的话够不够
4. 字号阶梯：一屏最多 3 档；hero 一屏一个
5. 片内数字与 claims.json 对得上（讲解型）；版本号、体积与真实产品一致（产品型）
6. 全片只有一套缓动/色板（`grep -c "eOut\|eInOut" scenes.src.js`，多套别名 = 违规）
7. 收口：每场 end-0.4s 画面已稳

## 五、什么叫「看起来贵」

同一对象需要连续观察时，可以保留主体，让取景和文案交接；需要比较、切换材料或交代时间时，直切也可能更清楚。不是镜头越少越高级。

本引擎当前是「逐场独立构图 + 交叉淡入」，要往这个方向走：
把相邻两场写成**同一主体的不同取景**（同一套构图在 addScene 里平移/缩放复用），
淡入退化为"文案交接"。这不是硬规则，是可选的高级路线——先保证 1–4 条的完成度。

## 六、新项目的默认视觉基线

默认模板应给作者一个可替换的**观看顺序**，而不是一排白底卡片：

1. **主张留白**：用一个判断和一条必要限定建立焦点；背景只提供轻微空间感。
2. **关系演示**：把条件、对象和结果放进同一张关系图，让分流、汇合、替换或对照本身成为画面。
3. **深色收束**：只在结论、门槛或聚焦观察时切入高反差场，作为节拍变化，不作为“高级感”滤镜。

这不是三场结构配额。题材需要真实截图、照片、图表或持续一镜时，优先让真实对象决定构图。卡片仅用于有边界的独立对象；能用留白、线条、位置和尺寸表达的关系，不再包一层卡片。
