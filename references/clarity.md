# 解释质量规范（Agent Explanation Protocol · 本 harness 的创作与验收基线）

来源：用户提出的「把事情讲清楚」协议，本文件把它落成本 harness 的创作约束与可执行检查（`vh clarity`）。
它管的是**内容层**：事实对不对由 claims 管，画面好不好由 quality.md 管，**讲没讲清楚由本文件管**。

本仓库统一使用 `vh.mjs` 入口；本仓库政策优先于共享 skill 中旧的强制审稿路径。新项目不自动启用或调用独立模型审稿，脚本提交、改稿、换来源或续跑不得重新开启；`review_content` / `content-review --independent` 仅用户明确主动选用时使用。可选审稿缺失、待审或返修不阻塞正常制作。历史项目已明确启用 `required=true` 的合同保留，除非用户明确要求关闭，不自动修改旧片。事实核证、讲述自查、技术/媒体/资源质检及人工发布审阅仍保留；未审不伪造 pass，实际试听状态如实记录。

## 0. 定义

**把事情讲清楚** = 让一个原本不理解这件事的人，能沿一条**连续**的认知路径，建立**正确**的认识。

四条等式化的否定（每条都对应一类真实事故）：

| 不是 | 反例 |
|---|---|
| 说清楚了 ≠ 理解了 | 术语都对，观众仍问「什么意思」 |
| 内容正确 ≠ 解释充分 | 结论正确，但缺中间机制 |
| 详细 ≠ 清楚 | 说了十分钟前提，没一句落到对象 |
| 用了术语 ≠ 解释了机制 | 「用 checkpoint 就能避免破坏项目」 |

**最典型的病灶**：解释者脑中有完整结构（背景→对象→条件→机制→结果 + 经验/判断规则/例外），
实际只说了其中一小部分 —— 观众必须自己补全，补不上就断裂。

## 1. Tacit Knowledge（隐性知识）是核心，不是补充

隐性知识 = 解释者默认「理所当然」因而没说出口的那部分：
默认前提、行业惯例、经验判断线索、隐含步骤、例外情况、适用范围与局限。

**判定方法（必须逐条走）**：拿到一句给 Agent/观众的指令或结论，问
「要正确执行/理解这句话，我还必须已经知道什么才不用猜？」——列出来的就是缺失项。

**示例（本 harness 自身）**
> 原句：在修改项目之前创建 Checkpoint，避免破坏项目。

缺：什么叫破坏（删功能/改错配置/引入过不了测试的代码）；Checkpoint 具体存什么（Git 提交已跟踪的代码与配置）；
为什么能降风险（可恢复）；何时恢复（改完发现问题）；边界（Git 提交**撤不回**数据库写入、外部 API 副作用，
这些副作用要另建保护）；它的目标不是「绝对安全」而是「降低不可恢复的损失」。

**另一类隐性知识**：专家自己也说不清的判断力（设计师一眼看出页面不协调）。
这类不能靠「写得详细点」解决，只能靠**样本 + 对比 + 判断线索 + 反馈**逐步提取；
材料不足时**明确写出缺口**，不许编造专家经验。

## 2. 六项能力（检查清单，不是文章章节）

1. **对象指认**：正在讨论什么、具体指向什么；「这个 / 系统 / 能力」必须有确定含义。
2. **背景补全**：为什么会有这个问题、当前发生了什么、理解它需要哪些前置知识。
3. **关系与机制展开**：不只说 A 导致 B，要说中间发生了什么、在什么条件下成立。
4. **隐性知识提取**：默认前提、行业惯例、经验判断、隐含步骤、未说出口的规则。
5. **具体化与边界**：具体场景/例子/反例；讲清什么时候适用、什么时候不适用。
6. **理解验证**：能复述、能区分相似概念、能独立应用 —— 不是「读着顺」。

## 3. 知识依赖闭合（Knowledge Dependency Closure）

> 本 harness 的工作概念，非标准学术术语。

- 每个关键结论都有**前置知识**。识别依赖，检查接收者是否具备；不具备就向前补一级。
- 每个会改变比较、推荐或行动的结论，都要能从**编号旁白**回指到「依据 → 中间变化/判断规则 → 结论」。同场的标题、画面、术语表、审稿人的解释不算中间步骤。
- **停止条件**：接收者已具备理解与使用当前内容所需的知识 —— 不再往下解释。
  （所以「讲清楚」不是无限展开，而是按接收者的认知起点，构建一条没有关键跳步的路径。）
- 与本 harness 已有机制的对应关系：
  - `references/explain.md` 的「概念台阶」= 依赖闭合的人工版本；
  - `vh clarity` 的术语-定义检查 = 依赖闭合的机器版本；
  - `脚本.md` 每场的 `← 依赖：…` 行 = 依赖图的显式声明。

## 4. 质量约束

准确 ≠ 清楚；详细 ≠ 清楚；通俗 ≠ 清楚。
禁止：术语堆砌代替解释；从抽象结论直接跳到抽象结论；把该解释的东西预设为已知。
必须区分：**事实 / 推断 / 假设 / 经验规则 / 建议**。
**最终标准：不是你说完了，而是接收者建立了完成当前目标所需的理解。**

### 文章改编：先跟住原文，再设计讲法

**复盘案例**：一篇讨论 RAG 与信息获取方式变化的文章，原本先交代争论和应用现状，再讲 grep 的例子。改编时却用支付日志开场，并把局部实验表格放大成重点，观众因此不知道主题和主线。上一轮还把原文中口径已写清的 41% 误说成混淆。静帧、字幕和数字对账的机器检查未能发现这些问题；不能据此宣称讲清楚或原文有错。

1. 写稿前读完整篇文章，在 `方案.md` 记下原文的主题、主要问题、核心判断、论述顺序和必要限定；用几行映射说明视频每个主要段落承接原文哪部分。文章主线为默认路径，用户另有要求时以用户要求为准。
2. 为口播可以压缩重复、补解释，但不应把局部例子或一张数据表变成新主线，以致丢掉原文的判断。若确有必要大幅调整论证或主题，说明调整及原因；有歧义时先确认。
3. 开场让不懂的人知道**在讲什么、为什么要讲、接下来要回答什么**。例子出场时要能回答「它为什么与这个主题有关」；听众尚不知道主题时，不靠孤立日志、代码或数字制造悬念。
4. 自查：不看标题，只读开头能否知道主题？看完能否说出每段怎样推进原文主问题？数字、术语或图表是否挤掉了必要解释？这些问题要实际核对旁白，不由关键词、得分或句数代判，也不要求自动调用模型审稿；文字自查不冒充实际试听。
5. 认为原文写错时，引用它的准确原句，再逐项核对来源的对象、问题、基数、时间和单位；无法确认就标待核，不把自己的推测说成原文错误。

讲法参考（以下为读过的文字材料，不等于已观看完整视频）：

- [3Blue1Brown：But what is a Neural Network?](https://www.3blue1brown.com/lessons/neural-networks)：围绕识别手写数字的明确任务，先解释输入和输出，再逐步展开神经元与层。可借鉴的是例子与主问题的关系，不照搬表达或动画。
- [StatQuest 作者 Josh Starmer 的访谈](https://opensource.posit.co/resources/videos/2026-01-19_teaching-out-loud-and-becoming-statquest-josh-starmer-data-science-hangout/)：他描述用最简单但仍能体现方法用途的例子，逐步展示过程；可借鉴这一取舍，不用减少关键机制冒充通俗。

### 先通旁白：不让画面替讲述补台阶

克苏鲁与默会知识这次制作的教训：直接宣称两个领域“同一个结构”，没有先交代两边的对象、各自怎样发生、究竟哪一步相似；后来虽增加故事，用户仍反馈跳过逻辑、听不明白。增加场景数量或解释结论，并不能补上缺失的推导。

- 脚本初稿先只读编号旁白，暂时隐藏标题、依赖行、术语表和画面。逐个关键判断问：前面给了什么依据，中间发生了什么，观众凭什么能跟到这里？缺什么就把那一步写进口播；不是给方案补一句就算修好。
- 类比先讲两边的具体过程，再说明对应之处与差异。有限相似不能升格为同一机制；没有充分依据就删掉等价判断，不靠反复说“本质”加强语气。
- 故事不是结论的例证目录。人物知道什么、看到了什么、为何继续调查、行动带来什么后果，要能前后接上。恐怖来自事件与认知的变化，不靠旁白反复宣布“这很恐怖”。不强迫所有故事提前揭底。
- 为时长删减时先删次要支线，保留从问题到答案的必要连接。观众说没听懂，优先修讲述，再改画面；不把添动画当成补逻辑。
- 纯旁白自查与实际试听分开登记。机器没有发现问题不等于逻辑成立，更不等于真实观众已经理解；这些不是新增句数、例子数或关键词配额。

## 5. 本 harness 的落地方式

| 环节 | 机制 |
|---|---|
| 写脚本前 | `方案.md` 必须写「受众基线：已经知道 / 不知道」——`vh clarity` 会读它当白名单与必定义清单 |
| 写脚本时 | 每场结尾一行 `← 依赖：…`；新术语要在旁白里让目标观众理解。`## 术语` 表只供作者记录，不替代口播解释 |
| 出片前 | `vh clarity`（本文件的机器检查）+ 事实核证与纯旁白讲述自查，逐个关键结论核对依据、中间变化和结论；不要求提交模型审稿记录，可选模型审稿不作为正常出片门槛 |
| 机器能查的 | 术语首现未定义、依赖倒挂/缺行、开场前 3 句内的未定义术语；抽象空转、因果缺中段、关键比较/推荐结论附近未检出桥接、仅登记术语表而口播解释未检出、强类比表述只记「待审」 |
| 机器查不了的 | 机制讲得对不对、隐性知识是否真的补齐、观众是否真的理解了 —— 这些进人工清单，不许用退出码冒充通过 |
| 评估器 | `vh clarity` 输出 `审查-解释.md`：FAIL/WARN/待审 + 每场「隐性知识追问」清单（观察到了什么 → 为什么注意它 → 如何判断 → 采取什么行动 → 如何获得反馈） |
