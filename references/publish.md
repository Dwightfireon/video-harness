# 发布清单（按平台）

一支片子做完后，各平台要的东西不一样。`vh cover` 一次生成三种比例，按下面这张表取。

## 一、画幅与时长

| 平台 | 画幅 | 建议时长 | 封面比例 | 备注 |
|---|---|---|---|---|
| B 站 | 16:9（1920×1080） | 3–10 分钟 | 16:9 | 知识区可长；灰阶封面文字要大 |
| YouTube | 16:9 | 3–12 分钟 | 16:9（1280×720 起） | 首帧即缩略图，别留空白 |
| 小红书 | 3:4（1080×1440） | 30–90 秒 | 3:4 | 竖屏大字；前 3 秒必须给结论 |
| 抖音 | 9:16（1080×1920） | 30–60 秒 | 3:4 → 裁 9:16 | 字幕必须够大（≥64px 等效） |
| 公众号 | 4:3 / 16:9 | 2–8 分钟 | 4:3 | 内嵌视频首帧也会被当封面 |

> 竖屏不是把横屏裁一刀：字号、行宽、每屏信息量都要重排。`vh cover` 只解决封面，
> 竖屏成片需要另排场景（当前未自动化）。

## 二、必备物料清单

出片后跑一遍，缺什么补什么：

```bash
node vh.mjs status          # 产物是否最新
node vh.mjs score           # 六关总分
node vh.mjs screen --frames # 静音静帧（人看：遮住字幕还能看懂吗）
node vh.mjs cover           # 三种比例封面
node vh.mjs pack            # 打包当前有效的公开交付物；内部 claims 不进入公开包
```

| 物料 | 从哪来 | 是否必需 |
|---|---|---|
| 成片 `video-voice.mp4` | `vh go --srt` | 必需 |
| 字幕 `subtitles.srt` | `vh voice --srt` | 必需（平台要单独传） |
| 封面（3 比例） | `vh cover` | 必需 |
| 标题 / 简介 / 置顶评论 | `发布文案.md` | 必需 |
| 分镜静帧 | `vh stills` | 建议（做预告/图文版） |
| `claims.json` | 写脚本时登记 | 建议（被质疑时拿得出） |

## 三、发布前 10 条自查

1. [ ] 按目标平台当前规则核对站外链接及推广标识的位置
2. [ ] 标题**点名主体**，不是"它 / 这个"
3. [ ] 封面文字在手机缩略图尺寸下仍读得清（缩到 320px 宽试）
4. [ ] 首帧不是空白（平台抓首帧当缩略图）
5. [ ] 广告段落**明确标注**是广告（`vh` 的广告场模板已含声明行）
6. [ ] 涉及真人真事：**不点名、不用原音**，或已取得授权
7. [ ] 所有数字能追到 `claims.json`（`vh claims` 无 unclaimed）
8. [ ] 静音看一遍：遮住字幕仍能看出"在说什么"
9. [ ] 片尾留 0.8–1.3 秒收口，不要戛然而止
10. [ ] 竖屏版若单独发：重新排版，不是裁切

## 四、发完之后

```bash
node vh.mjs publish-done    # 正常验收打包 → 清可再生缓存；保留源稿和素材
```

若审阅尚未通过但只需明确标记的待审包：

```bash
node vh.mjs publish-done --draft
```

交付包留在 `dist/<项目>-<时间>/`，包含当前有效的公开文件；静帧须显式 `--with-stills` 且凭证有效。内部 claims、研究素材和审阅资料不在公开包内，公开包不能代替工程备份。
