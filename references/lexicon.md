# 视觉语汇库（什么内容 → 用什么画面）

用途：`vh lexicon` 会打印这张表，并注入 agent 系统提示。
**原则：手法由内容推导，不是按喜好挑。** 每一行都给出「为什么这个内容适合这个手法」。

| # | 内容关系 | 用这个手法 | 为什么有效 | 实现 |
|---|---|---|---|---|
| 1 | 两个量比大小 | **条形对比** | 长度判断比读数字快 10 倍；差值一眼可见 | `track + bar`，数字用等宽字体 |
| 2 | 有先后 / 有依赖 | **步骤条 · 箭头链** | 顺序本身是信息，箭头消除"然后呢" | `steps.map` + `→` |
| 3 | 同一对象的不同状态 | **左右前后对照** | 变化必须并排才能比较 | 两栏同宽、同字号 |
| 4 | 机器里发生的事 | **窗口 mock + 代码行** | 真实感 = 可信；观众认得终端/编辑器 | `VH_UI.windowMock + codeLine` |
| 5 | 边界 / 谁负责哪块 | **文件树 + 色块** | 空间关系比文字更省认知 | 缩进 + 目录名 + 颜色分角色 |
| 6 | 很多 / 密集 / 流动 | **字符场 · 粒子汇聚** | 量感不能用形容词，要用密度 | `FX.glyphField` / `FX.streaksInto` |
| 7 | 规模 / 比例 | **形 + 单位**（条形/环形 + 一个数） | 单一数字配形状，避免读数字 | 条形 + `27%` |
| 8 | 结论 / 判据 | **大字 + 一句** | 一屏只留一句，观众才记得住 | `line() + type(el,'hero')` |
| 9 | 同一主体、多个层次 | **一镜到底**（镜头表推拉 + 文案交接） | 不切镜＝观众看到"有人在用一个东西"，不是"一堆截图配转场" | `VH_UI.oneTake(root, shots)` + `VH_UI.beats()` |

### 一镜到底的三条硬规矩（踩过的坑）

1. **越界钳制**：推近后取景点必须仍在世界内，否则主体被推出画面、只剩空白。
   `cameraShotValue()` 已内置钳制（`k` 限 1–4、取景点夹在世界内、落点夹在安全区）。
2. **文案择边**：主体被推到右边 → 文案放左，反之亦然。用 `st.captionSide(rt)` 取当前应放哪侧。
   文案**不能进 world 层**（否则跟着缩放，字号会变）。
3. **到停死**：镜头到位后不再逐帧写 transform（`held` 标记），避免亚像素重光栅化导致"字在抖"。

## 每场至少一个具体对象

| 类别 | 判定线索 |
|---|---|
| 数字 | 27%、3 倍、145 个项目 |
| 文件/路径 | `src/auth/session.ts`、`package.json` |
| 对比 | 前后、左右、vs、改前/改后 |
| 步骤 | ① ② ③、先→然后→最后 |
| 例子 | 例如、比如、走一遍 |
| 图表 | 条形、占比、环形 |
| 窗口/终端/文件树 | 真实界面类元素 |

> `vh screen` 会检查：一场里一个都没有 → 报「太空」。

## 禁止（自动化检查会拦）

| 禁止 | 被谁拦 |
|---|---|
| 只有标题 + 一段文字 | `vh screen`（元素 ≤1 或具体对象 = 0） |
| 画面抄旁白原句 | `vh layout`（dup 检查） |
| 文字压进字幕区（y > 840） | `vh layout`（safe） |
| 元素越界 | `vh layout`（edge） |
| 同面积元素重叠 >55% | `vh layout`（overlap） |
| 一屏三个以上强调色 | 人工（无自动检查） |
| 同一场同时用 3 种以上手法 | 人工 |
| 停 12 秒以上画面几乎不变 | `vh pacing`（第二批新增） |

## 手法密度建议

- 短片（≤2 分钟）：8–10 场，每场 1 个手法，不要混
- 中片（2–5 分钟）：10–14 场，可在同一场用"主手法 + 一个注解"
- 长片（>5 分钟）：14–20 场，每 3–4 场换一次主手法，避免审美疲劳
