# vh · 视频专属 Harness

围绕 **article-video skill**（确定性 `renderAt(t)` 引擎）的一层编排 + 本地工作台。
解决四件事：**做得快**、**讲得清楚**、**画面立得住**、**发布后好收拾**。

网页界面名为 **映序**；底层命令仍是 `vh`，不改变已有项目或凭证位置。界面改版与代码检查见 [2026-11-09 UI Review](docs/ui-review-2026-11-09.md)。

> 立场：只编排、不替代。渲染（render.mjs）、生成（gen.mjs）、TTS（voice-kokoro.py）、质量检查（check.mjs）
> 仍是 skill 的组件，skill 升级不受影响。
>
> **执行器可换**：写作者稿的那一层有两条实现——`opencode`（带 websearch、会话可续跑，
> 新工程默认）与 `local`（仓库自带的离线循环，作兜底）。两个实现返回同一形状，
> 任务记录、恢复、工作台都不需要知道用的是哪个。详见
> [执行器解耦](docs/runner-decoupling-2026-11-08.md)。
> **不自动切换渠道**，模型与渠道仍由本机配置显式决定。

## 安装与运行（从克隆开始）

> 如果你是第一次拿到这个仓库，按本节顺序执行即可。完成第 5 步 `doctor` 无报错后，再看后面的「快速开始」。

### 1. 前置条件

- **Node.js 22.12 或更新版本**（建议用 nvm / fnm 管理）
- **Google Chrome**，必须安装在 `/Applications/Google Chrome.app`
  - 最低版本：`156.0.8078.73`
  - 渲染器只使用系统 Chrome，**不要**运行 `playwright install`
- **Python 3**（用于 TTS 与部分分析脚本）
- **ffmpeg / ffprobe**（用于音视频处理）
- macOS / Linux（Windows 未专门适配）

### 2. 克隆仓库

```bash
git clone git@github.com:Dwightfireon/video-harness.git
cd video-harness
```

### 3. 安装 Node 依赖

```bash
PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1 npm ci --ignore-scripts
```

说明：
- `PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1`：跳过自带 Chromium 下载，本项目只用系统 Chrome。
- `--ignore-scripts`：跳过 Playwright / Electron 的安装脚本；桌面应用如需使用，再单独准备 Electron。

### 4. 安装系统与 Python 依赖

macOS 示例：

```bash
brew install ffmpeg python3
pip3 install edge-tts
```

可选：
- **离线 Kokoro TTS**：需要额外下载 Kokoro 模型到 `models/`（本仓库默认使用 Edge TTS，不强制）。
- **语音识别 / 转写**：需要 `models/faster-whisper-small`（未随仓库提供，可按 `node vh.mjs doctor` 提示另行准备）。

### 5. 检查环境

```bash
node vh.mjs doctor
```

`doctor` 会检查 Node、Chrome、Playwright、ffmpeg、Python/TTS 等实际解析到的路径与版本。**安装依赖不等于环境已验证**，请以 `doctor` 输出为准。

### 6. 运行测试（可选但推荐）

```bash
npm test
```

### 7. 启动与新建项目

启动本地工作台：

```bash
npm run desk
```

或直接用 CLI 新建项目：

```bash
node vh.mjs new --dir projects/我的视频
```

查看帮助：

```bash
node vh.mjs --help
```

### 8. 凭证与数据位置

- Bilibili 登录凭据：`~/.config/video-harness/bilibili.json`
- OpenDesign API Key：`~/.config/video-harness/credentials.json`
- 项目、队列与生成产物：仓库内的 `projects/`、`dist/`、`out/`、`schedule.json`

这些运行数据默认不进入 Git（见 `.gitignore`）。

### 9. 常见问题

- **`playwright install` 报错或提示下载 Chromium**：不要运行它，本项目渲染只使用系统 Chrome。
- **Chrome 版本过旧**：升级 Google Chrome 到 `156.0.8078.73` 或更新。
- **`npm ci` 失败**：确认 Node 版本为 22.12+，并删除 `node_modules` 后重试。
- **桌面应用无法启动**：因为 `--ignore-scripts` 跳过了 Electron 安装脚本，请单独安装 Electron 后再运行 `npm run desk`。

## 分段自动化

四段可以各自单独跑，也可以串起来：

| 段 | 谁做 | 入口 |
|---|---|---|
| **找选题** | 先提出值得问的问题，感兴趣再联网调查，有依据后确认入队 | 工作台「查找选题」；`vh schedule --discover` 开启后台自动发现 |
| **写稿做片** | opencode 写方案/脚本/分镜，再调 vh 命令出片 | `scripts/schedule-daemon.mjs` 按队列派发 |
| **发布** | 网页发布台，单条投稿或每日固定时点待发队列，失败即停 | `http://127.0.0.1:8144/publish` |

发布台已并入工作台（同一套 `desk/service.mjs` 用例，不再维护两套表单），
双击 `打开发布台.command` 直接打开那个页面。Electron 版仍可用 `npm run desk`，
但不是主路径。详见 [发布台并入工作台](docs/publish-workbench-merge-2026-11-08.md)。

定时派发不内置守护进程：`scripts/schedule-daemon.mjs --once` 可以交给 cron / launchd
（本机已装 `scripts/install-scheduler.command`），常驻模式则按 `schedule.json` 的间隔自查。
自动发布与制作独立：须在发布台明确确认启用，默认关闭，旧的时间窗口开关不会自动迁移为发布授权。

从工作台的新建表单点「设置自动制作与发布」，按 **加选题 → 定时生成 → 自动发布** 操作。只想出片就停在第二步；要接上新片，第三步选「当前及今后的制作队列」。首页直接「开始做视频」不会自动加入制作队列，可手动勾选该项目加入发布范围；队列里点「去做」关联照常。自动发现选题可另开，不是出片前置条件。

首页「加入待做队列」保存本次文章、链接或选题，以及画幅和交付选项，不创建项目、不调用模型。可在待做队列点「去做」，也可在「自动化」设置何时取队列。队列派发不会同时启动两支；首页直接开始不经过待做队列。排队控制同时运行的任务数，不会降低每支视频本身的模型消耗。

### 成片后自动投稿

- 发布台的「何时开始投稿」选 **成片后自动投稿**，设置最短间隔（默认 180 秒，最低 30 秒）。启用时已有就绪成片也可能开始投稿；第一支不用等固定钟点。上一支确认收稿才开始计时，工作台约每 10 秒检查一次，不并发，也不保证精确到秒。
- 只读取授权范围内现有的成片和投稿资料；没就绪成片就等，不会启动制作。服务重启后保留收稿时间，失败或结果未知会停住，不自动重投。
- 想每天定点做完接着投：在工作台「自动化」把制作方式设为 **每天定点启动一支**，例如 09:00，再启用上述发布方式。定点制作按工作台本地时间运行，工作台服务需在线；在该分钟尝试从待做队列启动一支，空队列、已有队列项目在做或错过时点不补。旧的「在时段内取队列」仍由原后台调度器负责。
- 两个新模式都需工作台服务使用新版代码；更新后若页面提示，先确认没有正在制作或投稿，再重启本地服务并刷新。它们不会修改原先每天到点只投一支的授权。

### 每日发布：有成片才动，到点发一支

在发布台选择 **每天到点投一支**，设置具体时间，例如 `12:30`、`20:00`。可以勾选待发作品（未出片也可先加入），或明确选择「当前及今后的制作队列」。自动发布分区在排程里单独选，不受单条投稿表单影响。登录后可直接点「确认并启用自动发布」，确认时一并保存当前设置；只想保存、不授权发布则点「保存排程」，排程保持暂停，不要求已有视频、登录或分区。页面提供未来七天排程、下次时点和就绪/等待/需处理数量。

- 每个时点按范围内的队列顺序取一支当前成片有效、资料齐全、未重复投稿的作品。制作中即使留有旧 MP4 也等待；没有就绪作品就跳过并继续开启，不触发制作、不补发。成功才出队；真实投稿失败暂停，未知结果须人工核对，不能靠重新启用排程解除保护。
- 默认仅显式选定的作品，新项目须另行加入；选择并确认「当前及今后的制作队列」后，队列后续关联的项目自动进入观察范围，完成后等下一个时点，不会完成即发，也不扫描全盘视频。使用各项目已保存的投稿资料（未独立保存时用原始发布文案）与排程保存的分区，不使用右侧尚未保存的编辑。
- 时点采用本地服务的时区，页面会显示。到点**开始投稿**，上传与平台审核不保证同一时刻完成。关闭网页不影响，但工作台服务必须运行；服务退出或电脑休眠错过的时点不补发。启用时不会立即投稿，从下一个时点开始。
- 队列与回执独立保存在 `out/.publish-schedule/state.json`，不混入制作选题队列。换账号/退出会暂停；多个服务实例通过持久认领避免同一时点连发。旧 Electron 连发工具与接口保留兼容，不承担每日排程。
- 工作台、发布台和调度器共用项目进程/锁与成片事实，不互相复制“完成”状态；发布台每 15 秒刷新状态，不覆盖正在编辑的文案。排程接口不可用或协议过旧时明确提示重试/安全重启，不再误报项目丢失或无限加载。重启前须先确认没有制作或投稿运行。

职责与验证见 [每日发布排程](docs/publish-daily-schedule-2026-11-10.md)。

### 商业推广声明

发布台「投稿内容」可勾选 **包含商业推广**。品牌 / 网站名称、行业、推广形式均标为选填：可以全部留空，只提交声明，不编默认行业、不创建或绑定花火商单。行业与形式按需读取 B 站当前选项。平台若要求补资料，会显示原错误并停止，不会去掉声明重发。

勾选会提交 B 站当前的创作者声明 `creation_statement: { id: 3 }`（「内容含营销信息」）；`porder` 仅是另一套商业报备资料，不能代替这个标注。收稿后只读回查对应稿件：分别提示「平台资料已确认」「声明不符」「尚未确认」，不凭收稿成功声称已显示。回读失败也不会重发，既有稿件不会自动修改。修复依据与边界见 [营销标注修复](docs/publish-marketing-fix-2026-11-13.md)。

- 手动投稿与试运行使用当前表单；确认框会显示商业声明。
- 点击「保存作品投稿资料」，把标题、简介、标签、封面选择、商业声明及单条分区一起保存到 `.publish-form.json`，不发布、不修改原始 `发布文案.md`、不启用排程。每日排程和批量使用各作品已保存的资料及排程/批量指定的分区。旧 `.publish-promotion.json` 仍兼容读取，不批量迁移。
- 旧项目缺省不勾选，不批量改旧片。新前端遇到不支持声明的旧后端，会阻止带声明投稿；如接口尚未加载，请在无制作或投稿运行时安全重启工作台，再刷新页面。

接口与验证边界见 [商业声明接入](docs/publish-promotion-2026-11-13.md)。

### 投稿资料保存与进度

未保存修改按作品暂存于当前浏览器标签页，切换作品或正常刷新可恢复；这不是自动发布配置。页面明确区分「项目原文案」「尚未保存」「已保存至本机」，保存期间继续编辑不会被回包覆盖，其他页面保存的新版本会触发冲突提示，不静默覆盖。主动「读取已保存资料」会先确认替换尚未保存的编辑。

缺封面时可以明确取消上传；保存该选择后，排程也不会再因缺封面卡住。本地「待发资料就绪」、当前「表单可提交」、平台「已收稿」是三种不同状态，均不冒充审核通过。提交预检起冻结当前表单与作品，并沿用确认的账号；失败按频率限制、登录、风控、明确拒绝或结果未知分别提示，不削弱既有防重复与未知结果保护。

网页投稿进度显示服务端确认的上传字节、百分比与阶段，不能测量的阶段只显示等待，不按耗时编百分比；视频上传 100% 不代表稿件已提交或公开。平台审核/下架状态持续同步和完整发布记录尚未接入。实现与验证见 [发布台可靠性优化](docs/publish-reliability-2026-11-13.md)。

### 查找选题：先提出问题，再调查依据

在工作台展开「下一支视频」→「发现选题」，输入探索方向并查找。默认先提出值得问的具体问题，不要求先有一篇可改编的文章，也不默认联网搜材料。候选说明对谁有用、为什么值得问、调查方向和待确认的前提；不预设结论、不强制反常识，允许少给。设置内的「聚焦方向／拓展探索」控制问题探索范围，不是材料类型配额。

- **查找选题**：保存问题候选，不入队、不制作。卡片先展示核心问题、价值、受众与研究进度；没有来源的好问题也可以保留。模型知识不保证时效性，涉及具体事件、数字、趋势的前提须待查，不冒充最新事实。
- **调查此题**：仅对选中的问题联网，检查前提、寻找解释、案例、不同证据及缺口。研究结果可为「已有研究线索」「材料不足」「建议调整问题」。后两者仍保留原题；建议问法不会自动替换核心问题，需通过单题继续探索并确认采用新建议。
- **入队**：「加入队列」在候选上可见；新版问题须取得通过原文规则校验的研究材料，并被标为已有线索，按钮才可用。这只是进入后续写稿调研的条件，不代表答案已证实。旧候选、旧队列保持原行为，不自动迁移或重新调查。
- 调查成功所用材料仍要求至少两个不同查询的检索完成记录，使用 `webfetch` 读取正文，并匹配摘录。新闻区分事件日期与发表日期，明确时间范围继续检查。深度材料允许较旧或发表日期未知，但须如实说明。工具返回正文和搜索结果留在 `out/topic-research/<批次>.json`；搜索失败保留问题及以前成功取得的依据，不自动付费重试。
- 卡片「换角度」只为当前题提出一个建议，挂在原题下，确认采用后才替换；「找一个子题」可另存为候选。新一批查找不覆盖已有候选，未采用建议也不记录负反馈。
- 「已经看过」「不感兴趣」单击即记录，可撤销或选填原因；不扩大成领域黑名单。「先收起」不是负反馈。历史支持搜索、筛选和分页；清空反馈不会批量放回候选。队列移除不清除选题记忆。
- 问题价值、研究进度与候选流转分开记录。入队后问题简报、未确认前提、研究依据和缺口通过同一个 `topicBrief()` 进入制作输入与 `materials/选题.md`，不因进入制作就丢掉问题意识。
- 「自动发现」默认只提出问题；独立的「自动调查并将有依据的选题入队」开关默认关闭，开启后才继续联网调查。只有符合条件的题目能自动入队，不自动开始制作。有候选等选择、队列足够、已有任务运行或仍在冷却期时不反复执行。定时制作和发布开关不受影响。
- 提问题与调查使用独立执行策略：前者不要求网页记录，不因没读到网页被看门狗误杀；两者都保留总超时、输出上限、锁、会话中断和进程回收。调查仍保留默认 480 秒预算及网络停滞保护，不延长预算来反复尝试失败来源。
- 去重仍结合核心问题、对象、事件和主要讲述内容；共享同一来源不代表同题，换文章链接也不代表新题。本地相似度只是保守兜底，不声称完整语义识别。

日期和摘录匹配不等于事实核实，来源是否真正支持解释仍需写稿时判断。不增加默认独立模型评分或审稿。入口和模块边界见 [问题优先选题](docs/question-first-discovery-2026-11-13.md)；历史材料校验说明见 [选题材料依据](docs/topic-discovery-evidence-2026-11-09.md)。

`node scripts/schedule-daemon.mjs --discover` 仅提出一轮问题候选，不调查、不入队；`--dry-run` 不调用模型、不修改状态。后台调度器的自动发现是否继续调查并入队，以用户明确保存的自动化开关为准。

## 四条主线

| 线 | 机制 | 命令/入口 |
|---|---|---|
| **快** | 迭代回路不渲染 MP4：预览页直接播 `scene.html`（驱动 `window.renderAt(t)`，同步播旁白音轨）；出片回路按「哪几场变了」增量重渲，安全守卫拦住错误复用 | `vh preview` / `vh render` / `vh go` |
| **讲清楚** | 先连贯讲述再分场，对照原文/调研依据自查解释缺口；`vh clarity` 提供形式线索；独立模型审稿仅用户明确主动选用 | `vh clarity` / 可选 `vh content-review --independent` |
| **画面立得住** | `references/quality.md`（归藏 + promo-film 的规则）+ `vh enhance` 注入 FX 手法库 + `vh jitter` 逐像素确定性/停死校验 | `vh enhance` / `vh jitter` |
| **好收拾** | 交付包 / 发布后清理 / 项目删除 / 占地可视 | `vh pack` / `vh prune` / `vh rm` / 索引页按钮 |

## 快速开始

### 默认内容优先：先交付，再按反馈改

现在默认流程是 **理解来源 → 写好完整旁白 → 简洁画面 → 必要技术检查 → 成片交付**。形式诊断、打分、两版试稿、关键样片、独立 claims 文书和人工审核表不再是默认前置步骤；关键出处保留在原文与方案/脚本中。自动推进不等于自动开启审核，更不等于自动发布。

新项目（含工作台直接新建和制作队列）默认允许按场混合：需要表现空间、物体或形态变化时可用 WebGL2 / SDF，普通画面和字幕继续用 DOM / SVG。无需额外提示，不强制使用；需要纯 DOM 时可在 CLI 新建时加 `--visual dom`。旧项目不迁移，发布台仍只判定当前有效成片。详见 [SDF 场景接口](docs/sdf-scene-api.md)。

```bash
node vh.mjs workflow --dir <项目>                         # 查看当前策略，不写配置
node vh.mjs workflow --profile content-first --dir <项目> # 内容优先（默认）
node vh.mjs workflow --profile audited --dir <项目>       # 主动启用完整诊断与发布记录要求
node vh.mjs build --audit --dir <项目>                    # 只为这次 build 追加形式诊断
node vh.mjs quality --dir <项目>                          # 手动完整机器检查（strict）
node vh.mjs pack --dir <项目>                             # 直接导出，不要求人工清单
node vh.mjs pack --reviewed --dir <项目>                  # 主动要求当前发布审阅记录
```

策略统一在 `PROJECT.json.workflow.profile`，缺省不写回、不批量改旧工程。历史明确启用的模型审稿合同仍保留；审校模式本身不授权付费审稿。技术模式省去对比度和版式策略扫描，但保留运行/资源、实测、字幕完整、媒体解码/基础音轨、版本与缓存、磁盘和沙箱保护。未运行的检查如实记录 `not-run`，不是通过。相同输入的有效渲染前浏览器检查可在最终阶段安全复用，最终媒体仍独立核验。

方案、验收和实测见 [内容优先系统优化](docs/content-first-optimization-2026-11-06.md)。

研究摘录逐字保真、可选原文事实锚，以及显式 `vh author-check` 的完整结果复用见 [作者可靠性最小修复](docs/author-reliability-minfix-2026-11-12.md)。不自动开启 Research Pack、不新增模型审稿；语义关系仍待核，旧制作入口不变。

讲述与画面优化不另加流程：主体先用具体行为解释，算例明说假设，比例交代分母，影响结论的限定进入旁白；画面优先同一对象的状态变化和图表近旁标注，沿用 SVG、字幕锚点与轻量变换，不默认加重型特效、素材搜索或模型审稿。正常制作不增加清理扫描；异常中断的辅助 CLI 有限时等待与定向回收，服务端回复未确认时如实提示。详见 [讲述、Motion 与收尾优化](docs/content-motion-lifecycle-2026-11-10.md)。

安装环境：使用 Node.js 22.12 或更新版本，在仓库目录运行 `PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1 npm ci --ignore-scripts`。Playwright 是仅安装在本仓库的运行时依赖；**不要运行 `playwright install` 下载自带 Chromium**。渲染只使用 `/Applications/Google Chrome.app`，最低版本为 156.0.8078.73（本次四个 CVE 的修复下限，仍须保持 Chrome 更新）。启动强制开启 Chromium 沙箱并使用临时用户目录，不连接日常浏览器；缺失、版本无法确认或过旧时停止，不降级到缓存内核或关闭沙箱。

Python、ffmpeg/ffprobe 和 TTS 环境仍须按 `node vh.mjs doctor` 的提示另行准备，安装依赖不代表已验证完整出片或配音。`doctor` 会显示实际解析到的 Playwright 版本和路径，避免误用用户目录中的另一份安装。上述 `--ignore-scripts` 也会跳过 Electron 安装脚本；全新环境的桌面应用需单独准备 Electron。已知渲染器模板由 harness 备份后加入同一浏览器策略；未知自定义渲染器不会自动覆盖，须另行检查。共享 skill 及其独立脚手架未修改；新建项目应使用本仓库 `vh new`，不要直接运行共享脚手架或历史备份。

### 配音引擎：当前用 edge-tts（Kokoro 模型已删，可随时重建）

**现状**：项目默认脚手架仍生成 Kokoro 版 `voice-kokoro.py`，但本机实际使用 **edge-tts**（微软 Edge 在线神经语音）。2026-10-31 已删除本地 Kokoro 权重（`models--hexgrad--Kokoro-82M*`，共约 626MB），原因是它机械感明显、且多音字不可控。

**新视频默认采用用户试听选定的 C 组：晓晓 `zh-CN-XiaoxiaoNeural`、1.25 倍原生合成语速、同场句间额外留白约 0.35 秒**（句尾 0.15 + 句间 0.20；场景间仍另留一拍）。默认值唯一来源是 `assets/voice-defaults.json`，不再分散修改 CLI、试音与 patcher。

新建项目的配音脚本会保存 `VH_NARRATION_DEFAULTS` 快照，正式测量、混流和试音沿用该快照。优先级为显式 CLI 参数 → 当前实测参数 → 已保存测量参数 → 项目快照。**旧项目没有快照时保留旧的晓依 / 1.0 回退，不自动改音色、加速、改停顿或重做旧片**；以后修改中央默认也不改已生成快照。试听选择与验证边界见 [旁白默认配置](docs/narration-defaults-2026-11-11.md)。

`lib/voice-upgrade.mjs` 里的 `zf_001` 是 Kokoro 模板身份探针，**不要改**。

**换引擎（一条命令）**：

```bash
python3 scripts/voice-edge-tts-patch.py projects/新项目
node vh.mjs measure --dir projects/新项目
```

脚本改写依赖引导、合成函数、音色与身份，并为本次显式新建/转换保存所选默认与停顿快照；槽位、混流、字幕、timing 契约保留。身份写进自有字段 `engineIdentity`，不冒充 harness 的 Kokoro `ttsIdentity`（冒充会让闸门误判为已知模板后失败）。修改前自动备份为 `voice-kokoro.py.bak-kokoro-<时间>`。已存在的 Edge 脚本不原地覆盖；本命令不是批量迁移旧项目的授权。

**并发合成（默认开启）**：未命中缓存的句子会以 4 路并发请求 edge-tts，再按原句序转码写缓存。逐句请求内容、音色、语速、缓存键与转码参数都不变，历史基准中 178 句的每句 WAV 与 `timing.json` 均与串行版逐字节一致；该负载 `vh measure` 从约 236 s 降到约 59 s，不代表所有工程的固定收益。`--tts-concurrency 1..8` 可调整。老项目没有声明该参数时不传入；已有旧 edge-tts 脚本不会被重新打 patch 自动覆盖，须保留原稿及备份后人工迁移，或在新工程从已知 Kokoro 模板重新生成。

当前 edge patch v3 按唯一文本/音色/语速键去重；部分请求失败时尽力保留成功句缓存，失败仍阻止生成测量或混流结果。`--no-cache` 和缓存写失败不再依赖缓存重读才能继续；正常缓存只保留路径引用，不常驻全片波形。仅完整匹配的已知 Kokoro cache-v2 模板可打 patch，未知自定义和旧 edge v1/v2 不自动覆盖。

**常用中文音色**：`zh-CN-XiaoxiaoNeural`（晓晓，温暖）、`zh-CN-XiaoyiNeural`（晓依，活泼）、`zh-CN-YunxiNeural`（云希，男声沉稳）、`zh-CN-YunyangNeural`（云扬，男声新闻）。全部：`edge-tts --list-voices`。

**依赖**：`pip install edge-tts`（需联网；CPU/内存占用接近零）。缺失时脚本会自动切到 `~/.local/share/opencode/video-tts/venv`。

**注意**：edge-tts 调用的是微软 Edge 的朗读接口，**微软未发布过针对该接口的商用授权条款**。个人分享、不开激励通常无实际障碍；要变现或商用，建议改用 Azure 语音服务（同音色，免费层每月 50 万字符）。

**想回到 Kokoro**（离线、Apache-2.0、可商用）：

```bash
bash ~/.config/opencode/skills/article-video/scripts/setup-tts.sh
```

该脚本会重建 `~/.local/share/opencode/video-tts/venv` 并重新下载 `hexgrad/Kokoro-82M-v1.1-zh`（约 314MB，走 hf-mirror）。之后把项目的 `voice-kokoro.py` 从备份恢复，或直接 `node vh.mjs new` 建新项目。代价是机械感较明显，且「长什么样」这类多音字会读错。

### 新视频默认不限时长

新建项目（CLI 和网页）在 `PROJECT.json.durationLimit` 保存 `null`，不预设分钟数或硬上限。内容需要多长就讲多长，先把对象、背景、过程、依据与限定说完整；删重复和无关支线，不靠删解释换短。不限时长不是鼓励注水。

- 用户明确要求限时时，使用 `vh duration --max N [--target N]`；不设十五分钟天花板。已有项目的显式上限保留，不批量修改；可由用户用 `vh duration --unlimited` 取消。制作 Agent 不能自行更改用户的时长策略。
- 有显式上限时，`measure`、正式渲染、混流与打包仍严格核对，`--force` 不能绕过。超限先保必要解释，再决定缩支线、调整或取消上限。
- 不限时长也必须有有效配音测量，字幕、时间轴、媒体、磁盘资源与质量检查保持不变；不会因为无上限就使用坏测量或无限申请资源。
- 不强行加速旁白、缩短实测槽位或直接裁尾。旧项目未设置此字段则保持原样，不自动缩短既有视频。
- 视频长度与制作耗时是两回事。先预览、批量改稿、定稿再渲染；局部修改用安全增量渲染，避免反复整片重做。

### 独立模型内容审稿默认不启用

- 新项目不自动启用或调用独立模型审稿；脚本提交、改稿、换来源、继续任务均不得重新开启。正常制作不因可选模型审稿缺失、待审或返修而阻塞测量、渲染、混流、打包或交付。
- `review_content` / CLI `content-review --independent` 会调用所选模型，仅用户明确主动选用时使用，不属于默认制作步骤。未执行不伪造 `pass`，模型结论不等于观众理解、实际试听或人工发布通过。
- 来源留存、写作中的关键事实核对与纯旁白讲述自查保留，不另起默认审稿循环；必要技术、媒体、资源保护照常执行。人工发布记录与模型审稿分开，普通导出不要求人工记录，主动审校/`pack --reviewed` 才核验。
- 历史项目已明确启用 `required=true` 的合同保留，除非用户明确要求关闭；不批量改写旧项目或重做旧片。
- 本仓库 `vh.mjs` 入口及本政策优先于共享 `article-video` skill 中旧的强制审稿路径；共享 skill 和历史 `docs/` 记录不作为自动启用审稿的依据。

### 先小样、后出片；待审不冒充发布通过

- `node vh.mjs voice-sample --dir <项目> --list`：只读列出开场及英文、路径、数字等高风险句。去掉 `--list` 生成最多 6 句小样；`--lines 1,4` 可指定全片句序号。`*Neural` 音色走在线 Edge TTS，其他音色走旧 Kokoro（仅用已缓存模型），不再把 Edge 音色传给 Kokoro。`--voice zh-CN-XiaoxiaoNeural --speed 1.25` 可比较新音色与原生合成语速；不改正式测量或项目默认参数。无需 `scene.html`/MP4，不自动安装软件或 ASR。`measure` 成功后也会直接复制刚测好的逐句音频，不再额外合成。小样和输入/发音工具/参数、WAV 字节绑定；**生成不等于实际试听**。本轮四组可播放短样见 `diagnostics/voice-audition-2026-11-11/试听.html`；用户已选 C 组并将其作为后续新视频默认，旧项目不迁移。
- 动作优先 `VH_FILM.sceneCue(root, '本场唯一句')`，直接得到场内时间；也支持本场句序号与句尾偏移，重测后自动更新。新项目内置；旧项目显式 `enhance --film --force` 备份升级，不覆盖未知自定义块。详见 [字幕锚点](references/cinematic-direction.md)。
- `cover` 默认三种比例独立排版，无需视频；同时输出 `out/cover/thumb-*.png`（320px）供实际检查。正文底图须显式 `--style frame --at <秒>`，不默认印工具品牌。过长文案会报错，不靠截字通过。有效封面按当前输入与 SHA-256 绑定，打包可携带；不绑定的旧封面仍会省略。
- `review-init --snapshot` 只生成全部 `pending` 的 `review.json`；已有快照不覆盖。显式 `--force` 会先归档旧记录，再重置待审，**不把旧 pass 搬到新指纹**。`review-status --json` 核对分项状态、文件指纹与证据来源。
- 普通 `pack` 不要求人工清单或 `review.json`，成功时 `deliveryReady=true`；未登记审阅仍 `releaseReady=false`，不阻塞交付。`pack --reviewed` 或审校模式要求当前发布审阅记录；`--draft`（兼容旧 `--force`）明确导出待审包，不能跳过媒体/版本/文案约束或冒充发布通过。
- claims 同时兼容 `assertion` 和 `statement`。外部事实登记 `sourceType:"external"`、真实 URL 与 `evidence` 的 `quote/type/checkedAt`；只有实际核到才用 `status:"verified"`。作者建议用 `recommendation`，作者计算用 `calculation` 并写算式，用户资料用 `user-provided`；本机或现场实测用 `measurement`，必须有本地原始记录。引用本地材料填写 `path/sha256/locator/quote/type/checkedAt`；外部标准可说明方法，但不能代替实测记录。摘录只写对应来源的原文，自己的解释另行登记。机器不能判断外部 URL 是否真的支持断言。

### 文章主线与广告口径

- 文章改编先读原文，在 `方案.md` 记录主题、核心判断、论述顺序和视频段落映射。开场交代讲什么、为什么讲、要回答什么；例子和数据服务主线，不强制悬念或反转。详见 [解释质量规范](references/clarity.md)。
- 广告口播、字幕、画面、简介和置顶评论都要对照用户要求，不擅加风险提示、价格或评价。已知重要限制或法律、平台要求与用户口径冲突时，先单独说明并确认；用户提供的信息和外部核实分开登记。ProdClub 的指定信息见 [广告参考](references/ad-prodclub.md)。
- `node vh.mjs review-init --dir <项目>` 为新项目生成待人工核对清单，默认不覆盖已有 `审查.md`。机器规则或清单本身不证明已听过、看过或理解内容。
- `vh hook` 的形式观察不作为失败，即使加 `--strict` 也不会因没有设问或反转失败；`vh loop --strict` 只对检测到的设问匹配疑点返回失败，不要求全片必须设问。`vh arc --strict` 和 `vh depth --strict` 仍可按各自形式规则返回失败，但它们不是内容清晰与否的证明，也不要求所有讲解套用叙事弧。
- 先只读编号旁白，核对关键判断的依据、中间变化和场间承接，再做画面。`clarity` 新增“术语表已登记但口播解释未检出”和强类比的待核提示，均不自动判语义通过/失败。已有认可视觉或用户催交付时不强做两版；详见 [克苏鲁视频复盘](docs/cthulhu-retro-2026-10-29.md)。
- 独立模型内容审稿按上文可选政策执行，不作为新项目或改稿后的默认分镜前置条件。历史 v3 的隔离上下文审稿设计见 [解释完整性修复（历史记录，旧的默认强制政策已取消）](docs/explanation-integrity-2026-11-04.md)；已明确启用 `required=true` 的历史合同仍保留，不能通过 `--record` 自签通过。
- `clarity` 支持受众行标记和双列表格，检查不存在的依赖；build 和 score 显示待核项数量，不再把它们隐去。但未知中文术语无法靠词面穷尽，关键跨步仍须讲述自查，不能用形式检查冒充理解。
- 发布文案与当前 B 站投稿表单共用限制：标题80、简介2000、标签最多10个、单标签20（按 JavaScript UTF-16 长度）。超限在交付前报错，不截断或改写用户文案；未实现多平台配置。

### 视觉意图：秩序、克制、韵律

- 自动分场时，制作 Agent 可用 `write_scene` 的 `visual_focus`、`visual_hierarchy`、`visual_restraint`、`visual_rhythm` 四个字段记录本场的焦点、层级、取舍和节奏；四项一起填写，作为 `// @visual` 保存在对应作者场景里。相邻场可参考上一场经过指纹核对的意图。旧场景不用补写，不会自动修改项目。
- 建议结合 `node vh.mjs stills --dir <项目>`、`node vh.mjs contact --times 2 --dir <项目>` 和 `node vh.mjs screen --review --dir <项目>`，对照实际画面核对焦点、留白和停顿。`screen --review` 只列作者声明与机器线索，**不会证明画面已符合意图或有人看过**。连续运动与旁白还需看预览、听实测配音。
- 流程配方 `node vh.mjs scene process-steps` 使用顺序线代替默认卡片；正式使用时将 `cueLines` 填为本场三句唯一字幕片段，使节点按旁白展开。配方默认的短时间仅供骨架预览，不代表声画已经同步。
- 密度、版式、转场等仍保留原有疑点和阈值，但留白、静止或相同版式不再被建议机械地“填满/加动效/强制换场”。字体对比度、布局、字幕及正式渲染安全门不因声明意图而放宽。

字段示例、实现边界与实测记录见 [视觉意图和架构](docs/visual-intent-architecture.md)。

### 查看制作究竟慢在哪

外部 OpenCode 会话可用 `node scripts/audit-opencode-session.mjs <sessionID> --from <用户消息ID> --to <交付消息ID>` 只读诊断；不指定边界则统计整段记录，不能称为“制作时间”。支持 `--json`、`--input <完整消息JSON>` 离线分析。通过既有 OpenCode CLI 的 GET 接口完整分页，不读数据库或凭证；输出只含时间/计数/错误类别和匿名模型别名，不含正文、思考、参数或原始错误。助手 created–streamed 区间包括模型、渠道、网络和客户端，不是纯推理或首字延迟。工具区间做并集，重叠不重复相加；未覆盖和缺测不归因模型，不自动猜交付边界。详见 [本轮流程优化](docs/agent-workflow-optimization-2026-10-29.md)。

`node vh.mjs performance --dir <项目>`（可加 `--json`）读取真实命令、子步骤和画面检查耗时、次数与失败次数；后续制作自动记录到 `out/.vh-performance.jsonl`，不保存命令参数或凭证。后续内置 Agent 还按次登记模型请求（含失败）与重试等待，旧日志不回填。命令包含子步骤，`ask` 也包含模型时间，不能相加当总耗时；外部 ASR、人工审阅和本会话外部模型未覆盖。报告本身只读。

新记录通过 `runId` 关联同一次 CLI 的命令和子步骤，保存可取得的退出码与固定失败分类。可区分渲染器失败、渲染后输入变化等情况；旧日志原因缺失仍显示 unknown，不据此认定重渲多余。渲染器还会分别记录截图、编码和拼接耗时。详见 [渲染性能优化](docs/render-performance-2026-10-28.md)。

报告还按真实记录列出渲染启动与失败构建的迭代观察（JSON 为 `observations`），提醒先修讲述、再按 `plan` 执行失效步骤；不推算节省时间、不自动调参或跳过质检。

已知标准渲染器模板会在写锁内升级：`--scenes` 只重截所选场及转场邻域，截图结束立即释放浏览器。未知自定义渲染器不覆盖；原文件备份在 `out/.vh-renderer-backups/`。macOS 内存压力正常时，并发可有界放宽到 2 路；压力、交换活动或采样未知时仍保守单路。

当前性能瓶颈、已实现优化、同覆盖实测及尚未实施项见 [2026-10-27 性能专项 Review](docs/performance-review-2026-10-27.md)；本轮新增改动见 [渲染性能优化](docs/render-performance-2026-10-28.md)。

运行时与整体流程的前后基准、CPU/RSS、回归结果与测量边界见 [2026-11-04 系统性性能优化](docs/performance-optimization-2026-11-04.md)：减少检查点重复解析、SSE 重复扫描、无效审稿分片的后续请求与恢复循环，以及隐藏网页的重复观察；不把局部收益冒充整片制作的同等提速。

对比度采样与配音并发的实测、一次被撤销的伪优化及其原因见 [2026-11-05 性能优化](docs/performance-2026-11-05.md)：`vh quality` −11%，`vh measure` 配音阶段约 3.95×（178 句真实项目），时间轴与逐句音频逐字节一致。

用户已经给了原文时，不要把「调研」做成把每条都追到官方原文：原文即主要来源，沿用其内容的断言用 `sourceType:"user-provided"` 登记即可（不需要 URL、不标 verified）。核证预算与事故记录见 [核证预算与用户提供原文通道](docs/claims-research-budget-2026-11-05.md)。

核证防循环在内置 Agent 的 `fetch_url` 执行端生效：用 `assertion` 填要核证的具体原句，同一断言连续两次取不到正文后拒绝重复抓取；未填时按同一 URL 保护。结果保存在 `out/.vh-research-attempts.jsonl`，恢复后仍有效；不再用会去重的 worklog 或原文文件数推算次数，也没有全项目 8 次上限。只读任务不写记录，外部会话的搜索工具不在此计数范围。抓取成功不代表来源支持断言，换一种说法的断言也不能靠机器可靠归并。`vh claims` 支持部分中文数量写法，但词面检查不证明数量或事实全部核对。当前修复与验证边界见 [通用流程加固](docs/pipeline-hardening-2026-11-05.md)。

工作台完整状态及终态交付核验移到有界后台观察器；同一观察中的并发请求合并，但完成后不缓存通过结论，制作与交付仍独立强校验。工作台重截静帧与 CLI 共用 `vh stills` 的锁和凭证，并显示实际运行结果。计划不再重复哈希同一批素材；新增的渲染器耗时只包含实际启动后的截图与编码总时间。事实对账按完整数值识别 `2049 个`，摘录里的数字不能代替断言登记；仍须人工核对事实与来源。架构边界、合成基准和未完成项见 [DNS 复盘后的管线优化](docs/pipeline-optimization-2026-10-28.md)。

### 选择画幅

- 首页“做一支新视频”提供 **16:9 横屏（1920×1080，B 站常规视频）** 和 **9:16 竖屏（1080×1920）**，新项目默认明确显示 16:9。
- 已有项目：打开工作台，在预览上方“画面比例”里选择并点击“保存比例”。运行中的任务须先取消、等待进程停止再切换；不会自动启动模型、渲染或取消任务。
- 选择保存在项目 `PROJECT.json.videoFormat`，刷新及恢复任务仍生效。旧项目只显示当前实际方向，不因升级擅自改幅。
- 保存前备份项目元数据、模板和旧预览到 `out/.vh-format-backups/`。保存后尝试按有效实测时间轴重建 HTML；失败会明确提示“预览尚未更新”，不会把旧方向冒充新方向。
- 改幅不是拉伸视频。须检查文字、字幕与图表布局并整片重渲；已有 MP4 不自动修改。构建会按保存的选择纠正引擎，主渲染/配音与交付会核对方向及成片实际像素尺寸，避免错误复用旧竖屏视频。

### 执行前计划与安全复用（2026-10-24）

- 先用 `plan --dir <项目>` 或 `go --dry-run --dir <项目>` 查看执行/复用原因；`--json` 输出结构化结果。只读计划不执行项目 JS、模型、TTS 或渲染；上游变化后仍会重新判定，不是费用或耗时承诺。
- 渲染默认最多 4 路，并受 CPU/可用内存约束。`--jobs 1..32` 或 `VH_RENDER_JOBS` 可指定请求值，命令行优先，实际可能调低。按目标卷估算帧空间；不足 512 MiB 安全余量时阻断，未知容量只警告，不冒充已检查通过。
- 编辑期 `go` 默认保留帧缓存，保证后续单场修改仍可安全增量；定稿后 `prune`，或显式 `go --clean-frames` 清理。`--keep-frames` 保持兼容。默认并发被调低也会显示原因；FPS 暂只支持整数，避免底层截断。
- `go --srt` 遇有效成片只补字幕，不为 SRT 重做 TTS 或混流；独立 `subtitles` 从当前 HTML 导出，不保证 HTML 本身已定稿。旧字幕覆盖前备份到 `out/.vh-subtitle-backups/`。
- `assets/` 全树及部分静态本地资源按字节纳入版本凭证；同路径替换图片也使旧媒体失效。未使用素材也可能触发重做。动态路径、外部资源和传递依赖尚不保证覆盖；大素材的同步全量哈希仍有性能成本。
- 手动 `--scenes` 必须覆盖全部已改动场景，并具备完整有效缓存、共享输入及编码基线。`--all` 不得与 `--scenes` 混用。正式 CLI 暂拒绝 `--encode-only` 与 `--from/--to`，因为旧帧没有逐帧来源证明；预览用 `stills --at`，出片用 `--all` 或安全局部范围。

全管道已修问题、兼容变化及仍未解决的产品缺口见 [全管道成熟度报告](docs/pipeline-maturity-2026-10-24.md)。
本轮性能证据、已修复路径及尚未优化的边界见 [性能审查与实测](docs/performance-review-2026-10-26.md)。

### 不盯阶段的自动制作

**网页直接生成默认使用自动模式，无需先运行命令。** 首页「开始做视频」、项目页普通生成/改片与继续任务会自动推进、质检和有限修复；只读审阅及单项编辑不扩大范围，明确关闭过的项目保留关闭。运行中任务不因刷新被热切换或重复派发。

独立 CLI 可用 `node vh.mjs automation --dir <项目> --enable` 开启项目默认值（配置不调用模型）；或单次 `ask "制作要求" --unattended --dir <项目>`。准备好作者输入后也可 `go --unattended` 本地出片。这些命令不是网页生成的前置条件。

自动模式由程序推进制作阶段，检查范围由独立的 workflow 策略决定，默认仅必要技术检查；普通内容错误同任务内最多两轮短补丁自修，恢复不清零预算。自动制作不表示启用视觉审核或独立模型审稿，提交、改稿或恢复也不得自动开启付费审稿。必需检查器未运行不算通过，环境/未知故障不盲目重试。最终绑定输入与媒体的回执含字幕、完整解码及有限音频检测；不伪造人工审阅、不自动发布。主要 CLI 制作命令与 ask 整任务共用项目锁。

详细用法、取消语义及仍未覆盖的视听/事实能力见 [无人值守制作](docs/unattended-production.md)。代码和测试通过不证明任意文章都能自动达到手工样片质量。

网页还有「自动制作」控制区：直接查看实际策略、修复轮次、失败点和逐项机器质检；可在页面核验当前版本、取消、继续或保存高级设置，不必翻 CLI 日志。后端轻量读取与 worker 强核验分开，具体接口、状态与边界见 [网页前后端闭环](docs/workbench-production.md)。

### 固定模型渠道

- 制作模型默认 `deepseek/deepseek-v4.1-flash`；OpenDesign 的请求别名为 `deepseek-v4.1-flash`。**可以在设置页自己换 provider 与模型**：工作台 → `/settings`（首页与播放器右上角都有入口），或命令行 `node vh.mjs provider --use <渠道> [--model <模型>]`。
- 选择只影响**之后启动**的任务；正在跑的不受影响。切换后仍**不自动切换渠道**：失败时不会悄悄换到另一个渠道重试，由你决定用哪个继续。
- 界面会分开显示「上次用的渠道」与「当前选择的渠道」：切了渠道但还没重新执行时，会明确提示"点继续任务后才会用新渠道"——不会让你以为切换没生效。
- **OpenCode Go**（`opencode-go`）：opencode 内置渠道，含 `minimax-m3.1-flash-free`、`longcat-2.5-preview-free` 等免费模型。凭证直接读 opencode 自己的凭证库（不用复制 key），端点需要 `x-opencode-session` 头（已自动加）。部分免费模型有地区限制，被拒时界面会显示原因。
- 默认仍只用 OpenDesign；旧项目缓存不能改成 CommandCode，OpenDesign 缺凭证也不能回退。其他渠道凭证保留但不会自动使用。
- 设置文件在 `~/.config/video-harness/providers.json`（权限 600，项目外）。密钥只写本机私有文件，不进项目、不进日志、不回显；页面只显示"是否已配置"与来源。现有凭证优先沿用原处（harness 凭证文件 / opencode 凭证 / 环境变量），设置页里填的会覆盖它们。
- 所选渠道（含 OpenCode Go）的超时、可识别临时断连（如 ECONNRESET）或 HTTP 500/502/503 后，在同一渠道最多重试当前请求一次；第二次仍失败才停止。上下文纠偏、定向工具回退与传输重试共用总计两次请求的上限，不叠加成无限重试。不会重跑已完成工具。额度、认证、限流、证书、域名不存在及不明网络错误不自动重试，任何错误均不自动切换渠道。服务端要求等待超过 30 秒则停止。
- **请求发送前清理空轮**：流式渠道可能产生无文字、无工具调用的空 assistant 消息。它不能代表完成，也不应被原样放进下一次请求（严格网关会回 HTTP 400）。请求投影会剔除这类空轮，检查点中的原消息和工具配对保持不变；这不是模型渠道自动切换，也不是忽略真实失败。
- 暂停时保留对话与工具结果，由用户点击「继续原任务」。失败时 CLI 非零退出，网页显示渠道、具体原因及已重试次数，不报“完成”；预算或空转暂停按设计退出 0，但状态和日志都写「已暂停」。
- 流式接收较长生成，收到完整响应后才执行工具。默认响应头等待 120 秒、接收无数据 90 秒、单次总时限 600 秒；持续输出不会再被固定 90 秒总时限打断。
- 每次请求只发送缩减后的历史投影：剔除较早的纯文本推理，节选旧工具长输出，必要时按完整轮次将较早的工具调用和结果折叠为历史回执，避免内联代码参数反复膨胀。保留原始要求、全部用户补充、最新轮次及签名/加密数据，不留下孤立工具消息。192 KiB 是软目标而非模型窗口；必要内容仍较大时继续发送，不因此本地中断。完整工具参数和结果仍保存在原检查点，不修改、不删除。
- 错误诊断记录安全错误码、HTTP 状态、请求阶段、耗时和已收字节，不记录原始异常正文、响应正文、请求头或凭证。`transport` 只表示传输故障，不等于已证明上游模型有故障。证书错误会具体说明是域名不匹配、过期还是签发链不可信，并额外记录请求主机名与失败证书的 SHA-256 指纹（长度与字符白名单校验，不含 SAN、正文或凭证）；这些只是证书校验证据，不能判定证书来源、是否经过代理或上游是否故障。
- 只使用本机已有凭证；可读环境变量 `OPEN_DESIGN_API_KEY`、harness 本地配置，或已配置的 OpenCode 同名 API 凭证。不会创建新账户或改写凭证。
- 验证使用模拟响应与本地 HTTP，不扣真实渠道额度；不代表对外部服务可用性的承诺。

`node vh.mjs scene <配方>` 默认只输出代码，不创建项目；`--append` 才追加当前场景，`--demo` 才显式建示例。制作 Agent 不允许使用 `--demo`。

### 中断后继续

“指挥”在发现未完成任务时默认显示「继续原任务」，保留任务 ID、原模式和完整执行检查点，不再把再次生成当作新任务。已记录完成的工具不自动重放；执行结果未知则先核对，仍在执行的子进程会拦住重复派发。新一轮任务必须单独确认，旧日志与检查点归档保留。

单次执行有步数预算（默认 400，可用 `VH_AGENT_STEPS` 调整）。达到预算时任务标记为**暂停**，不是失败：检查点已保存，点继续会从当前进度接着做，不重做已完成步骤，CLI 退出码为 0。

预算之外还有一层**推进检测**：连续 60 个模型轮次（`VH_AGENT_STALL_STEPS` 可调）没有改动任何作者文件（方案/脚本/claims/scenes/engine/timing/成片/中间产物）会先明确要求它停止探索、立即动手；再 40 轮仍无产出就暂停，不再烧完预算。只读、查模板、列目录都不算推进——真实事故里 400 步有 163 次在查同一份模板，第 367 步才第一次写方案。构建失败、被拒执行或重写相同内容，不会冒充新产出；小文件比内容而不是只比修改时间。**计数每次执行重新开始**，不跨执行继承。一个批次有多个工具也只算一轮。暂停时日志按持久化状态写「已暂停」，不会因为退出码是 0 就写成「完成」。

**重复读取保护不限制正常分段阅读**：按文件内容版本和读取范围计数，同一范围反复读取超过 6 次才会拦；不同段落、文件内容变化后可以继续读，产物推进后重新计数。对同一版 `engine.tpl.html` 换关键词无界 grep 仍会合并计数，防止重复猜接口。只有连续 3 个模型轮次全部在请求被拦截的重复读取、且没有产物推进时才暂停，不会因为一个批次的多个调用直接用完纠偏机会。提示与恢复请求会按实际文件给出下一关；`PROGRESS.md` 只作线索，不以过期勾选代替现场。

长文件不缓存不完整前缀；小文件缓存与直接读取使用相同范围规则。`read_file` 只给 `start_line` 也会从指定行开始。网页抓取含响应正文总计限时 30 秒、最大 4 MiB，超时会返回失败而不是无限等待。帮助可用 `node vh.mjs --help` 或 `node vh.mjs build --help`，不会执行制作。

模型中途回复或被输出上限截断不算完成。全流程（article/topic）缺关键作者文件、没有成片或成片落后时，提醒补完后仍未交付会保留为可恢复暂停，不会把检查点误锁为 completed。单点修改仍按用户指定范围执行，不强求重造全片。恢复会真正去掉重复的执行器提示，普通用户补充不按前缀截断去重。

**中途报错不算失败**：opencode 运行中出现 `ECONNRESET` 一类错误后若继续工作，只有「错误之后有工具成功执行、并且又输出了回答」才算恢复；恢复后仍按作者文件与交付物核验，没改到文件照样判未完成。错误原文只进日志，卡片显示「运行中曾出现网络连接中断，之后已恢复并继续」。收尾阶段退出码非零但交付物齐全时记为「制作结束 · 已交付（收尾异常）」，不再显示「制作失败」。详见 [执行器收尾](docs/runner-settlement-fix-2026-11-09.md)。

**文案版本自动登记**：opencode 用原生工具写 `发布文案.md`，不经过受控写入钩子，因此执行器开跑前记下源签名与文案哈希，收尾时若文案确实改变、脚本/要求未变、机械检查通过，就按 `by: 'agent'` 关联当前稿。用户手动确认的（`by: 'user'`）不会被自动流程覆盖；文案不完整或输入在运行期间变化则不登记，也不冒充人工核对。

**长片分场写入**：agent 用 `write_scene({scene: 1, layout:"本场版式", content: "root => { ... }"})` 每次保存一场；草稿不覆盖 `scenes.src.js`。齐场后执行器原子组装，再 build 验证。脚本修订后先核对身份与基线，归档旧草稿、受控重开，只复用可证明旁白/标题/说明/引擎未变的场次；旧清单缺身份信息则不复用。外部源码冲突不自动覆盖。`inspect_scene_drafts` 返回只读检查与 CAS 指纹，`rebase_scene_drafts` 受当前范围约束。编辑文案/只读模式不能写场景；异常退出核对已保存内容，不盲目重放。

**工具调用被输出上限截断**：整批工具参数都不执行，也不把半截参数放进对话或项目文件；仅保留安全的解析子类型、结束原因与工具片段数。第一次会明确要求缩成单场调用，再发生则暂停并保留检查点；跨恢复仍有限制，用户补充具体指令后才能重新给予尝试。流不完整等其他响应错误会标明子类型，不把它们一律当截断，也不盲目重试/切换渠道。此功能减少可恢复截断导致的中断，不保证外部模型永不失败。

**HTTP 200 中的 error 也细分原因**：只保存固定子类（上下文超限、工具参数失败、消息配对错误、内容策略、输出参数限制、未知），不记录原始错误正文或任意上游错误码。明确的上下文超限才尝试一次更紧的历史投影；保留原文、全部用户补充、最新工具批次及配对、签名/加密内容，确实变小才重发。无法缩小、再报错或未知拒绝均停止，不猜“都是上下文太长”。接口明确报告工具参数失败，或完整响应里的工具参数 JSON 无效时，整批不执行，给予一次小调用纠偏机会；第二次仍失败则暂停，只读工具不能清零这个恢复预算，已落盘的真实推进才可清零。所有路径都不换渠道。

**阶段契约与场景空转**：恢复不改写历史 system 或用户原文，每轮尾注给当前一场的脚本文案和接口。首次文章是材料，不会关闭制作授权；同一场四轮没有落地产物后，工具收窄到该场 `write_scene`，执行端也验证工具名、目标、场号和请求基线。换读取工具、失败写入或重写相同内容均不重置预算；违规混合批次整批拒绝，恢复也先整批核对，持续违规有界停止。齐场后由程序组装。只读与审阅范围跨恢复保持，普通追问不解除，明确制作/修改授权才解除；自动阶段同样检查待接收插话。接口明确不支持定向参数时，同渠道仅回退自动工具选择一次，本地契约不放宽。

代码更新不会热替换已运行的制作进程；新启动/恢复才加载新逻辑。不要为了加载更新重复启动仍在运行的任务。

旧任务没有检查点时只能按已有文件接续，界面明确提示，不能追溯恢复此前丢失的工具上下文。模型仍可能根据新要求决定修改文件；检查点不是所有外部副作用的 exactly-once 保证。

### 长任务上下文

每轮只把最近 8 个工具轮次完整发给模型，更早的折叠进 system 里一份有上限（24 KB）的工作台账。台账按「写入 > 失败 > 最近」选行，不从最早的前缀硬截，后期实际产出不会被早期探索挤掉。原始要求与全部用户补充不删不改；签名、加密推理和最新轮次保留。最近一次工具批次不截断，重读能取回中间片段。

另有项目级 `out/.vh-worklog.json` 记录已写文件、已跑命令与失败原因，跨执行累积，写入与失败不会被读取流水淘汰。每次请求前把最新台账放进发送投影，恢复后不会停留在几百步前的状态；历史消息与检查点本身不改。`read_file` 支持 `start_line` / `max_lines` 读中段；重复读取返回本次范围的真实内容，而不是“不必再看”。

### 已有项目改稿与可靠交付

#### 发布文案与发布包

- 默认交付目标是 **视频＋发布包**（`PROJECT.json.deliveryTarget: "publish-package"`）。article/topic 按程序阶段执行 `build → measure → render → voice → publish → validate`；视频完成后必须补齐发布文案，不能仅凭一句“完成”结束。已有有效视频不因补文案而重做。
- **只要视频**：在工作台「发布」页选择「仅视频」并保存，或运行 `node vh.mjs delivery-target --target video --dir <项目>`。这不会启动模型、重渲或改写视频；全流程不再强制发布文案。运行中的任务不能切换目标。旧项目不会被自动改写配置；未配置时按默认发布包目标检查。
- **分项状态**：「发布」页分别显示视频、发布文案、人工审阅与发布包状态。必填项为标题、简介、置顶评论、标签和封面文案；公开字段中的 `<带码链接>`、`[待填…]`、TODO 等占位内容阻断完成与打包。标题偏长只提示，由目标平台进一步校验。仅视频目标不因发布文案缺项而阻塞。
- **写给观众**：标题、简介、置顶评论、标签、封面文案会原样出现在公开页面，因此不写取材与检索过程、来源采用与弃用、核证状态、待人工审阅提醒、模型/工具名、本地路径、内部字段名或任务编号。程序按字面分三档检查：项目文件名与路径（任何公开字段都算错误）、明确的取材失败叙述（简介与置顶评论算错误，短字段只提示）、可能只是题材词的说法（只提示）。这些都只报位置、不自动改写，正确去处是 `## 素材与数字（可核）` 等内部小节或 `claims.json`。投稿表单手填标题与简介走同一套检查。详见 [发布文案只写观众内容](docs/publish-audience-fix-2026-11-09.md)。
- **文案版本**：新生成/修改的完整文案关联到当前脚本、明确要求和文案内容的 SHA-256，回执位于 `out/.vh-publish-revision.json`。已关联的脚本或要求变化后，旧文案阻断发布包完成与打包；仅改画面、交付目标或更新时间不会使文案过期。生成期间被外部改稿时，旧响应不能写入并冒充新稿。历史文案只显示“未关联”，不自动补造凭证；手动修改保留并显示待关联。人工核对后可点「已核对文案，关联当前稿」，不改正文、不调用模型；关联不是语义或人工审片保证。
- **单独生成/重试**：点「生成发布文案」或「修复 / 补齐文案」，沿用 `edit-copy` 执行器，只允许修改 `发布文案.md`，不重做脚本、画面、测量或配音。模型失败后可以单独继续文案任务。若当前未完成任务不是文案任务，须先确认归档原任务再另开；原文件和历史检查点保留。缺凭证不启动或归档任务。
- **保护已有内容**：已有文案禁止整份覆盖，须通过带文件指纹的短补丁修改并备份；保留用户手动标题与无关修改。受控文案工具拒绝新增人工审阅勾选，机器检查通过不等于已经看过成片。
- **打包门槛**：发布包文案未通过检查、视频无效或过期时，`pack --force` 也不放行。普通 `pack` 不等待人工手续；`--reviewed` 或审校模式才要求当前审阅声明与证据。`--draft`/旧 `--force` 可明确导出待审包，不修改审阅结论。`pack --video-only` 不携带发布文案；任何已有输出目录都拒绝复用，不删除用户文件。
- **公开包边界**：默认仅带带声成片、可选静音母版、脚本、有效当前 SRT、已绑定版本且核验字节的三比例封面，以及发布包目标的发布文案；另有 `manifest.json`（SHA-256）和交付说明。同卷暂存、核验后发布，不增量覆盖旧包。不带内部 `方案.md`、`claims.json`、原文或审查资料；未绑定版本的封面省略并提示。`--with-stills` 只接受新 `vh stills` 登记的当前输入签名和逐文件指纹，旧静帧须重截。公开白名单不是语义脱敏保证，公开稿仍须人工核对。
- **参考资料**：简介底部的「参考资料」清单由程序汇总，不必每条片子手抄。四个来源合并去重：`claims.json` 的外部事实证据（只收 `sourceType: external`，作者建议/计算/用户提供不算，排除明确未取得的条目）、`脚本.md` 的「数字与来源」、`materials/选题.md`／`原文.md` 的「检索来源」段、`research/` 各小标题下的首个链接。链接只做归一与排版：裸域名补 `https://`，`doi:10.x/…`、裸 DOI、`doi.org` 链接统一成可点开的 `https://doi.org/…`，`arXiv:` 编号转摘要页；同一篇的 DOI 与出版方页面合并成一条。没有来源就不生成，不补编链接。
  - 写入只有一处实现，标题统一为「参考资料」，一次只写一遍，重复执行不重复添加；简介已有参考段落时接着往里加，不另起同名标题。
  - 守 B 站简介 2000 字上限：超限时整条丢弃并报出条数，绝不截断单条链接。
  - 出片、打包与 `vh refs` 结束都会打印结果：补了几条、已含全部、或四个来源都没有 URL／DOI。不再静默跳过。
  - 程序补完链接会把文案重新关联到当前稿，回执标记为 `system`——表示"程序补链接"，不是人工核对，也不覆盖用户的确认。
  - 核证用地址与读者看地址分成两个字段：`url` 可以是 SEC XBRL 接口或存档原文，`publicUrl` + `publicLabel` 写给人点的页面与标题。缺 `publicUrl` 时仍列出并在工具输出里标出「点开不是文章」，不在正文里冒充可读页面。
  - **默认自动执行**：`vh go` 与 `vh pack` 结束时会检查简介，缺来源就自动补上并报出补了几条；用户不用记命令。只做加法（不改已有文字），重复执行不会重复添加。
  - `publish-check` 只提示「还有几条来源没进简介」，**不阻断发布**：题材不同，并非每条断言都要附链接。
  - 这一步只做去重与排版，不判断证据是否支持断言，也不核证 URL 是否可达；链接与断言的对应关系仍需人工核对。文案追加后需重新核对版本。
- **边界**：`go` / `render` / `voice` 仍是本地视频命令，不会悄悄调用模型生成文案；`go` 会提示发布包缺项。版本关联、完整性与占位符检查不等于**自动语义一致性判断**；网址、优惠码、推广口径及内容是否忠于脚本仍须人工核对。分平台适配与自动发布不在本轮范围。

```bash
node vh.mjs publish-check --dir projects/我的片子
node vh.mjs refs --dir projects/我的片子                 # 预览：四个来源汇总的参考资料
node vh.mjs refs --append --dir projects/我的片子        # 追加到简介底部（幂等，已有链接不重复）
node vh.mjs ask "按当前脚本补齐发布文案，只改发布文案.md" --mode edit-copy --new --dir projects/我的片子
node vh.mjs pack --dir projects/我的片子                # 视频＋发布包
node vh.mjs pack --video-only --dir projects/我的片子   # 明确不携带文案
```

- **短补丁，不整片重写**：`read_edit_file` 返回作者文件的 SHA-256，`patch_text` 按原文精确替换并核对匹配次数；`read_scene` / `replace_scene` 只读写指定一场。保存前检查完整文件基线，冲突不覆盖；原始字节备份到 `out/.vh-edit-history/`。旧初稿清单过期，不妨碍基于当前作者版本开展新一轮编辑。
- **写入失败不算推进**：模型发起了写工具、但被 `base_hash` 冲突、约束或语法检查拒绝时，文件没有改变，执行器不会清掉待修改标记，也不会进入完成校验。失败原因写进下一轮提示，要求先重读当前文件再改。真实事故：`patch_text` 返回 `stale base_hash` 后，任务却直接走 `validate`，把旧成片当成这一版完成了。
- **只能通过受控工具改作者文件**：`node -e` / `python3 -c` / `sed -i` 直接写 `脚本.md`、`发布文案.md` 等会被拒绝；只读查看仍然允许。真实事故：模型用 `node -e` 写入发布文案成功，但没有更新版本回执，界面一直报“仍关联旧稿”。受控的 `patch_text` / `write_file` / `append_file` 会同步关联当前脚本。
- **插话有待完成清单**：明确的脱敏/替换、删减保留要求进入检查点。宽泛脱敏先用 `define_change` 登记姓名与具体表述，再逐项短替换；`verify_change` 检查公开脚本、所有场景与发布文案，绑定当前作者文件指纹。收到不等于完成，公开文件后续改动会使旧核验失效。内部方案与证据不参与公开脱敏，也不因补写内部证据让已完成的公开版本失效。“保留重点/不放某段”这类内容取舍登记为语义要求，机械检查后仍标为待人工复核。用户明确的新替换/取消要求可取代对应旧要求。
- **阶段由程序闭环推进**：公开交付文件已无登记禁止词时，执行器直接做机械核验并推进，不再要求模型重复登记清单或搜索内部证据。确定性阶段（build / measure / render / voice / validate）连续两轮未执行时由执行器按固定参数代跑一次；同一阶段失败后不原样重跑，先暂停在真实报错。脱敏任务中读取 `方案.md` / `claims.json` 会被拒绝并提示范围，避免把修改范围越扩越大。
- **阶段调度**：全流程优先处理待完成修改，再按实际文件进入 build → 必要 measure → render → voice → 必要 publish → validate。`run_stage` 使用固定 argv，不通过 shell 管道，真实退出码与完整日志保存在 `out/.vh-tool-logs/`。每个小步骤本次执行最多 12 轮未推进；明确恢复会得到新的本次机会，历史计数仍保存。失败阶段不盲目重复重型命令。
- **中途插话保护**：请求/工具批次期间到达的新要求会阻止尚未执行的旧写入；最终回复期间到达的插话也不能被旧回复跨过去标记完成。已发生的副作用不假装撤销，恢复先核对。
- **统一产物凭证**：status、go 与最终完成检查共享一个只读判定。成功渲染/混流才登记源文件、时间轴和真实媒体指纹；时长相同不能证明版本相同。阶段开始和结束都校验输入，运行中被改稿不能给旧产物登记新版本凭证。相同内容的重写不因时间戳变化误失效。
- **可选视觉实测（对比度 / 版式）**：默认内容优先不运行这两项策略审核；`workflow audited`、`render --audit` 或手动 `quality` 才执行真实浏览器抽样，不能把未运行显示为通过。主动视觉审核仍按实际底色、文字行框、碰撞和边界判定；自动审校模式不接受质量豁免。所有渲染路径仍核对运行、资源、字幕与检查前后输入一致性，修改后的版本不能借用旧结果。
  为什么必须实测：静态检查只认 `abs(mk(...), x, y, w, h)` 这种写法，实际场景常写成 `const el = mk(...)` 再 `abs(el, ...)` 或坐标来自变量，于是**一个都没命中**；颜色同理，场景写 `var(--ink, #eef1f6)` 想要浅字，但 CSS 变量存在时回退值不生效，引擎的 `--ink` 是深色，结果深字压在深卡上（实测 1.17:1）而旧检查全部放行。
- **有声才是默认交付**：article/topic 必须有当前版本的 `out/video-voice.mp4` 和真实音轨；静音 MP4、损坏媒体、旧画面和未核验修改均不能 completed。仅改画面/改文案的对话可以结束，但不因此把未完成的整片说成已交付。
- **测量幂等**：稿件和测量参数未变、timing 有效时复用，不清除真实渲染基线；确需重测可用 `vh measure --remeasure`。基线描述实际做过的产物，过期不等于删除基线。
- **输出额度可显式配置**：默认仍为 6000，可设置 `VH_AGENT_MAX_OUTPUT_TOKENS=8192`（整数 256–65536）或注入 provider 的 `maxOutputTokens`。不在触顶后无限涨额度，也不猜测模型专有推理参数。阶段请求使用更小的历史投影；纯推理触顶后可从发送投影剔除该条无工具的纯文本推理，完整检查点及签名/加密信息保留。
- **执行边界**：Shell 开启 pipefail，失败不能被 `| tail` 隐藏。受限编辑模式不通过 run 启动解释器或嵌套项目脚本，写入只用受控工具；制作阶段由 run_stage 执行。article/topic/普通 edit 中保留的通用 run 及用户工程脚本仍是可信代码执行入口，**不是完整 OS 沙箱**。制作循环拒绝直接安装用户级/全局依赖。
- **长文分批写与提交**：`append_file` 默认每批最多 3000 字符，第一批创建文件，后续批次带上一批返回的 `base_hash`。Agent 新建的方案/脚本全部写完后须 `finish_draft` 提交当前全文指纹；第一批落盘、工具回复“已写入”都不代表整稿完成。私有草稿状态跨恢复保留。缺规划场次、空场、跳号、过期指纹均不能提交；旧完整工程不强制补提交。旧初稿会核对方案的分场表，不能因三场脚本恰好匹配三块示例就提前构建。非法 claims 仍留在证据表阶段；初始化场景须替换为本片真实内容，保存场景时必须声明真实 `@layout` 版式名。
- **修复轮次与阶段回执**：固定 `run_stage` 回执由 wrapper 给出阶段与真实退出码，构建成功时的非阻塞警告不会被误当成失败再扣一轮额度；一轮修复可连续多处短补丁，用 `finish_repair` 提交复检。任一处补丁落地都算读盘推进，但不算“整轮修完”。
- **主体字段格式兼容**：`build` 识别头部明确的 `主体：…` / `__主体__：…` 等写法，以短补丁规范为 skill 所需的 `**主体**：…`，保留名称、顺序与正文，原稿备份到编辑历史；不从标题推测主体、不删除比较对象、不改全局 skill 或放宽检查。多主体开场仍须明确点名，格式规范化不代替内容修复。
- **失败与空转分开计**：`run_stage` 参数用错（例如把 shell 命令塞进 stage）会被本地拒绝并直接给出正确用法，不计偏离、不写 blocker；轮次上限只累计"没有推进产物"的轮次，有产出就清零。强杀后遗留的元数据门在可证明已遗弃时自动恢复，否则项目会永久卡在 `metadata-transaction`。
- **用户要求的判定是结构性的，不是词表**：任何新的用户发言都默认算一条要求，只有封闭的一小组纯"继续/重试/保留原稿继续出片"才豁免；明确要求"先讨论、不要改"时不强行改稿。因此"片尾接广告""换标题""改字幕"等新说法不需要逐个登记到正则里。是否**落实**则看模式契约：article/topic 必须落到 `脚本.md` / `scenes.src.js` / `engine.tpl.html`，`edit-copy` 才认 `发布文案.md`；只改发布文案不能满足视频修改要求，反过来发布文案任务也不会被视频判据卡住。
- **准确显示暂停原因**：首页卡片和“指挥”先显示具体失败/暂停原因，缺成片单列为产物状态；继续运行后清空旧提示。修复额度耗尽不会因刷新或继续而清零；补齐缺失的上游稿件、或修正作者输入后可重新核验，若仍失败则按剩余额度停止，不无限自修。若用户已从命令行补完该阶段，当前实际产物成立时旧暂停不再冒充当前故障，但历史与已用轮次保留。
- **缺稿不再无限查资料**：方案、脚本、证据表缺失时，阶段调度直接进入对应分批写作；查资料阶段允许 8 轮只读侦察，超过仍不动笔就停在明确缺口，而不是耗完步数。
- **浏览器内核回退**：优先用 Playwright 自带内核；缺失时自动用本机 Google Chrome，渲染、静帧、字幕实显检查与工作台测试不会因内核未下载而整片失败。
- **只读环境体检**：`doctor` 不派发 `npx` 或自动下载；核对实际可执行内核与 Chrome 回退，外部命令有超时，磁盘检查项目所在卷。凭证存在不代表渠道可用。
- **磁盘卫生**：`go` 默认保留 `out/frames` 支持后续安全增量；定稿后 `prune` 或显式 `--clean-frames` 回收。普通 `prune` 和 `publish-done` 不删 `materials/`、作者备份或过程证据；`publish-done` 默认正常打包，显式 `--draft`（兼容旧 `--force`）才导出待审包，打包失败不清缓存，公开包不是工程备份。`vh rm` 默认先清帧/TTS/分段再移入回收站；`vh prune --trash` 仅清回收站缓存，彻底删除需单独确认。工作台清空回收站只删除确认时列出的项目，列表变化需刷新重确认，隐藏和非目录文件不随之清除。
- **额外交付物**：当前自动交付目标只覆盖“视频”或“视频＋发布包”，不能自动识别或验收用户另外要求的独立文章等成果；须单独列出路径和完成状态，不能以视频或口播脚本代替。详见 [交付与清理边界](docs/delivery-safety-2026-10-28.md)。

`run` 的守卫只拦实际执行底层脚本（如 `node gen.mjs`），`sed`/`grep`/`cat`/Python `open()` 里的同名文件属于只读查看，不再被误拦。复合命令即使最终 `exit=0`，只要输出里有 `✗` 失败行，就记为失败并保留原因。

### 生成与改稿的共同约束（2026-10-25）

- **同一判据**：`build` 的浏览器提示、`fit`、普通渲染与自动制作共享布局观测/判定；对比度共享像素采样，带背景的透明分组逐层核对实际背板，不重复合成。布局检查增加入场、收尾、每 2 秒及字幕触发边缘，逐帧内判断，不拼接不同时间的对象；只检查本场正文，正常 push/wipe/fade 的邻场进出不冒充场内越界。每场须有自己的主体观测证据，空场不能借其他场或全局页码通过。对比度仍测本场停稳时刻。旧严格回执随布局策略版本失效。
- **先验候选再提交**：现有作者稿不能经 `write_file` 无指纹整份覆盖（空文件或指纹未变的安装脚手架除外）。短补丁、追加、单场替换先计算候选；场景逐块检查完整语法和 `render` 结构，再执行 CAS、备份与原子单文件提交。初稿分场也用同一场景结构判据。可信阶段指定了场号时，短补丁与替换同样不能越场；本场内部可联动改布局。
- **如实记录影响**：受控作者编辑返回 `affectedScenes` / `sharedImpact`，表示源码归属变化，不是运行时依赖、语义或视觉通过的证明。共享输入仍按现有产物签名使整片失效。
- **内容驱动布局**：标准构建在场景执行前提供 `VH_LAYOUT.flow` / `grid`，让实际换行自动推动后续组件，不裁字、不自动缩字号。旧场景不强制重写；自定义组件可声明 `data-vh-component`。有意叠放只允许在具体元素显式命名 `data-vh-overlap`，不能靠“重叠很多”自动豁免。
- **对比不碰正式稿**：新 `snap` 保存真实预览 sidecar；`compare` 不再临时换源码、运行生成器或用当前引擎伪造旧画面。旧快照没有预览、素材已变化或快照损坏时明确拒绝；`undo` 不把旧预览恢复成当前预览。

整体方案、实施边界和后续路线见 [生成与修改的整体可靠性方案](docs/holistic-visual-edit-plan.md)。本轮并非完整的多文件候选/视觉回归事务：作者稿提交前目前是结构与范围检查，浏览器检查在构建/出片执行；语义保留、逐组件授权和所有动画时刻仍不能自动保证。

### 大文本输入

首页与“指挥”的输入框超过 4000 字时自动分页：`textarea` 只渲染当前页，翻页控件显示「第 N / M 页 · 全文 X 字」，提交时按原顺序拼回全文，换行与空白不丢。

原因是 `textarea` 每敲一个字都会重排全部内容，成本随「字数 × 换行行数」增长。实测 5.6 万字 / 4000 次换行时每次按键 p95 约 39ms，分页后降到约 3ms。样式类方案（`contain`、`content-visibility`、`wrap=off`、固定高度）实测均无效。

### 完成与成片过期
“已完成”不再等于“存在过视频”。如果 `out/video-voice.mp4` / `out/video.mp4` 不存在，或 `脚本.md`、`scenes.src.js`、`engine.tpl.html` 比成片新，项目会显示**成片落后**及具体原因，提示重新测量与渲染。这是可见性提示，不会替你决定是否重渲。

### 换文章的画面质量

可复用的是镜头、字幕、排版与生成管线，不是某条片子的题材素材、构图和审阅结果。
每篇文章按内容选择简洁画面，不默认要求两版试稿或关键样片；用户主动要求视觉探索时才增加。图片存在和测试全绿不能证明看过或讲清楚。
`comet` 的机身特写是专门设计的样片，**尚未证明任意文章一键生成都达到同等质量**。

## 发布台（双击 `打开发布台.command`）

视频做完后不用再去 B 站网页手填表单：本地选项目 → 改标题/标签/简介 → 选分区 → 一键投稿。
关窗即退出；窗口卡住时用 `关闭发布台.command`。

- **走接口，不走网页填表**：`preupload` 申请线路 → UPOS 分块上传 → 封面上传 → `/x/vu/web/add/v3` 提交。B 站页面改版不影响，失败能看到服务端 code 与 message。
- **登录只扫一次码**：手机 B 站 App 扫码，凭据存 `~/.config/video-harness/bilibili.json`（0600），不进项目、不进交付包。保存整份投稿相关 cookie（含 `buvid3` 等设备标识，缺了会被风控拦成 403），仅排除体积大的追踪指纹。
- **扫码后自动体检**：登录成功不等于能投稿。当场检查登录状态、创作中心接口、上传线路三项，任一失败直接说明原因，不等到上传完才报错。体检只读，不传数据、不投稿。
- **试运行不发请求**：右侧先显示将要提交的完整内容（含封面尺寸/体积/比例提醒），确认后才上传与提交。投稿不可撤销，程序不会自动提交，也不会在失败后重试提交。
- **不伪造成功**：分区未登录时显示离线清单并标注；封面 < 960×600 直接拒绝而不是放大糊弄，只有体积超限才转码并写明。
- 置顶评论 B 站没有公开接口，提交成功后复制手动贴。

用法、边界与模块划分见 [desk/README.md](desk/README.md)。业务逻辑不依赖 Electron，`node --test test/desk-bili.test.mjs test/desk-publish.test.mjs` 可脱离窗口验证协议与编排。

## 工作台（`vh preview` → http://127.0.0.1:8144）

- **开始前选交付**：首页可选择“仅视频 / 视频＋发布文案”，配置先落盘再派发任务；CLI 对应 `vh new <目录> --delivery video|publish-package`。非法目标不会创建半成品项目。
- **阶段与下一步**：播放器概览展示脚本、画面预览、配音实测、带声成片、发布文案和人工审阅，提供对应标签入口。执行阶段来自当前 task/attempt 的记录，不借用上一任务，也不虚构进度百分比或剩余时间。
- **草稿可选保存**：首页文章和项目聊天框均提供勾选保存，只存当前浏览器，默认不保存，不上传。勾选后刷新恢复全文（含分页长文），取消勾选会清除本机副本但不删除页面输入；失败不清稿，服务器确认提交成功且输入未变才清除草稿。敏感内容不建议保存；超长或存储失败会明确提示未保存。
- **断连可见**：状态读取失败时保留最后结果并标明不是实时状态，恢复连接后清除提示；后台只重连读取，不自动重新派发任务。提交超时须先核对项目/任务是否已创建，避免重复消耗额度。
- **运行中保护**：网页清缓存和删除项目接口拒绝正在制作或仍有工具子进程的项目；先等待或取消再操作。失败不会在界面误报成功或丢掉原卡片。

成熟度判断、本轮边界与后续路线见 [docs/product-maturity.md](docs/product-maturity.md)。

- **索引页**：所有项目一屏列出——静帧缩略图、时长、成片下载、**占地与缓存**、「打开播放器 / 清缓存 / 删除」
- **播放器**（`/?p=<项目相对路径>`）：
  - 左：直接播 `scene.html`（完整 16:9 等比缩放）+ 同步旁白音轨（🔊 可静音）+ 变速/拖动/章节跳转
  - 右：**脚本对照**（播到哪句亮哪句）、**分镜**（每场真实静帧，标出「变了」的场）、**成片**（配音版优先，带 Range 秒拖）、**指挥**（三模式入口）

## 解释质量（`references/clarity.md`）

用户的「把事情讲清楚」协议落成了可执行检查：机器判定的部分 = **依赖闭合**
（术语首现未定义、依赖倒挂、开场前 3 句依赖未闭合、受众基线里「不知道」的词是否解释）；
机器判不了的部分 = 机制对不对、隐性知识补没补 —— 进 `审查-解释.md` 的逐场五问，**退出码不等于讲清楚了**。

## 画面质量（`references/quality.md`）

从 `op7418/guizang-product-video-skill` 与 `whyubel1eve/promo-film-skill` 提炼：一套缓动、停死原则
（≤0.02px/帧 的缓慢运动会变成"字在抖"）、文案等镜头停稳、20fps 静态颗粒、收口 0.7–1.3s。
`vh enhance` 注入的手法库：确定性画布层 `FX.fxCanvas`、静态纸纹 `FX.grain`、呼吸光斑 `FX.breathe`、
停死运镜 `FX.dolly`、速度模糊 `FX.camBlur`、确定性随机 `FX.mulberry`。

### Motion 正确性与节奏审阅

- `vh motion` 是动作起点的**静态线索**：支持 `t/rt`，排除注释/字符串与场外时间，提示动作扎堆；不会把动画次数冒充可见运动或审美质量。
- `vh alive` / `vh pacing` 按完整画幅采样，排除字幕和进度条；报告最长连续低差区间，而非要求画面一直动。阅读停顿可以保留，不靠 drift 刷分。
- harness 的生成出口统一安装可 await 的 `renderAt(t)` 屏障，等待素材与新版 `videoEl` 的目标帧；不再在解码结束时异步回零。长转场暂时安全降级整片渲染。
- 旧工程需显式 `vh enhance --force` 更新手法库，再 build、审阅并整片渲染；不会自动覆盖既有模板和视频。
- 增量需完整帧缓存；仅有 MP4 分段不足以重编边界相邻段。编辑期默认保留帧；显式清帧后自动整片回退，不会截图完才报缺帧。

具体修复、兼容边界和成熟产品差距见 [Motion 专项报告](docs/motion-maturity-2026-10-23.md)。

**第二轮：动作编排与取景。** 新版 `VH_FILM.compileMotion` 可按当前字幕编排对象状态、时长与阅读保持，拒绝歧义触发、同属性抢动画和时间越界；`fitCamera` 按主体矩形与字幕安全边计算镜头。旧版 FILM 显式用 `vh enhance --film --force` 备份升级。可预览的同内容 before/after、精度边界与用法见 [Motion 高级感与准确度](docs/motion-polish.md)。
