# Motion 打磨与产品差距 · 2026-10-23

## 结论

现在是**已有完整制作链、适合熟练操作者内测的工作台**，还不是稳定的自动 Motion 导演产品。最缺的不是更多粒子、缓动或动画库，而是：**动作跟随讲述推进、同一帧可复算、修改后可验证、用户能定位并修正问题**。

本轮优先修正确性与检查口径；没有重写用户项目、修改既有成片、调用付费模型或给未看过的视频登记人工审阅。

## 现场证据

只读检查了 `projects/图像生成模型格局与能力差-1023`。运行：

```sh
node vh.mjs motion --dir "projects/图像生成模型格局与能力差-1023"
```

8 场的场内时间合计约 451 秒。新检查器识别 51 个字面量动作起点，但它们明显集中在各场开头。这不是逐帧审片结论：循环、变量时间和自定义动画可能漏检。

其中 S7 有更直接的源码证据：`scene.html` 的场景区间约 72.07 秒；`scenes.src.js:632–646` 中矩阵、三问与结语约在前 5.1 秒完成入场，之后没有新的主体状态推进。不能据此断言编码后每一帧都静止，但足以说明“长旁白 + 一次性展示整页”的编排问题。

这场应优先改成：概览矩阵 → 随讲述聚焦对应用途与证据强度 → 保留同一对象进入三问筛选 → 最后显示结论并停稳阅读。时机从当前实测旁白取，不凭空填一组秒数，也不靠整页持续漂移掩盖长停。本轮没有擅自改写该片的内容或重新出片。

## 本轮已落地

| 问题 | 改进 | 验证方式 |
|---|---|---|
| `oneTake` / `cameraShot` 用“曾经停稳”缓存，跳到另一保持段仍留旧构图 | 按本次计算的 transform 保证终值；`oneTake` 同时使用传入的世界尺寸选项 | 执行原语，比较直达、顺序采样、倒播与新实例结果 |
| `fxCanvas` 同一帧槽使用第一次调用的任意小数时间 | 使用 `slot / fps` 规范时间；验证 fps | 正向、回跳、同槽及负时间测试 |
| 素材视频只设置 `currentTime`，截图不等 seek 完成 | `videoEl.seek/freezeAt` 返回等待任务，跟踪当帧媒体屏障；快速改目标作废旧等待，结尾定住，失败明确拒绝 | 本地 ffmpeg 生成红蓝视频，真实浏览器截图核对颜色、倒播及不同页面结果 |
| 初始资源 gate 异步回零，renderer 没有等待约定 | `renderAt(t)` 返回可 await 的 Promise；等待字体、素材和当帧视频，不再异步重画 0 秒 | 延迟就绪、多个请求、保留转场包装标记测试 |
| 坏图可能直接被当作加载成功 | 新版 `assetsReady({strict:true})` 在加载/解码失败或超时时拒绝；正式帧屏障使用严格模式 | 浏览器坏图/坏视频失败测试；默认非严格模式仍提供诊断计数 |
| 重测、改幅后重新生成可能丢掉 gate 和转场表 | 在 `normalizeGeneratedMetadata` 统一安装，build / measure / 工作台改幅共用 | 旧 gate 迁移与重复处理幂等测试 |
| 转场表改动只归属文件尾最后一场 | 把共享转场表、帧屏障纳入每场依赖，变化后安全整片失效 | 第一场转场/运行时变动与普通单场改稿对照测试 |
| 旧 renderer 不认识长转场标签的增量 padding | 超过 0.45 秒的非硬切转场自动整片；显式局部渲染拒绝，不静默漏边界 | CLI 实际 argv 测试；这是安全降级，不是已完成新版增量引擎 |
| 清帧后仅剩 MP4 分段，增量截图完成才发现相邻整段缺帧 | 同时核验完整帧缓存；帧不足自动整片，显式局部提前拒绝 | 缺帧、空帧、目录冒充帧与 CLI 实际派发测试 |
| `cut` 也提前一个转场窗口显示下一场 | 硬切可见窗口严格从场景起点开始 | 边界前、边界点和倒播执行测试 |
| `growTo('100%')` 丢单位；零时长出现 NaN | 保留长度单位、拒绝非零混合单位；count/slide/grow 明确零时长语义 | 单位、倒播、零时长与错误输入测试 |
| `motion` 把注释、场外时间和扎堆动作算合格；漏掉 `render(t)` | 屏蔽注释/字符串示例，识别 t/rt、小数与负数，排除场外点，报告过长起点间隔与未知覆盖 | 正反例测试；不再把起点间隔叫“静止时长” |
| `alive` 裁画幅、字幕刷分、采样数量被当秒数 | 全画幅采样、隐藏字幕/进度条，按实际时间统计，修正最长低差区间起点 | 自建横竖屏浏览器场景与不同步长测试 |
| `pacing` 用累计低差代替最长连续、比较失败也可能成功 | 按连续段计算；ffmpeg 失败返回错误；原路径加载素材，finally 清本轮临时目录 | 交错低差、相对素材、失败及清理测试 |
| 制作与审阅仍只有一次入场骨架 | 分场能力说明加入对象状态/讲述触发原则；画面体检加入动作静态线索，并明确连续观看/试听未执行 | 能力提示与画面体检回归测试 |

现有 `enhance --force` 也改为按明确的 FX 结束边界更新，保留后面的作者助手与 FILM；无法识别边界就拒绝覆盖。转场 `--inject` 可以备份升级旧标准块。

补充边界回归：图片的加载与 `decode()` 共用有限等待预算，永不完成的请求/解码也会失败；没有源注释时不再删除生成调用前的换行，保留作者的行注释边界并保证重复处理幂等。

## 距离成熟产品的剩余工作

| 优先级 | 差距 | 下一步与验收标准 |
|---|---|---|
| P1 | **缺少结构化动作编排层**：主要依赖模型临场写 JS，检查发现问题后仍靠改代码 | 先把“旁白锚点 → 对象 → 前后状态 → 动作 → 阅读保持”做成可检查的场内描述。换稿、重测后触发点仍正确；锚点缺失/歧义必须报错。已有 `VH_FILM.cue` 可复用，不先换渲染框架 |
| P1 | **连续审阅没有版本闭环**：静态/像素指标不能判断解释得对不对 | 工作台按时间段记录问题、跳转预览、局部修订；人工回执绑定最终视频指纹。画面/音轨改过，旧回执失效。不能由机器补勾“已看过” |
| P1 | **全链确定性还未证明**：本轮只覆盖所修原语与合成视频素材；默认 jitter 仍偏向同点重复 | 增加动作前/中/后、顺播/倒播/随机跳播、多个 worker、整片与增量的编码后对照。稀疏关键帧 `kf` 的属性继承仍需单独统一，不能宣称任意自定义场景都纯函数 |
| P1 | **运行时分散在项目副本**：用户模板/renderer 与 skill 各有版本 | 增加能力版本与迁移预检，迁移前后渲染同一组基准片。当前采用显式备份升级，不静默覆盖所有工程 |
| P1 | **增量 renderer 的边界与编码段未统一** | 让重渲区间对齐所有受影响编码段，或直接安全拼接局部结果。当前保守要求完整帧缓存；`go` 默认清帧后，下次修改会整片回退。频繁改稿可先保留帧，不能把只有分段视频说成安全增量 |
| P2 | **缺少 motion 时间线与可解释的编辑入口** | 显示旁白、动作区间、保持段、转场与失效范围；让用户能改“此句讲完再揭示”，而不是找到 JS 里的第几个 `.9` |
| P2 | **视听包装还没有稳定验收** | 对旁白停连、动作重音、音乐 ducking、字幕可读保持和镜头收口做连续试听；保留同内容样片对照，不能用装饰运动替代内容 |
| P2 | **安装、性能和资源预算尚非可分发产品** | 补锁定依赖与内核、首次运行诊断、每阶段耗时/磁盘统计、并发和取消压力测试、低磁盘故障测试。当前 package.json 没有完整表达可复现环境 |

另外，`lib/scene-builder.mjs` 的多场自动生成入口尚未接入，且存在待修的运行时问题；不能把它算作已交付的自动导演能力。美术参考中的部分 pilot 文件在当前工作区缺失，需恢复可复现样片或撤掉失效入口。

**建议顺序：先做一个真实内容的 20–40 秒完整动作段并连续审阅，再把通过的“讲述—动作—保持”关系抽成编排协议，最后扩展整片。** 不是再加十种转场，也不是把“每几秒必须动一次”设成硬门槛。

## 使用与兼容边界

新项目使用新版手法库。旧项目不自动改模板；需要应用原语修复时，在确认没有运行中的制作任务后执行：

```sh
node vh.mjs enhance --force --dir "<项目目录>"
# 仅对已使用/需要多转场运行时的工程：备份升级标准转场块
node vh.mjs transition --inject --dir "<项目目录>"
node vh.mjs build --dir "<项目目录>"
# 首次升级后复核预览，再按正常人工闸门整片渲染
node vh.mjs render --all --dir "<项目目录>"
```

- 没有绕过人工审核、对比度或版式门槛。上述命令是升级说明，本轮没有代用户执行。
- 正式 renderer 需要返回 `window.renderAt(t)` 的 Promise（现有标准 renderer 的 `page.evaluate(t => window.renderAt(t))` 满足）。自定义 renderer 如果丢掉返回值，仍不会等待；直接运行裸 `gen.mjs` 也不走 harness 的生成后处理。
- 当帧视频等待只覆盖新版 `VH_UI.videoEl`。作者直接设置原生 video、使用 CSS animation 或依赖上一帧状态的代码没有被自动改写。
- `maskJS` 是保守的词法屏蔽，不是 JS 语义解析器；模板插值与动态表达式可能漏检。`motion / alive / pacing` 只给线索，不能签发“节奏合格”证明。
- 本轮没有对现有 7 分多钟带声成片做完整人工视听审阅；测试通过不代表该片已达到发布质量。

## 验证入口

```sh
npm test
node scripts/test.mjs test/motion-runtime.test.mjs test/motion-scan.test.mjs test/alive.test.mjs test/pacing.test.mjs
```

测试使用隔离临时工程、本地 HTTP 和合成媒体，不上传素材、不调用真实模型。没有新增依赖。
