上述 command 包含 step，不能相加。它们不包含模型等待、外部 ASR 和人工审阅。历史记录未分别测量截图和编码，不能据此推断硬件编码能节省多少。

`grep-vs-rag` 另有一次 renderer 成功、耗时 413.631 秒，但外层 go 失败的记录。缺少该次完整失败原因，不能断言随后重渲没有必要，也不能把旧产物直接认定可复用。

## 失败定位

新性能事件在同一 CLI 进程内带相同 `runId`，可关联外层命令与子步骤；可用时记录真实退出码。输入变化、渲染器变化、子步骤失败、渲染器失败及中断使用固定原因分类。未识别的错误保留通用分类，不保存原始错误正文、命令参数或凭证。

`node vh.mjs performance --dir <项目>` 同时显示最近失败；旧日志没有原因时显示 unknown。此功能用于诊断，不会改变质量结论或让失败产物跳过验证。

## 已实施

| 改动 | 验证 |
|---|---|
| 已知标准渲染器模板可安全升级（完整 SHA-256 识别，未知自定义不覆盖，原稿备份） | 语法检查、幂等、自定义拒绝、真实媒体基准 |
| `--scenes` 改为离散帧区间：只重截所选场及其转场邻域，不再截取两场之间未改的场 | 真实媒体基准与临时项目；同一片子旧路径 150 帧，新路径 66 帧，解码视频 SHA-256 相同 |
| 截图结束立即释放浏览器，再开始编码 | 真实媒体基准阶段顺序 screenshot → encode → concat |
| 渲染器分别上报截图、编码、拼接耗时；vh 只接收本次 `VH_RENDER_RUN_ID` 的整行事件 | 伪造 batch、错误 schema、错误 runId、负数耗时均被拒绝 |
| macOS 内存预算读取压力与短时交换增量，健康时最多放宽到 2 路 | 单元测试；实机曾观测到 2 路，内存吃紧时仍为 1 路 |
| 已知标准配音脚本模板可惰性加载模型（缓存全命中时不加载） | 真实 Python mock 冷/热执行，WAV 与 timing 逐字节一致；未知脚本不覆盖 |
| 性能日志关联同次执行，记录退出码与固定失败分类 | 关联、脱敏、未知原因不冒充已归类 |

已发布项目中的两个渲染器和两个配音脚本都与已知模板完全一致，具备安全升级条件；但本轮遵守“不改已发布项目”，没有对它们执行升级。

## 实测

### 真实媒体基准（10 秒合成片，非生产项目）

同一合成片只改第 1、5 场：旧渲染器重截 150 帧、耗时 5.32 秒；升级后只截 66 帧、耗时 4.35 秒，两版解码后视频 SHA-256 完全一致。该差异主要来自少截未改场次与减少无效尾帧，不代表长片同等比例的提速。

### 临时真实项目（2 场，17.24 秒 @ 12fps）

整片 207 帧：截图 3.74 秒、编码 0.53 秒、拼接 0.03 秒。只改第 2 场后：只重渲 126–207 帧（81 帧），分段新编 2、复用 1。以上是合成画面的短样，不包含真实长片的字体、图片、视频素材解码成本。

## 边界与未验证

- 真实 442 秒项目未重渲；无法给出整片提速百分比。
- 增量范围仍包含转场邻域；相距很远的多个改动不会再桥接中间场次，但字幕、总时长和素材仍属于共享身份，追加片尾等改动可能整片失效。
- 并发最多放宽到 2 路是保守启发式；短采样不能保证运行中不交换。运行态恶化不会动态降并发。实际并发仍取决于当时可回收空闲页；同一台机器在内存吃紧时仍会回到 1 路。
- 未启用硬件编码；未改变默认 CRF、preset、分辨率、帧率或质量阈值。
- 配音缓存 key 仍保留原语义；模型身份变化不会自动失效，惰性加载不改变这一点。
