# 发布台并入工作台 · 2026-11-08

## 为什么并

原来发布是独立 Electron 窗口（`desk/main.mjs`），视频在工作台做、发布在另一个窗口发。
两个界面各自维护一套表单，字段映射、分区校验、封面检查都可能走偏。

关键事实：**`desk/` 里除了 `main.mjs` 之外都不依赖 Electron。**
`service.mjs`（投稿用例）、`publish.mjs`（编排）、`bili.mjs`（协议）、`publish-contract.mjs`
（校验与 payload）本来就是纯 Node 模块。所以并进网页不需要重写，只需要接线。

## 新的分层

```
www/publish.html            页面骨架
www/publish-panel.mjs       界面与调用顺序（不写业务规则）
        ↓ HTTP
lib/publish-api.mjs         接线层：凭据来源、登录会话、批量闸门
        ↓ 直接 import
desk/service.mjs            投稿用例（已测）
desk/publish.mjs            上传→组 payload→提交
desk/bili.mjs               B 站协议
desk/publish-contract.mjs   校验与字段映射
```

`desk/main.mjs`（Electron）仍保留，`npm run desk` 还能用，但主路径是网页。
双击 `打开发布台.command` 现在开的是 `http://127.0.0.1:8144/publish`。

## 低耦合的具体做法

| 原则 | 实现 |
|---|---|
| 业务规则只有一份 | 网页与 Electron 都调 `desk/service.mjs`，没有第二份校验 |
| 前端不复制协议常量 | 分区清单接口连同 `taxonomy` / `human` / `compatTid` 一起下发，值来自 `desk/partitions.mjs` |
| 页面不认识项目结构 | 项目字段由 `desk/harness-adapter.mjs` 统一产出，换存储只改适配器 |
| 依赖注入到底 | `createPublishApi({ root, home, fetchImpl })`，测试不需要真实网络与真实凭据 |
| 副作用可替换 | 批量发布的 `sleep` 与 `submitOne` 都能注入，测顺序不测等待 |

## 修掉的一个真实 bug

接线时把 `createClient` 写成了 `cookies => createBiliClient({ cookies })`，
但 `service.mjs` 的适配器约定是传**选项对象**。结果 cookies 被多包一层，
所有接口都返回「账号未登录」，而界面上看起来像"登录过期"。

这类错误正是两套实现最危险的地方：它不会崩，只会静默失败。
现在 `createClient: options => createBiliClient({ ...options, fetch })`，
并把「未登录」与「没凭据」在 API 层分开（`overview.loggedIn` 与 `account`）。

## 界面

两栏：

```
┌─ 项目 ────────────┬─ 投稿内容 ─────────────────┐
│ □ 标题 有文案 22MB │ 标题 / 分区 / 标签 / 简介    │
│                   │ [试运行] [确认无误，提交投稿] │
├─ 批量发布 ────────┤                             │
│ 间隔 3 秒          ├─ 提交前预览 ────────────────┤
│ [自动发布已选]     │ 问题 / 提醒 / 完整 JSON      │
└───────────────────┴─────────────────────────────┘
```

首页与项目页都加了「发布台 →」入口；项目页「发布」标签里也给了按钮，
但那一页只管发布文案（标题/简介/标签），投稿在 `/publish`。

## 仍然刻意保留的限制

- **分区必须人选。** 投错分区发出去撤不回来，程序不猜。
- **提交要确认框。** 单条与批量都要显式确认，`confirmed !== true` 直接拒绝。
- **失败即停，不自动重试。** 批量里任何一条失败，后面的不提交。
- **结果未知不重发。** 错误发生在提交阶段后，提示先查稿件管理。
- **写请求过同源检查。** 跨站来源一律 403，浏览器里的任意页面不能替你投稿。

## 距成熟产品还差什么

已解决：单条发布、批量发布、分区、封面、登录、失败处理、可测性、低耦合。

仍然缺：

1. **没有真实投稿过。** 上传与提交协议只用假客户端测过；真实 B 站风控、
   分块超时、封面上传失败后的清理，都没在线上验证。
2. **定时任务的失败可见性不足。** 失败记进 `schedule.json`，但不会弹通知；
   用户得自己去看工作台队列。
3. **没有成本护栏。** 定时 + 自动找选题可以连续跑，模型费用没有上限控制
   （只有每日支数上限）。真按 3 支/天跑，费用取决于单支时长与重试次数。
4. **agent 的 project-local 限制。** `--agent vh-builder` 只在仓库目录内可见；
   别处启动会回落到内置 agent，制作纪律失效。
5. **没有并发保护跨项目。** 两个项目同时制作会抢 CPU/内存，只有渲染层有预算，
   调度层没有全局并发上限。
6. **审阅仍是提示不是闸门。** `review.json` / `claims.json` 缺失只提示不阻塞，
   这是 content-first 策略的有意选择，但发出去的内容没有第二双眼睛。
