# 每日发布排程

## 用户语义

原网页「批量发布」是立即对一组作品连续投稿，秒数只是条与条之间的等待，不是日常内容排期。现在改为每天固定时点，每个时点取一支有成片的待发作品。可设多个时点，例如每天 12:30、20:00；七天日历展示重复排期，不是指定单次日期。

默认关闭。「保存排程」只保存配置并暂停，允许无视频、无登录、无分区；「启用自动发布」才校验账号/分区并要求明确确认。修改后保存会撤销旧授权，需再次启用，不能把新范围静默加入旧授权。队列可为空、可包含未完成作品；没有就绪成片时不制作、不上传、不写投稿尝试。暂时未完成的作品保留等待，不阻塞后面的就绪成片。

发布范围默认 `selected`，只观察明确保存的项目；显式选择并确认 `production-queue` 后，观察 `schedule.json` 制作队列当前及以后关联的 `projects/<项目名>`，按队列顺序取候选。不让制作模块主动调用投稿，不默认扫描所有磁盘视频，也不把制作队列的状态复制到发布状态文件。

成功后出队；真实投稿失败暂停，不在下一次检查或次日重试。制作/取消尚未结束、成片过期、资料未齐都不是一次投稿失败：保留排程等待。若快照后项目又开始制作，最终投稿租约会阻止上传，本时点记录 `waiting` 并保留启用，等下个时点。暂停不会撤销已开始的投稿。重新启用也不能绕过账号级未知结果、防重或冷却保护。到点表示开始投稿，上传和平台审核需要额外时间。

时区取运行服务的本地时区，不取浏览器时区或 UTC 日期。只处理当前指定分钟，不追补过期时点；启用当前分钟也不会立即发。服务应持续运行，关闭页面不影响，退出服务/休眠可能错过时点。夏令时不存在的时刻跳过，重复时刻凭本地日期时点去重。

## 低耦合边界

| 模块 | 只负责什么 | 不负责什么 |
|---|---|---|
| `desk/publish-schedule.mjs` | 时点/队列校验、本地日期、到点判断、七天预览 | 文件、计时器、网络 |
| `lib/project-state.mjs` | 共用进程/制作锁事实、任务完成观察、成片快照读取边界 | 发布授权、排程计时 |
| `desk/publication-state.mjs` | 将任务/成片/资料/投稿保护投影成发布状态与队列统计 | 文件、进程、上传 |
| `lib/snapshot-service.mjs` / `lib/snapshot-worker.mjs` | 有界只读 worker，媒体/文案核验不占 HTTP 主线程 | 状态副本、付费调用 |
| `lib/publish-scheduler.mjs` | 持久队列、版本冲突、时点认领、调用注入执行器、失败暂停 | 视频制作、B 站协议、网页表单 |
| `lib/publish-api.mjs` | 读取成片候选、绑定账号和分区、复用发布用例 | 时间规则计算 |
| `desk/service.mjs` / `desk/publish-transaction.mjs` | 单条真实投稿、捕获账号核对、账号锁、防重、未知结果保护 | 每日排期 |
| `lib/server.mjs` | 生命周期启动/停止、同源 HTTP 接线 | 浏览器计时与制作派发 |
| `www/publish-schedule-panel.mjs` | 时间输入、队列排序、日历、显式确认与状态显示 | 自动投稿计时、上传实现 |

网页与排程共用同一发布服务实例。排程执行依赖 `getCandidate`、`submitOne`、`accountKey`、`clock` 注入；测试不需要真实登录或上传。

### 项目状态不是两个页面互相同步

工作台的 `workbenchTaskStatus` 委托给共同状态边界；发布草稿在媒体核验前后读取相同的制作事实，主线程在等待 worker 后再检查任务身份，防止下一轮制作继承旧成片结果。取消协调只在服务线程执行；worker 的 `reconcile:false` 观察既不结算取消任务，也不回收锁的遗弃元数据门，不会覆盖主线程新创建的任务。不会以 `status=completed` 或 `hasVideo=true` 单独判定可发布。

发布投影包括：`producing`（制作中）、`waiting-video`（无成片）、`stale`（等当前版本）、`needs-attention`（资料待补）、`ready`（素材就绪）、`submitted`（已投稿）、`blocked/unknown`（投稿保护阻断）。人工作品审阅声明与技术/素材就绪仍分开，未审不伪装通过。

普通列表投影复用本轮素材核验的媒体指纹读投稿日志，不再次整片哈希；制作中只观察遗留媒体元数据，不争抢 I/O 核验不可发布的旧片。自动候选和真实投稿分别执行正式预检，真实账号事务内以异步流重新计算完整指纹，期间两把锁持续持有，不能拿旧快照指纹代替。轻量任务观察也不为暂停原因检查而同步哈希整片，该核验留在只读 worker。

提交先获取项目上传租约并重新读取草稿，再取账号事务锁；上传期间同进程 HTTP 派发、改幅及遵守制作锁的命令都不能覆盖成片。不是仅按 PID 豁免：只有私有 WeakMap 登记且仍匹配当前锁记录的真实句柄，才允许本次投稿内部复核忽略自己的租约，句柄不会传给 worker 或浏览器。账号锁、防重/未知结果日志仍是最终保护，不由页面状态替代。

### 接口版本与交互

- `GET /_api/publish/schedule` 为全局接口，无默认项目也可读，返回 `protocolVersion:2`、配置、日历、下次时点和动态 `pending` 统计。
- `POST /_api/publish/schedule` 使用 `action:save|enable|pause` 与 `revision`；启用才要求 `confirmed:true`。原 `enabled:true/false` 请求保留兼容，不自动迁移旧时间窗口授权。
- 前端拒绝把 v2 操作发送给 404 或没有 v2 标记的旧服务。读取失败显示真实错误与“重新读取排程”，不把状态未知当成队列为空或已暂停。
- 排程、账号、分区、项目分别初始化；某一路失败不阻塞其他配置读取。项目及排程状态每 15 秒轮询，正在编辑的投稿表单、队列、范围和时间不被后台刷新覆盖。
- 旧服务读新磁盘网页是本次灰按钮的原因：旧进程没有新接口。网页不自动杀进程或重启，运行代码更新须先确认无制作/投稿进行中。

## 状态与并发

独立状态：`out/.publish-schedule/state.json`，默认读取不创建文件；保存权限 0600。与 `schedule.json` 制作队列隔离；首页旧的未接通时间窗口控件改为发布台入口，不自动迁移或启用历史发布开关。Electron 旧批量工具/API 兼容保留。

配置编辑及当前时点认领使用同一跨进程短锁，采用原子替换和版本校验。先落盘 `running` 与本地日期时点，再进入原投稿事务；同一时点不能再领取下一支。回执合并最新状态，避免上传期间的暂停被反向开启；短暂锁竞争只重试本地记账，不重试上传。

崩溃遗留 `running` 时停止推进、禁止普通重新启用，必须人工核对原投稿事务日志及平台稿件。没有提供绕过未知结果的自动解锁入口，不应删除状态或日志来恢复。状态损坏失败关闭，不当成空配置。持久时点认领是本地防重，不宣称平台端 exactly-once。

账号切换/退出立即撤销当前排程；后台也检查账号变化。提交用例对实际捕获的凭据再次核对 `expectedAccountKey`，防止外层检查后凭据切换。未出片与已重复投稿的候选跳过；其余投稿问题走原用例并暂停，不跳过账号阻断换视频继续发。

## 发布文案与封面

**封面只看「封面文案」。** `out/cover/manifest.json` 的输入指纹只绑定 `## 封面文案` 的主/副标题（旧版绑定整份文案字节，会在程序补参考链接后误判过期；遇到旧清单会提示重新生成一次）。简介、标签、置顶评论改动不作废封面；图片字节被改或封面文案变了才失效，`coverStatus()` 会给出 `missing / legacy / copy-changed / input-changed / missing-file / tampered` 等具体原因，发布台据此给出下一步。

**参考链接来自项目里已经写下的来源**：claims.json 的 external 证据、`脚本.md` 的「数字与来源」、materials 的检索来源、research 的调研资料。程序只提取和排版，不核证链接是否可达、也不判断它是否支持某句断言。

- 「数字与来源」常写成表格，标签取「说法」列而不是整行；链接在「（2026-11-10 抓取）」这类全角括号处截断，避免把日期算进 URL。
- 一次最多追加 10 条，简介 2000 字上限；两种"没放进去"分开提示（条数上限 vs 字数上限）。
- 程序追加参考链接后会把文案重新关联为 `system`，不等于人工核对通过。

**公开文案检查与参考来源不冲突**：`opencode` 既是本仓库的执行器名，也可能是影片题材里的产品名。只有「用 opencode 跑的 / 由 opencode 生成 / opencode 会话」这类"谁在做这支片子"的写法算内部记录；点名产品、贴它的官方链接不算。此前程序补进去的来源标题会被自己的检查判违规，导致简介里链接被整段删掉——这条已修。

**发布台的封面问题会给下一步**：摘要区除了原因，还给出 `node vh.mjs cover --dir projects/<项目>` 的命令；新增「投稿时上传封面」复选框，暂时不想重生成封面时可以不勾选，投稿本身仍可完成（B 站允许无封面投稿）。
