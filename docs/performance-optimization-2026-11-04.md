### 修改文件与保持不变的边界

- `lib/task-status.mjs`：暂停状态的一次调用只 `readCheckpoint` 一次；校验器不变。下一次查询/恢复仍重新读取；文件变坏、被删、身份失效不会沿用旧观察。HTTP 在 await 前后重新核对任务的逻辑不变。
- `lib/provider-response.mjs`：将原结束标记正则等价为跨块扫描状态；仍保留完整文本，仍在完整响应后执行原 `parseChatSSE` / 工具参数校验。保留大小限制、UTF-8 解码、LF/CRLF、空白跨块、主动取消、读锁释放与半截工具拒绝策略。不是把整个解析器改成流式，也不减少接收字节或网络请求。
- `test/runtime-performance.test.mjs`：新增 3 项回归，覆盖读取次数及跨请求失效、结束标记逐字节切分与旧正则对照、长空白前缀、非 SSE、大小上限及取消。
- `scripts/benchmark-runtime.mjs`：新增离线可复跑基准；复用真实入口，不运行用户项目代码，不访问外部模型。
- `README.md`：加入报告入口。`diagnostics/performance-2026-11-04/` 保存原模块副本、其 SHA-256、原始样本、profile 与测试日志，用于复核；不是新运行时依赖。

## 3. 测量方法

修改生产代码前先运行现有全量 `npm test` 和新增的无生产修改基准，保留 `baseline.json`。先保存两个原模块及 `baseline-manifest.json`，随后用**确切原实现**与新实现复测，而不是用估算公式充当 before。

最终基准 `comparison-final.json`：每个条件独立新 Node 进程，3 次预热、25 次样本；不同 case 交替前后执行顺序；没有与全量测试并行运行。task 使用 1/5 MiB 合成合法暂停检查点，调用真实 `taskStatus(..., {includeDeliverable:false})`；SSE 使用合法内容事件、完整 stop/DONE、中文文本、Web ReadableStream/Response，包含 `readResponseText` **和** `parseChatSSE`。

所有成对完整输出的 SHA-256 相同；只将不同临时工程根路径规范为 `<fixture>`，不删决定、错误或恢复字段。检查点读取次数/字节通过 `fs.readFileSync` 针对目标文件计数；这是应用请求的读取字节，不是物理磁盘流量。OS 文件缓存是热的。

CPU 为 `process.cpuUsage`；可能包含运行时后台线程，不能与 wall time 相加。RSS 为每个新子进程的 `resourceUsage().maxRSS`，包含夹具、预热及 GC，不是单次分配或生产内存上限。每样本前显式 GC，GC 本身不计入操作耗时；这是受控比较，不代表真实调度。P95 用 25 样本 nearest-rank，仅为本次样本分位数，不是稳定 SLA。

## 6. 续做：整体流程、后台资源与回归闭环

### 6.1 审稿失败不是只有模型慢

对原始候选与分片缓存的只读核对发现：同一个输入签名下，**六次候选的 result SHA-256 完全相同**，14 场却返回了 26 条场记录，其中 S4/S6/S8/S14 分别重复 2/9/2/3 条，每次均失败于逐场覆盖校验。代码在完成所有后续请求之后才检查这些结果，并把结构无效分片也写入恢复缓存；再次执行又读取同一无效结果，无法正常推进。

证据：`review-failure-audit.json`、`review-offline-replay.json`。核查期间真实项目输入发生外部变化，因此结构对账使用保存时的签名、场数及候选；没有拿新稿核验旧引文，也不声称对当前稿完成语义复审。未改写用户项目或替用户登记通过。

**实施：`lib/content-review.mjs`**

1. 分片返回后立即执行结构、场次、引文与必要解释校验；无效时保存明确标记的候选诊断，停止继续消耗后续模型请求，不自动涨额或无限重试。
2. 缓存命中也重新校验，拒绝的分片不再反复复用；同一中断任务内保留其余已验证分片。
3. 缓存键绑定真实请求、系统提示、渠道与模型，不再只绑定拼接旁白。缺少活动标记的孤立缓存不能充当新审稿；旧键不冒充新身份。
4. 整稿最终校验、所有 findings、硬失败、原始来源签名及独立两阶段隔离保持不变。分片校验不是通过回执；跨场引用仍可引用整稿原句，任一盲听缺口仍使整稿返修。

兼容性代价：旧版中断缓存没有新的请求身份，首次继续可能需要重新审稿；未给旧缓存补签新键。正常有效回复也增加了一次本地验证，下面如实列出 CPU 成本。

### 6.2 模拟完整审稿编排的前后对照

`scripts/benchmark-review-workflow.mjs` 使用保存的原模块与当前实现，16 场、4 个盲听分片＋16 个判断分片；每条件 9 次、交替前后顺序。包含输入哈希、请求构造、落盘、最终校验及中断/恢复。响应与每次 10 ms 延迟是明确的测试夹具，**没有调用真实模型**。

| 场景 | 请求数：前→后 | 请求 JSON 字节：前→后 | 结论 |
|---|---:|---:|---|
| 正常整稿完成 | 20 → 20 | 60,059 → 60,059 | 完整记录一致，无削减审稿覆盖 |
| 第 2 个判断分片重复场记录 | 20 → 6 | 60,059 → 14,286 | 提前发现同类错误，首次失败轮少发 70% 请求、76.2% JSON 字节 |
| 第 2 个判断分片引用越界 | 20 → 6 | 60,059 → 14,286 | 同样保持拒绝通过，不继续无效等待 |
| 第 3 个判断分片中断后恢复完成 | 21 → 21 | 63,326 → 63,326 | 有效断点恢复不增加模型请求，最终记录一致 |

原始每次 wall/CPU、P50/P95、代码 SHA-256 和结果摘要见 `continuation-review-benchmark-final.json`；成功记录只排除 `reviewedAt` 后逐字节对比，故障按错误类别与未生成通过回执对比，不要求提前失败和整稿失败具有同一个诊断文件名。

**重要限定：**20→6 是首次故障轮的减少，不是“最终成功审稿只需要 6 次”。修复该分片后，余下必要分片仍要执行，不能把推迟的工作算作永久省掉的 token。此改动主要兑现更早失败、更少失败轮浪费，以及解除无效缓存循环；不声称真实模型计算或完整视频制作提速 70%。正常路径的墙钟时间基本不变，本地验证 CPU 有数毫秒额外成本。

新增 `test/content-review-recovery.test.mjs` 覆盖：早停、无效结果不入缓存、只重做受影响分片、坏缓存场次/引用、换模型、缺失恢复标记、跨场引用和全局盲听返修。现有审稿/索引/来源/权限测试继续执行。

### 6.3 先减少不需要发生的后台观察

工作台后台页原来仍不断请求任务、完整快照、画幅和项目列表。这既产生网络/JSON工作，也可能触发服务器素材哈希、探针和 worker 调度；迁到 worker 不等于减少工作量。

**实施：**新增 36 行 `www/visible-polling.mjs`，供 `panel.js`、`index.html`、`settings.html` 复用。隐藏页暂停自动 GET；恢复可见立即刷新；完成后再等待下一周期；在途请求不重叠，多次 visibility 事件合并。显式刷新保留，既有 POST/取消/授权/渠道选择不变；GET 复用 `http.mjs` 的超时，不跨请求缓存成功结论。首页去掉启动时多余的一次列表读取。

真实 Chrome＋真实本地 HTTP、同一临时工程、12 秒受控隐藏窗口：

| 页面/接口 | 请求数：前→后 |
|---|---:|
| panel chat / state / format | 8/6/3 → 0/0/0 |
| 首页 projects | 6 → 0 |
| 设置页 projects | 4 → 0 |
| 合计 | **27 → 0** |

对应 CDP 记录响应传输 **43,678 B → 0 B**；同长可见窗口请求总数 **26 → 26**，首页启动列表请求 **2 → 1**，恢复时五个页面/接口刷新各发一次，页面异常均为 0。没有通过减少可见页刷新覆盖来换这个结果。

### 6.4 恢复可信测试基线，不放宽生产契约

### 6.6 完成边界与剩余瓶颈

- 已把确认的运行时重复扫描、暂停状态重复读取、审稿坏分片失败/恢复链和后台重复观察做成可复核闭环，而不只交付微基准建议。
