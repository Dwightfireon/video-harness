# 发布台可靠性优化 · 2026-11-13

## 本轮范围

落实评估中的第一批改动，并把底层已有真实上传进度接入网页。未加入独立内容审稿、自动评论/私信、自动重发或自动启用排程；未修改任何已发布视频。

## 改动

### 统一保存与防丢

- 「保存作品投稿资料」保存标题、简介、标签、封面选择、商业声明及单条分区，替代页面中单独保存声明的按钮。原始 `发布文案.md` 不改写，制作和交付包仍使用原始作者文案；独立设置仅用于投稿。
- 保存文件为项目根目录 `.publish-form.json`，含 `version/revision/savedAt/fields/partition`。用独立设置锁和原子替换避免交叉写，版本冲突返回 HTTP 409，不覆盖他人保存。配置损坏会报错，不当成未保存或取消声明；不提供强行覆盖损坏配置的捷径。
- 可先保存不完整草稿，不以保存为发布授权。正式提交仍保留标题/标签、文案限制、实时分区、媒体和事务核验。保存不需要登录，不启用或重新启用每日排程。
- 页面按作品保留未保存编辑，用当前标签页 `sessionStorage` 应对刷新，用基于项目路径的非秘密 `editorKey` 防止同一服务端口换工作区后串稿。不是永久备份；浏览器禁止存储时只保证本页内存暂存，关闭页面仍有未保存提醒。
- 保存期间继续编辑、切换作品、后台刷新、保存版本冲突均不覆盖正在编辑的内容。主动读取服务器资料会确认替换未保存修改。
- 后端投稿草稿优先读取统一设置。每日排程/批量取已保存标题、简介、标签、封面选择和声明，但仍使用排程/批量明确选定的分区；单条表单可覆盖本次输入，不暗中保存。
- 旧 `.publish-promotion.json` 继续读取。已有统一设置后，旧声明保存接口更新统一设置中的声明，不创建互相冲突的两个有效来源。旧项目不自动写回、迁移或重新发布。

### 封面和状态

- 无封面时勾选框仍可操作；取消上传后摘要明确写「本次不上传封面」，不继续显示红色缺封面阻断。保存该选择后，队列就绪判断和正式执行也遵守它。
- 列表显示「待发资料就绪」，不把未选分区的当前表单说成可直接提交；表单角标由当前检查结果决定。
- 本地就绪、表单可提交和平台已收稿不等于平台审核通过。平台持续审核/下架状态同步与完整发布记录不在本轮内，不伪造完成。

### 提交、错误与进度

- 从预检开始冻结作品和表单，防止预检等待期间切换作品或分区导致确认信息错位。确认框包括作品、账号、分区、封面是否上传和商业声明；确认的账号身份在服务端再次匹配。
- 业务失败结果完整返回 `kind/retryable/waitMs/advice`，不只对 HTTP 抛错做分类。未知结果仍由持久投稿事务阻断，不因刷新或等待解锁。
- `GET /_api/publish/progress?id=…&progressId=…` 只读当前同一操作的进度；操作身份由前端随机生成并随明确确认的提交发送。其他操作不能覆盖当前进度。内存只保留一份，不保存 cookie、正文、上传凭据或资源地址。
- 服务层把真实分块字节与步骤回调交给 API。页面轮询读取确认的字节比例，不推算虚假百分比或剩余时间，进度不可用不会被当成未提交。上传 100% 不代表平台已经收稿，收稿也不代表公开。
- 进度不是持久投稿事实：服务重启后可能丢失，应查原有事务回执与稿件管理，不按进度缺失重发。现有账号锁、媒体指纹、项目租约、重复/冷却/未知结果保护保留。

## 新接口

- `POST /_api/publish/form`：`{ id, revision, form }`，返回 `savedForm`。写请求仍过同源与项目路径检查。
- `GET /_api/publish/progress`：当前操作进度，无发布或重试副作用。
- `/projects` 返回 `savedForm/coverWanted/editorKey/formSupported`；`/plan` 返回 `formSupported: true`。旧进程未加载新接口时保存明确失败，不假装已保存。
