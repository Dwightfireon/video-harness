# 生成与修改的整体可靠性方案

## 目标与不变量

不是分别优化几个报错，而是让作者输入、场景生成、局部编辑、质量检查和成片复用遵守同一条链路。

1. 新要求必须落实；未授权内容不得顺带改动。
2. 修改范围不等于文件范围：局部修改必须考虑场景内部布局依赖，共享引擎变化必须按全片影响处理。
3. 初稿、改稿、普通渲染和自动制作使用相同的真实布局判据；检查失败不能视为通过。
4. 只比较同一帧中同时可见的对象；合法的父子包含、背景承托和显式叠放不等于碰撞。
5. 成功写入不等于成功修改；候选、正式作者稿、预览、实测时间轴和媒体不能串版。
6. 拒绝或失败不覆盖现有好稿；并发编辑、新插话和恢复不得绕过版本保护。
7. 机器抽样不是审美、语义和连续观看验收，不扩大已有质量承诺。

## 实施阶段

### A. 共用观测与判定

- 将文字实际行框、祖先可见性、裁切、安全区、组件身份和叠放关系集中到一份浏览器观测器。
- 将文字碰撞、组件碰撞、边界和采样时间集中到共享规则，fit、layout-measured、严格生产检查共同使用。
- 移除按大面积重叠推测“有意设计”的文字豁免；用 DOM 包含关系与明确叠放声明区分正常设计。
- 补充入场、退出和固定间隔采样；不拼接不同帧的矩形后再判断碰撞。
- 保留现有对比度、字幕、媒体完整性与版本校验，不用新模块替代或弱化它们。

### B. 修改契约与候选提交

- 基于现有受控编辑、CAS 指纹和备份扩展，不另起一套编辑器或绕过制作锁。
- 一次修改先描述目标与依赖影响，局部场景改动不得无声扩展到共享引擎。
- 在正式提交前验证候选语法、场景边界及修改范围；支持对同一场必要的联动调整。
- 对无法证明安全的全局改动要求明确范围，不让模型靠“顺便优化”获得权限。
- 保留失败候选与诊断；不通过回退正式文件模拟事务，也不自动撤销用户并发修改。

### C. 生成与回归闭环

- 在现有分场任务中加入布局约束说明，鼓励使用安全区与容器布局，而非独立猜测每个坐标。
- 在适配真实引擎能力的前提下逐步前移预检；不把语法通过称为浏览器布局通过。
- 覆盖初次生成、局部修改、全局影响、恢复、横竖屏、检查器失败与旧版本回执。
- 做真实浏览器隔离集成测试；现有项目仅只读检查，不自动改稿、TTS、调用付费模型或重渲。

## 验收

- 完全重叠、嵌套重叠的两段文字均可检出；正常卡片文字不误报。
- 文字含 span、组件相互遮挡、祖先隐藏、纵向裁切与字幕区冲突有真实浏览器测试。
- 不同时间出现的对象不会被误判为同屏碰撞；采样未执行不得通过。
- 局部编辑能联动调整本场布局，但不能改变其他场次和全局引擎。
- CAS 冲突、拒绝、异常与恢复不丢正式稿、不伪造成功。
- 运行现有全量测试与新增跨模块回归；明确剩余的抽样、语义和审美边界。

## 后续路线（不以本轮完成冒充）

稳定组件 ID 与结构化场景计划、隔离整片候选构建、自动视觉差分及人工确认入口，应沿上述契约演进。旧项目自由 JS 不能无损自动转成结构化组件；不强制迁移、不用模板重写现有视频。完整端到端质量仍需经授权的真实模型制作验收。

## 首轮落地范围

| 链路 | 本轮实现 | 不能据此宣称 |
|---|---|---|
| 初稿与后续编辑 | 分场草稿、短补丁、追加、单场替换共用完整场景结构检查；支持块体、对象表达式和 function builder，不执行作者 JS | JS 语法正确不等于运行、语义或构图正确 |
| 正式稿保护 | 已有稿禁止无指纹整份覆盖；纯候选验证后再 CAS/备份/原子单文件提交；可信场号约束实际修改跨度 | 未实现跨文件原子提交或通用自然语言组件授权 |
| 生成布局 | 标准生成出口统一注入内容驱动 flow/grid；按字体和换行自动联动，不裁字、不静默删内容 | 不自动重写旧项目，也不保证任意内容都适合容器布局 |
| 质量判断 | 共用观测器、几何判定、采样计划及对比度像素计算；包括完整文字重合、span、组件、祖先裁切和安全区；只在同一帧判碰撞；本场独立提供观测证据，邻场进出不按场内溢出处理；带背景的透明分组按实际背板逐层合成 | 不覆盖 Canvas/SVG 内部文字、所有遮挡关系或每一帧动画；主体 DOM 存在不证明其内容正确 |
| 出片与版本 | 普通/自动检查器失败均阻断；普通显式内容豁免不豁免检查失败；质检前后输入绑定；主片与备用输出均在渲染后再次核对输入；新策略使旧严格回执失效 | 普通内容豁免不等于严格自动质量通过 |
| 修改影响与对比 | 编辑回执记录源码影响；snap 保存真实预览；compare 只读原稿、不重造旧引擎，并拒绝变化素材 | 中点截图对比不等于自动视觉差分或语义回归 |

**仍待实现的核心闭环：**持久化的整次编辑 scope（含组件与保留内容）、多文件候选封存与崩溃恢复、隔离构建候选并在作者稿提升前完成浏览器回归、逐组件视觉差分及前端确认。当前拒绝的结构候选不会写正式稿；尚未把所有失败候选持久化为可继续编辑的视觉草稿。不得把本轮基础设施说成这些能力已经全部完成。

### 下一阶段的统一事务契约

沿用现有项目锁、检查点、作者稿 CAS 和媒体凭证；不为候选另外维护一套完成判定。

```text
scope = {
  id, revision, instructionIds,
  baselineHashes,
  allowedFiles, allowedSceneIds, allowedComponentIds,
  preserve,                 // 旁白、数据、非目标组件、既有场次等
  impact,                   // 局部场 + 邻场，或共享输入导致全场
  requiredChecks
}

open → sealed → checked → promoting → committed
          ↓         ↓          ↓
       rejected   stale     recovery-required
```

- 模式给出权限上限，用户要求进一步收窄；模型提出范围不等于自行获得扩大范围的授权。
- 新插话增加 scope revision，旧 revision 的候选不能提升。纯“继续”不重置范围或修复预算。
- 候选构建必须显式分开输入根与输出根；不能临时替换正式文件再“还原”，也不能依靠执行任意项目脚本来证明只读。
- `checked` 必须绑定候选内容、scope revision、检查策略与素材指纹；只检查旧片或作者文件发生过变化都不算完成。
- 多文件提升使用日志和可恢复中间态，不能把数次 rename 称为整体原子事务。恢复逐项比对旧/新哈希；未知外部修改阻断，不盲目回滚。
- 正式源码提升后，继续由已有依赖判定选择 build/measure/render/voice；不能为局部画面变更重做 TTS，也不能让共享模板变更复用旧分段。
- UI 展示目标、实际影响、保留检查、候选画面差异与尚未通过项。用户确认是单独事实，不由机器勾选代替。

此阶段发布前必须一起通过：局部修改保留其余场、共享变更全场回归、追加尾场不重写旧场、失败候选不动正式稿、封存后插话不串版、多文件提升中断后安全恢复。不能只上线某个写工具而遗漏完成/恢复出口。

### 独立复核后的跨模块修正

- 转场：统一筛选当前场景；push/wipe/fade 的邻场进出不按本场正文越界处理，但全局标题仍会与本场正文检查碰撞。
- 采样证据：逐场记录正文/主体，不能让 S1 或全局页码替空的 S2 提供通过证据；这仍不是对 Canvas 像素或内容正确性的证明。
- 半透明分组：隐藏文字后分别采集透明组之外的实际背板，按由内到外的分组合成计算字色，不将背景已经合成过的透明度再乘一次；检查后精确恢复原样式。
- 草稿组装：源码与清单各自提交前重新核对 source/script/engine/manifest，拒绝并发改稿；源码已提升而清单随后冲突时保留现场，不盲回滚，不宣称跨文件原子性。
- 场景结构：返回对象逐属性检查 callable render，拒绝重复键及不明覆盖；括号函数、控制语句后的正则保持兼容。动态引用、computed keys/spread 等无法证明的返回 API 仍保守拒绝，不执行作者代码猜答案。
- 备用输出：`render --name ...` 与主片一样做渲染结束后的输入核对，不把旧内容登记成新源码的增量基线。

新增真实浏览器转场/透明度/空场测试、备用输出及并发改稿测试，并为读取草稿、准备源码临时文件、准备清单临时文件三个窗口分别注入 source/script/engine 冲突。未通过放宽质量阈值或删除原断言换取兼容。
