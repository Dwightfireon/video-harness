# 映序 WebGL2 / SDF 接入方案

状态：首版已实现，下文保留设计边界。新项目默认允许按场混合；显式 `vh new <目录> --visual dom` 可关闭。试点为新作《OpenMotion：从参考视频到可编辑工程》；没有重做或迁移旧项目。OpenMotion 是介绍对象，不是映序的运行时依赖。实际接口见 [SDF 场景接口](sdf-scene-api.md)。

## 1. 先做一条能走通两端的路径

| 层 | 首版改动 | 保持不变 |
| --- | --- | --- |
| 作者输入 | 新项目默认 `hybrid-sdf`，由分镜决定用不用；在 `scenes.src.js` 声明该场的 SDF、镜头与动作。共享 WebGL2 runtime 按版本随项目固定，由构建内联，便于重现 | `脚本.md` 是旁白权威来源；`engine.tpl.html`、`scenes.src.js` 仍是作者入口，`scene.html` 仍是生成物 |
| 出画面 | WebGL2 片元着色器做距离场步进，负责物体、空间、光照和镜头；DOM 负责字幕、术语、数字和真实界面素材。第一版用一个共享 canvas，按当前场启用，进入 DOM 场不继续画 | 唯一时间入口仍是 `window.renderAt(t)`；复用 `lib/frame-runtime.mjs` 的可等待帧边界。由实测时间轴和 `VH_FILM.sceneCue`（或其生成后的确定性时间参数）驱动画面，不让 shader 自跑时钟 |
| 工作台 | 复用 `/_api/production`，按需加可选的画面模式与阶段错误摘要，由后端从项目声明和当前运行结果派生。`www/player.html` 继续播生成页、同步旁白与拖动，显示 WebGL 不可用等错误；本机不能预览 WebGL 时，已有有效 MP4 仍可回看 | 前端不加载 shader、解析场景源码、复制完成标记或新增周期性强核验。首版不扩新建表单，CLI/脚手架选用后网页即可识别 |
| 发布台 | 沿用 `desk/harness-adapter.mjs` 的 `readMedia` / `deliverableState()`，继续识别带配音 MP4、封面及发布文案。相同就绪规则对待 DOM 和混合项目 | 不加 WebGL 判断、不改投稿表单或排程、不启用任何自动投稿。识别待发不等于授权发布 |

建议在 `PROJECT.json` 加**可选**画面模式，缺省和未声明的旧工程保持原行为。声明只说明选择了什么，不能证明已经渲染成功。运行失败复用现有生产状态，不另设一套网页、队列或完成凭证。首版也不引入 OpenMotion Studio、MCP、GSAP 或新的渲染器分支。

## 2. 让改 shader 和改普通场景一样可追溯

- 可编辑 shader 首版随对应场的 `scenes.src.js` 内联，保证源文件修改立即进入 `lib/artifact-status.mjs` 的现有指纹范围；共享 runtime 固定在项目模板内，由现有构建产出自包含的 `scene.html`。如画面模式或其他配置能改变输出，只让相关配置进入构建与成片指纹，不把整个 `PROJECT.json` 当作失效依据。
- 只改某场几何、材质或镜头时，继续沿用场级差异与分段缓存；只有现有检查证明分段可复用才做局部渲染。共享 runtime 改动按共享输入保守失效。脚本和配音参数不变，不重测 TTS；首次试点仍用真实配音测量。
- WebGL2 不可用、shader 编译失败或上下文丢失要报告对应场和阶段，正式导出不能悄悄交付黑帧或切成旧视觉。保持现有本机 Chrome 沙箱、素材隔离、磁盘保护与媒体核验；不把上游仓库脚本直接装进映序或预览页。
- 性能用 `vh performance` 记录实际截图、编码、混流耗时；另做同尺寸短样本对照，记录首帧和稳定帧耗时。之前的 39ms/帧是原型小样，不作为正式成片速度承诺。先限制首版场景复杂度，不靠关检查、降正式画质换速度。

## 3. 用新片验收，不拿旧片返工

1. **先接最小运行层。** 当前 scaffold opt-in 能构建同一时间轴下的 SDF 场和普通场；用隔离 fixture 验证同一时间点重复/倒序跳转结果稳定、切场不串画、字幕不被 canvas 遮挡，以及无 WebGL / shader 编译失败的明确诊断。
2. **接两端并做版本回归。** 工作台可从项目列表进入这支片，预览可拖动；发布台可识别当前成片。修改单场 shader 后旧 MP4 必须提示过期、不能进入待发就绪，重渲并混流后恢复就绪；纯 DOM 工程不因新增模式无端失效。网页发布回归用隔离样例或模拟投稿，不实际发送。
3. **用 OpenMotion 新片完成一条正式链路。** 旁白定稿后 `vh measure`，用 `vh plan --srt` 核对失效，`vh go --srt --keep-frames` 出片，依旧生成发布文案、封面和交付包。用正文而非炫技片头验收：做一个相同镜头从“参考画面”拆成“顺序、节奏、转场”，换上自己的内容，再转到可编辑工程。这个 WebGL 段标成“流程示意”；实际 Studio 界面或官方素材须独立标源，不用示意画面冒充产品录屏。交付时区分技术回归和实际播放、试听。

## 4. 新片的客观口径

观众问题：**OpenMotion 所谓“参考视频复刻”，到底是把原片复制一份，还是重建成一个能继续改的工程？**

- 沿官方仓库说明讲参考、`Motion.md`、Agent 重建、Studio 修改、MP4 导出。介绍时要说明 `Motion.md` 记录镜头和动效规则，不等于视频本身；模板中也有只提供参考、并无可编辑源码的条目。
- 能验证的就展示具体操作；没有亲自运行的能力按“官方文档说明”表述。若做小实测，只记录所用版本、输入、实际产物和未完成项。开源软件与外部模型用量费用分开，不用星数、模板数量或宣传口号代替判断。
- 以制作时固定的仓库版本和对应文档为依据，不翻旧闻凑内容。原始资料放新项目的 `research/`；方案、口播与发布文案用中文，公开文案不出现海外社交平台名称或账号。
- 本片的 WebGL2/SDF 是映序自己的制作方式；不能由此推断 OpenMotion 默认使用 SDF，或那条未取得源码的角色短片一定靠 SDF 实现。

首批来源及实际采用的版本见 [试点来源](../projects/OpenMotion客观介绍/research/原文.md)。

放行范围：一条新片能在现有网页预览、识别和交付即完成首版。第二支片出现明确复用需求后，再抽象通用 SDF 配方和评估是否增加网页新建选项；不先做模板市场、全局默认切换或批量迁移。

## 5. 首版实测

- 试点 50.29 秒、1920×1080、30 fps。首轮单路截图 1509 帧耗时 46.55 秒，分段编码 3.90 秒，混流 1.62 秒（不是整次制作时长，也不代表其他复杂场景）。
- `test/scene-sdf.test.mjs` 通过真实工作台和隔离 Chrome 验证跨场帧互不污染、倒序拖动同帧一致、普通文字层可读、着色器报错可见并可从拖动中恢复、WebGL2 缺失时明确报错。
- 在实际试点的隔离副本上，通过发布台只读列表接口验证 `ready → stale → ready`。只改第二场的一个着色器颜色，`vh go` 仅重画该场和边界（548 帧），旁白 8 句全部命中缓存；混流后发布台恢复就绪，无真实投稿。
- 当次交付查看了三张正文静帧和三种封面缩略图。未做全片人工播放与试听，也未投稿。
