# 内容审稿与返工优化 · 2026-10-29

## 范围

修复整体 review 复现的问题，不改写或恢复已发布的克苏鲁项目。重点是把讲述判断提前、让待核项可见、统一发布限制、隔离过期配音缓存，并补模型耗时记录。没有降低画质、探针覆盖或发布审阅要求。

## 新的制作关口

新建项目以及 `finish_draft` 新提交的脚本启用内容审稿。方案/脚本完整、依据齐备后，自动 Agent 先进入 `review_content`；不能直接跳去写分镜。手工路径：

```bash
node vh.mjs content-review --dir <项目>
node vh.mjs content-review --record <审稿JSON> --dir <项目>
```

第一条只读，返回当前 `input.signature`、纯编号旁白、形式硬失败及待核项。第二条在制作写锁内记录判断，不能读取文件存在就当成审稿通过。`--strict` 在未登记或未通过时返回非零；没有审稿记录的旧工程明确为 `legacy-unreviewed`，不补造 pass，也不触发重做。

审稿 JSON 格式（所有引文须替换成该项目的真实旁白）：

```json
{
  "signature": "第一条返回的当前64位签名",
  "verdict": "pass",
  "question": "这支视频回答什么？",
  "answer": "结论及必要限定",
  "scope": "列出需要核对的关键推断；是否存在跨域类比，若无，说明为何不适用",
  "scenes": [
    {"scene": 1, "quote": "本场旁白原句片段", "takeaway": "本场获得什么信息", "bridge": "开场的对象与问题，或后场的人物/时空/信息承接"}
  ],
   "links": [
    {"premise": "依据的旁白原句片段", "middle": "实际说出的中间变化原句片段", "conclusion": "结论原句片段"}
  ],
  "analogies": [
    {"claim": "类比判断原句片段", "mapping": "哪一步对应的旁白原句片段", "limit": "差异或不适用边界的旁白原句片段"}
  ],
  "findings": [{"finding": "返回的每一条机器提示原文", "reason": "已补写位置、误报理由或具体断点"}],
  "issues": []
}
```

从内容审稿契约 v2 起，`vh clarity` 会列出可能改变比较、推荐或行动的**关键结论**。`verdict: "pass"` 时，`links` 必须逐个覆盖它们：`conclusion` 要是该结论的连续旁白片段，`premise` 与 `middle` 同样只能引用编号旁白。这样不能只写“建议选 A”，却把“ A 的什么特性怎样改变结果”留给观众或审稿人补全。机器只提示候选与附近桥接缺口，不用关键词替代语义判断。

每场一条核对；关键推断和类比按内容选，不设数量或句数配额，不适用可传空数组并在 `scope` 解释。`findings` 按返回顺序逐条处理，不允许静默丢掉提示。形式硬失败和未解决问题不能标 pass。返修用 `verdict:"revise"` 并列出 `issues`，中间步骤可写缺失点，不能假装已经在旁白中出现。

程序能验证覆盖、引文存在、版本绑定及记录完整性，**不能验证审稿人有没有漏选关键判断，不能证明依据推出结论或观众已经理解**。仍需质疑主命题本身是否成立，不能把“记录有效”表述成内容已被机器认证。没有增加固定问句、反转、时长、术语或句数配额。

记录只绑定方案、脚本、claims的字节；修改任一项即过期，纯视觉调整不触发重审。待审、返修、过期时，正式测量、渲染、混流、go与打包阻断；估算 build/静帧/预览仍可用于草稿。人工 `review.json` 不因该记录自动通过。

## 其他修复

- `clarity` 解析双列表格与加粗受众标记；`S0` 等不存在的依赖不再通过。普通中文术语仍不能无来源穷尽提取，不宣称已自动发现所有逻辑跨步。
- build 输出、score 的警告数包含待核；评分改称解释形式并说明不是内容审稿。
- `lib/publish-limits.mjs` 为文案与 B 站投稿台提供同一边界；12标签、超长标题/简介/单标签提前失败。没有新增多平台配置，不改写手动文案。
- 已知标准 TTS 模板完整哈希核验、备份后升级。缓存独立命名空间纳入脚本、发音工具、包与本地模型字节；测量保存合成身份。旧缓存/无身份时间轴不得补签复用，未知自定义模板不自动覆盖。身份探针不加载模型、不联网；全命中仍惰性加载。测量、计划、出片及交付路径须核对当前身份。
- 内置模型池逐次记录请求与重试等待，包含失败/取消，不保存请求、响应或凭证。诊断写入失败不导致成功请求重发；`ask` 含模型子耗时，不能重复累加。

## 效果边界

本轮未改渲染器的全片共享指纹或帧/分段复用规则。字幕、时长变化仍可能导致整片失效，不能为了省时间放宽这条安全约束。下一阶段若重构分场依赖，需验证字幕、跨场访问、转场邻域与时间轴变化的真实媒体等价性。

这些修复减少内容问题暴露过晚和无效缓存复用的机会，不代表已证明制作提速，更不代表机器自动保证讲清楚。真实端到端收益、真实模型听感及观众理解仍须后续制作验证。
