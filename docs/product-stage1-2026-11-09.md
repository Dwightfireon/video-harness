# 第一批产品打磨：执行与安全底线

对应 `product-gap-review-2026-11-09.md` 的 G01–G07。目标是让“选择的配置、用户的要求、实际执行、交付状态”相互对应；不重写前端，不扩平台，不增加默认模型审稿。

## 已实施

### 1. 实际模型配置

- 新增 `lib/execution-config.mjs`，默认选择来自模型设置；显式项目模型和环境变量仍可覆盖，并记录来源。
- 通过 OpenCode V2 的运行期配置和环境引用桥接产品保存的端点、密钥。使用 `--standalone`，避免共享服务忽略本轮环境；不修改全局配置或凭证库。
- 任务记录只保存脱敏执行快照。密钥不进入启动参数、任务记录或日志；子进程错误输出先按完整行脱敏，再截短。
- 设置页“下次选择”和项目页“本轮配置”分开。就绪检查仅说明配置/程序可用，不表示已验证网络、鉴权、余额。
- 非法执行器、损坏配置、所选渠道缺凭证均明确失败，不静默改用其他渠道。

### 2. 要求与恢复

- CLI 恢复沿用任务保存的模式，不再默认套文章模板。
- 补充要求按身份与内容记录，并注入 OpenCode 请求；出现已接收请求的会话事件后保存接收标记。请求拒绝不会消费要求；这不是修改完成回执，也不承诺平台级精确一次投递。
- 无会话时明确按已有文件恢复；损坏会话不静默新开。纯“继续”保留本轮作者基线。
- **运行中实时插话暂不支持独立服务**：不能实时送达时，原文立即持久写入当前任务的恢复指令，并把失败原因固定显示在「修改」区，不再只闪一下错误。用户停止后点「继续原任务」，下一次执行会收到；输入框仍保留原文。不会写入无人读取的 local 队列后假报已送达，也不会因继续时重复提交同一句而注入两次。
- 提交/继续/停止失败与任务原因分开展示；轮询只能更新任务原因，不能冲掉提交失败。失败提示可点击关闭，成功提交后才自动清除。

### 3. 目标完成判定

- OpenCode 正常退出与目标完成分开。空回答、没有对应作者改动、越出模式作者范围、缺少目标产物，均不得认定完成；保留文件和恢复入口，不自动回退作者稿。
- article/topic 复用既有成片/发布目标有效性检查；edit-copy 检查发布文案，edit-script 检查编号脚本，edit-visual 检查当前构建。局部任务不要求重新生成完整配音视频。
- local 的局部交付观察与恢复结算也使用目标类别；既有工具权限、写入保护和检查点流程保留。
- 首页、项目页、队列读取最新观察；队列不能仅凭 `completed` 字样判定 done。只读回答不算视频交付。
- 作者哈希只能证明版本/范围变化，不能证明语义正确、审美合格或用户已经验收。OpenCode 范围检查是完成时核对，不是操作系统写入沙箱。

### 4. 浏览器与静态文件

- 预览 iframe 使用不含 `allow-same-origin` 的脚本沙箱，直接打开项目 HTML/SVG 也受 CSP sandbox 限制。
- 播放、暂停、拖动、尺寸数据通过有限消息桥接，不再直接执行或读取场景窗口。
- 所有请求检查准确 Host；控制请求拒绝 opaque/cross-site/same-site 的非同源来源，写请求须精确匹配协议、主机、端口。无浏览器来源信息的本机 CLI 仍可访问；这不等于客户端认证。
- 静态文件只开放必要项目文件、素材和交付物。隐藏文件、私有状态、仓库源码、node_modules、路径组件符号链接均拒绝；Range/HEAD 从已验证 fd 读取。
- macOS 路径保护已验证；Linux fd-walk 分支未实机验证，其他平台保守拒绝静态打开。

### 5. 发布共同保护

- 网页单条、批量、Electron 的共同 service 入口强制执行预检、账号级跨进程互斥与记账。
- 以账号 mid 优先确定身份，跨项目共用冷却；全量视频 SHA-256，保留旧回执的只读保护。
- 提交前先持久化 `submitting`，提交后更新结果。日志损坏、持久化失败、提交状态未知均阻断重发；普通 `confirmed:true` 不越过 duplicate/unknown。
- 未知结果不再因 30 分钟过去自动解除。现有 BV verify 只查询，不自动解锁或重发。
- 账号状态位于 `~/.config/video-harness/publish-state/<账号摘要>/`；不是公开交付包内容。

## 验证范围

使用临时 HOME、假 OpenCode/发布服务、真实 CLI/浏览器和隔离子进程。未真实登录、上传或投稿，未调用付费模型，未重做现有视频，未重启 8144。

最终全仓回归：`node scripts/test.mjs` → 1613 个测试点，1688 通过、0 失败、1 跳过（真实媒体稀疏帧夹具按环境跳过）。全仓首次运行暴露出以下兼容问题，已按行为契约修正并复跑：

- 队列不得仅凭 `completed` 判定完成（已用交付观察）。
- 新建项目但未填材料时不再写一条“缺凭证”的假失败任务。
- 局部编辑的交付观察不再要求无关视频；`edit-visual` 只核对当前预览。
- 设置页/来源链读取必须能注入隔离 HOME，避免测试读到本机凭证。
- 服务根目录（macOS `/var` → `/private/var`）按工作区根别名归一，项目路径内的符号链接仍拒绝。
- 发布页 duplicate/unknown 只阻断，不提供“仍要提交”即时绕过。
