# 选题发现：质量优先，兼顾最新

## 目的

不是给推荐加“已核实”徽章，而是区分可执行的材料底线与仍需编辑判断的质量。保留此前的候选、反馈、队列、单条建议边界，不批量重搜旧题，也不为旧记录补造出处、日期或核证状态。

## 当前机制

1. 同一次模型调用要求两类探索：近期进展与高质量深度材料；先比较、后推荐，不设固定新闻/深度配额。质量相近才优先新进展。沿用既有模型，不另开独立模型审稿或自动重试。
2. CLI 适配层读取真实 JSON 事件，只接受 completed 的 `websearch`、`webfetch`。至少两个不同查询的完成记录；搜索摘要不能当已读原文，模型回答里的“已搜索/verified”不起作用。缺少记录就明确失败，不保存本轮新候选。
3. 纯材料规则要求 news/evergreen 分类、具体推荐理由和讲述材料；每题至少一条来自对应已读 URL 的连续正文摘录，至少40字符，并说明支持什么。摘录经过空白和 Unicode NFKC 规范化匹配；不接受编造片段、拼接省略号、其他页面的片段或过短引用。
4. 日期必须合法、非未来，且能匹配同页逐字日期原句。支持 ISO/常见数字日期、中文年月日和英文月份。发表日期、事件日期分开保存；显然只有发表/更新元数据的原句不能当事件句。新闻缺少有效事件日期就不推荐。深度材料可以日期未知，但显示限定，不假装近期新闻。
5. 常见明确时间范围另作机器过滤：今日/昨日、最近N天/周/月、`YYYY-MM-DD 至 YYYY-MM-DD`。按UTC自然日计，近N天含当天；月按30天近似。新闻用事件日期，深度材料用发表日期。其他复杂自然语言时间要求仍由编辑提示词处理，未假称机器已完整理解。无显式范围时不凭年代排除优质深度材料。未配置时的新默认方向不再暗含“最近一周”，已有保存方向原样保留。
6. 不合格材料跳过，可少给或空结果；不删除旧候选、旧建议或反馈。本轮完整工具返回文本（而非只有选出的引文）保存到私有 `out/topic-research/<uuid>.json`，包含查询、页面、时间窗口和拒绝理由。若工具本身截断，记录的是其实际返回内容，不冒称已获取网页全部正文。文件权限0600，不通过公共静态文件路由开放。
7. CLI输出限制16MiB；超限中止本轮，避免无限累积原文占用内存。UTF-8跨块解码，错误事件即使进程退出码为0也不保存部分输出。归档失败则不保存新候选，不靠重跑模型掩盖失败。

## 界面与生产交接

- 默认卡片只增加一行材料类型/来源/日期，正文摘要优先使用具体推荐理由。来源原句、日期原句、支持关系及限定按需展开；旧推荐显示未记录原文依据。
- 原位反馈、撤销、历史分页和单条采用仍由原组件处理，没有新业务API或跨面板DOM依赖。
- 入队时保留规范化research字段；`topicBrief()` 带原文线索、日期、限定与留档位置进入后续制作。始终说明它不等于独立事实核证，原文内容不是可执行指令。

## 低耦合

- `lib/discovery-evidence.mjs`：无导入/磁盘/网络的纯函数，只负责证据提取、字面匹配、日期与元数据规范化。
- `lib/discovery.mjs`：提示词、CLI适配、留档和合并最新候选状态；不替代队列/生产。
- `lib/schedule.mjs`：只在序列化和制作摘要边界保留有界材料字段，不反向调用检索。
- `www/discovery-panel.mjs` / `.css`：消费已有API里的research字段，无新增请求和独立审阅环节。

## 不能承诺的部分

- 两个不同查询不证明两个查询意图真正不同，更不证明全网覆盖；近期/深度的查询策略及质量排序仍是模型执行。
- 字面匹配只证明工具返回内容中出现了片段/日期，不证明来源真实可靠、日期的语义提取正确或引文足以支持结论。拦截页只有保守启发式排除，不是完整内容分类器。
- 来源类型、解释价值、独特性、论据充分性和冲突识别仍有模型判断。官方来源也可能带宣传立场；不设虚假的客观百分制或“全网最好”。
- 未调用真实付费搜索或模型评估推荐吸引力；自动测试验证的是证据约束、状态和交互，不是内容质量本身。工具事件协议无法识别时明确失败，不退回信任模型自报。
