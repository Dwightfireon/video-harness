# 选题发现优化方案

目标：把「搜三个标题直接入队」改为「找有讲述价值且彼此不同的候选，用户选择后入队，并保留推荐记忆」。不改视频渲染、发布权限，不自动调用额外审稿模型。

## 实施范围

1. 编辑提示词：明确当前日期、观众收益和展开方式，先探索多个检索角度，不强制热点/反转/凑数。
2. 推荐记忆：在 schedule.json 的 discoveryTopics 中保留题目、核心问题、来源、时间、反馈和入队关联；旧队列/运行记录兼容读取。移除队列不删除推荐记忆。
3. 去重与探索：提示词按事件、核心问题及主要内容排重；本地再用规范化标题、核心问题和保守相似度兜底。focused/explore 控制探索范围；新进展须标明旧题及新增依据。不是完整语义判定或事实核证。
4. 偏好反馈：想做、看过、不感兴趣（原因/备注可选）；反馈按具体题目保存，不把跳过或移除当作讨厌整个领域。个人偏好可编辑清空，反馈可逐条撤销或清空，推荐历史仍保留。
5. 候选界面：显示看点、讲法、区别、来源；可入队、沿方向再找、换角度。手动搜索始终先候选。自动发现与自动入队独立，自动入队默认关。来源和选题依据随入队进入制作材料。

## 验收

- 相同标题/核心问题及历史重复被拦截，同一来源下实质不同的问题可保留。
- 删除队列后记忆仍在；空结果/错误 JSON/无来源/危险 URL 不入队。
- 手动搜索不自动开工；自动入队只有显式开启才执行；设置不影响发布/制作开关。
- 反馈可修改、撤销；撤销不删历史、不撤销已入队或制作项目。
- 模型调用期间用户修改的队列、偏好、开关不能被旧快照覆盖。
- HTTP 与浏览器模拟测试覆盖核心动作、刷新恢复、移动布局和输入不被轮询打断；不使用真实付费模型或发布接口。

## 兼容与边界

历史只保存了计数的旧推荐无法凭空恢复。旧队列与 runs 中尚存的标题可以纳入记忆，缺失来源不伪造。新元数据不作为事实已核实的声明。所有模型输出和 URL 均作为不可信数据处理。
