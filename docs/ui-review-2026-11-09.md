# 映序：界面改版与代码 Review

本轮范围：网页创作入口、项目编辑器、网页发布台、模型设置，以及可选 Electron 发布台的配色与名称。检查了相关 HTTP 接线、发布表单状态和既有 UI 测试；不是对全仓库、全部发布协议或安全边界的穷尽审计。

## 代码发现（按风险排序）

### P1 · 批量投稿未经过统一的尝试登记，未知结果可能再次提交【本轮未改】

- `lib/publish-api.mjs:147–164`：单条投稿包装器登记成功、拒绝或未知结果。
- `lib/publish-api.mjs:194–205`：批量路径直接调用 `service.submit()`，没有经过上述登记；前置检查仅对 `cooldown` 停止，对 `unknown`、`duplicate` 继续。
- 后果：响应丢失后重新运行批量，可能重复投稿；已有未知记录也不能阻止这条路径。
- 建议：让批量与单条共用尝试登记，未知结果停止并要求先核对稿件，重复项单独确认。这涉及实际投稿的行为与确认策略，本轮视觉改版不顺带改动；未做真实投稿复现。

### P1 · 无默认项目时，发布检查接口被错误拦截【已修复】

- `lib/server.mjs` 中 `globalAPI` 漏列 `/_api/publish/plan`、`/_api/publish/batch-state`，而网页发布请求不携带项目参数 `p`。
- 后果：从多项目工作台启动服务时，这两个已存在的发布路由可能在进入用例前就返回 404。
- 修复：补全全局接口分类；同源检查与提交确认保持原样。增加无默认项目的真实 HTTP 路由测试。

### P2 · 发布表单继承旧错误或旧通过状态【已修复】

- `www/publish-panel.mjs` 原先在编辑后保留 `P.plan`，`currentProblems()` 继续叠加旧校验错误。
- 修复：编辑立即作废旧计划，暂停后合并发起本地校验；没有当前校验结果时不沿用旧通过状态。复用后端校验，不复制一套文案长度规则，不调用模型、不上传或投稿。
- 校验失败可见；修改后的空标题、超限简介、修复后恢复均有浏览器回归测试。

### P2 · 项目或表单变化后，异步返回会覆盖当前状态【已修复】

- `www/publish-panel.mjs` 的来源读取、简介追加、试运行没有检查返回时的项目身份。
- 修复：绑定项目选择版本、表单版本与请求序号。A 项目的迟到响应不能覆盖 B；同一项目的旧校验不能覆盖新表单；简介在等待期间被编辑，也不覆盖新输入。
- 上述跨项目和同项目乱序情况均有浏览器回归测试。

### P2 · 附件端点无限收集上传内容、同步写盘【本轮未改】

- `lib/server.mjs:432–442`：没有大小上限，整包保存在 chunks，并重复 `Buffer.concat()`；写盘同步阻塞服务。
- `www/panel.js:754–766`：先完整读为 ArrayBuffer，失败被空 catch 忽略。
- 后果：大文件可能造成较大内存峰值或阻塞状态、停止等请求。当前改片页附件入口隐藏，但服务端端点仍存在。
- 建议：单独实现有界流式上传、断连清理、体积限制与明确错误反馈。本轮未进行大文件压力测试或更改资源策略。

### P2 · 运行标识按 HTML 子串匹配项目【已修复】

- `www/index.html` 原先用第一条运行项目的路径匹配卡片 HTML，前缀相似的项目可能被误标，同时运行的其他项目反而漏标。
- 修复：从 cards Map 的项目状态直接判断；增加相似路径与双项目运行回归测试。

### P2 · 缩略图 URL 会删除项目名中的空格【已修复】

- `www/index.html` 原先构造静帧路径后全局删除空白，合法的含空格项目找不到画面。
- 修复：对路径逐段 URL 编码，并用于静帧、成片和脚本链接。补充缩略图替代文本与路径回归测试。

## 界面改动

- 对外名称改为 **映序**，保留 `vh` CLI、项目格式、缓存、凭证及 `window.vh` 等内部接口身份。
- 首页文案「把文字，讲成影像。」；材料选择改为「从文章开始 / 从想法开始」。编辑器「指挥」改为「修改」。
- 参考 [OpenAI](https://openai.com/) 的中性层级、内容留白与安静导航，以及 [Anthropic](https://www.anthropic.com/) 的暖纸底和衬线标题，不复制其品牌标志。
- 统一暖纸白 `#faf9f6`、炭黑 `#252520`、灰绿 `#6e7d65`；错误、警告和成功使用可读的深色状态色，主操作使用炭黑，不再通篇绿色描边。
- `www/theme.css` 集中颜色、字体和交互基础；`www/workbench-shell.mjs` 只负责共享导航，不读凭证、不发起制作。
- 首页先创作，再查看作品；选题与定时设置移到作品后，默认收起。保留定时发布的真实作用说明，不让一般创作提示替代定时授权信息。
- 增加本地项目搜索，不重建卡片；保留长文分页、草稿选择保存和失败保留输入。
- 编辑器优先展示进度与画面，画幅设置及自动制作详情后置；发布页窄屏改为单滚动区，底部操作仍可见。
- 控件补充可访问名称、材料选择键盘焦点、当前导航标记；遵循减少动画偏好。
- 可选 Electron 发布台同步名称与配色，不改变 IPC、权限、登录和投稿逻辑。

## 验证与边界

- 使用仓库 `scripts/test.mjs` 和已配置的本机 Chrome，10 个定向测试文件共 **72 项全部通过**，覆盖现有 UI、画幅、长文输入、草稿、恢复、制作面板、选题入口、发布路由、Electron 页面及新增交互测试。
- 新增 `test/workbench-design.test.mjs`，验证桌面和 375/320px 窄屏、材料键盘选择、搜索节点稳定性、运行身份、表单更新及乱序响应保护。
- `diagnostics/ui-refresh/` 是测试夹具截图，含模拟项目与模拟账号，仅用于布局检查，不代表用户作品或真实投稿。实际本地网页另经浏览器打开检查。
- 测试使用临时工程与假客户端；没有调用付费模型、重做用户视频、登录或提交真实稿件。没有执行整库测试或完整出片验收。
- UI 静态文件刷新即可更新；发布路由修复需要重启当前工作台服务。若有制作中的任务，先等任务结束，不要为换界面强停进程。
