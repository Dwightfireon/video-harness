# 候选选题与历史：交互复查

## 发现的问题

1. **单条操作走整批入口。** 卡片「换角度」携带顶部 query/mode/count，后台同样按整批生成；新结果混入全局候选，既没有原题关联，也没有采用确认。单条卡片上的按钮因此造成整批变化的错觉。
2. **操作结束后缺少原位反馈。** 「已经看过」「不感兴趣」先打开可选说明，却还需再点一次才能真正记录。记录后卡片进入默认折叠的历史，用户不容易确认做了什么，也不容易撤销。
3. **入队状态失真。** 历史用永久 queueId 当成当前仍在队列；已移出的题仍显示「已加入」，也无法明确重新加入。
4. **历史既冗长又不完整。** 复制候选的全部说明和操作，却只截取混合列表前 100 条；没有独立总数、分页或筛选。反馈清空还会把历史重新放回候选。
5. **全局忙碌和迟到回执。** 一张卡保存时全体操作一起禁用；多个响应与轮询没有清晰的状态版本约束。旧测试侧重 API 有请求，没有验证“只改变目标”“保留原位”“实际折叠”和独立并发。

## 改进后的操作边界

- **查找一批新候选**：使用顶部方向、模式、数量；新增，不清空待选内容。
- **换角度**：只基于被点击的原题，后台强制最多一个 suggestion。原题和其他候选不变，建议挂在原题下。选择「采用这个角度」后才替换原题；原题收进历史。
- **找一个子题**：同样只找一个建议；选择「另存为候选」，不替换原题。
- **不用这个建议**：中性收起，不记负反馈。失败或没找到时保留原题和上一条未处理建议。
- **已经看过 / 不感兴趣**：单击即记录，原位置显示确认条，可撤销或选填原因。无需先填写理由。正在保存的卡片独立忙碌，其他卡仍可操作。
- **先收起 / 放回候选**：只是整理位置，不推断兴趣。清空反馈需要二次确认，不重新摆放整份历史或移除队列。
- **历史**：默认折叠、原题说明可展开；独立分页、总数、状态筛选、题目/反馈搜索；变更后保留当前页，最后一页空了才退到有效页。
- **队列关联**：实时区分当前在队列、曾入队已移出、旧制作记录；重新加入必须显式选择，不靠旧请求自动复活。

## 数据与验证边界

新增 parentId/followup 关联，suggestion 独立于全局 candidate；adopt 原题并发变化时返回 409，不覆盖已经做出的选择。保留原题、旧建议和历史证据，不重写过去的用户反馈。

revision 用于防止迟到响应覆写新状态；GET 不迁移写盘。只使用隔离临时目录、模拟模型和真实浏览器验证，不调用真实付费模型、不改真实候选或中断用户检索。

## 低耦合边界

不是把组件机械拆成小文件，而是隔开变更原因与依赖方向：

- `www/discovery-panel.mjs` 负责本面板交互；API、刷新队列、查看队列、订阅队列变化均由组装层注入。它不拼 HTTP 端点，也不查询队列 DOM。
- `www/discovery-api.mjs` 只适配 HTTP，使用注入的 request；可独立测试，不认识 DOM、轮询或选题规则。
- `www/queue-changes.mjs` 是实例级、可解除的成员变化订阅，不是全局事件总线。队列只通知自身成员/关联变更，不持有选题面板引用；重排、勾选和制作状态刷新不引起历史重读。
- `www/index.html` 只在组装处连接两者。改队列布局不需要改选题面板，换 HTTP 客户端不需要改卡片交互。
- `lib/discovery-request.mjs` 集中单条/整批范围规则；HTTP 与后台执行复用同一纯函数，不各写一套 count/query 逻辑。规则不依赖磁盘、HTTP、模型或子进程。
- `lib/schedule.mjs` 负责序列化与兼容读取；记忆事务显式请求保留未知队列字段，不再自行第二次读取并解析 `schedule.json`。默认制作输入读取行为不变。
- `lib/topic-memory.mjs` 管候选、建议、反馈与历史的状态迁移；`lib/discovery.mjs` 管模型检索与结果合并；队列、制作和发布仍保持各自入口，不从反馈或建议操作隐式启动。

另有 `test/discovery-boundaries.test.mjs` 对纯规则、HTTP 适配、订阅解绑与依赖边界单独设测试，不必启动模型或浏览器才能验证这些规则。

## 验证结果

- 12 个相关测试文件，**135 项通过，0 失败**。覆盖前端点击、真实 HTTP 与后台子进程、单题强制一条、采用冲突、建议归档、反馈撤销、历史分页、队列移除/重新加入、迟到响应、错误重连，以及原有制作/发布入口与安全回归。最终输出保存在 `out/topic-discovery-interaction-validation/final-tests.tap`。
- 低耦合隔离验证：面板只注入假 API，不提供 request、HTTP 服务或队列 DOM，也能挂载、入队回调、响应队列变更；销毁后订阅解除。请求范围、HTTP 适配与实例级订阅另有独立单元测试和边界守卫。
- 真实浏览器联调使用临时工程和假 OpenCode：模型故意返回两项，单题请求只保留一条建议；原题、其他题目与队列在采用前不变。采用后仅原题进入替换历史，队列不变。
- 额外修复：历史改过反馈后同步旧确认条，补充原因不恢复旧类型；操作前记录焦点，保存/撤销/采用后自动交接；同页移除队列自动刷新历史状态；任务完成后读取失败仅重试读取，不重发模型请求。
- 320 / 375 / 768 / 1440 像素宽无横向溢出。实际查看了桌面和手机的单条建议截图，见 `out/topic-discovery-interaction-validation/topic-single-suggestion-*.png`；截图内均为测试题目与测试来源，不是联网推荐结果。
- 本地工作台已更新，地址 `http://127.0.0.1:8144`。重启前确认无制作、发布批次或检索在运行；重启后只读浏览器检查无页面异常、无非 GET 请求，原有候选/反馈/队列不改动。重启与只读检查前后 `schedule.json` SHA-256 均为 `58880992cd8d8739305eacf3365e1aad86d41062dbf69823ad5f558bcc81d426`。
