# DNS 复盘后的管线优化 · 2026-10-28

## 范围与契约

本轮优化编排器与工作台，不改 DNS 视频项目的素材、脚本、成片或审阅结论。目标是减少重复工作、避免轮询阻塞、改进缺陷识别与阶段可观察性；不降低画质或质量门槛，不把时间戳、文件存在或旧成功报告当作可发布凭证。

最后一次只读核对时 `projects/` 已为空，`projects/dns-20261028/` 不在原位置，因此无法继续检查该项目的最新状态。本轮没有移动、删除或恢复该项目；去向和原因未确认。

| 环节 | 现行做法 | 安全边界 |
|---|---|---|
| 事实对账 | 统一带量词的数字提取与数值边界：`2049 个` 不当年份丢弃，`3` 不再匹配 `300`/`3.5`；千位逗号和小数尾零可对账。来源摘录不能代替断言或脚本文字登记 | 只比较可识别的阿拉伯数字与量词、跨登记的相同数值；不证明单位、上下文、事实或来源语义相符。中文数字、复杂范围和其他单位仍需人工核对 |
| 工作台状态 | 完整 `snapshot` 和终态交付检查移入最多两个后台线程；同项目、同类型的并发请求只合并在途工作，完成后不缓存结果；队列、超时和关闭均有界。执行过项目代码的快照线程用完即回收，避免自定义时间轴及其依赖被模块缓存 | HTTP 状态仅是观察结果，并发合并的请求可能共享已经开始的观察，并非原子文件快照。完整快照仍会运行项目自定义 `timeline.mjs`；后台线程不是安全沙箱，依赖仅主线程可用 API 的自定义代码可能不兼容。失败/超时不返回旧成功；任务状态变化时不继承旧观察 |
| 高频轮询 | `/_api/state`、`/_api/chat`、`/_api/chat/status` 和项目列表的终态交付检查移出 HTTP 主线程；画幅状态只读取必要的进程状态 | 取消/派发/清理等写操作仍由原进程状态和锁作判断，不使用 UI 的旧观察作为授权。首页目录体积的冷扫描、部分暂停状态恢复检查仍可能占用主线程；常规轮询仍会读取并哈希字节，后台化不等于减少磁盘 I/O |
| 执行计划 | 同一次 `artifactStatus` 返回的输入观察供计划使用，去掉第二次全量素材哈希 | 仅在同一个同步观察中复用，不作跨请求缓存；渲染、混流及交付前后依旧分别重新核验 |
| 渲染与日志 | 明确整片或基线已不具备增量条件时，不再逐帧 stat 无法复用的旧缓存；记录实际渲染进程的截图与编码合计耗时及成败 | 所有可能增量的路径仍检查共享身份、切点、编码、完整分段及帧。日志不会把未启动的渲染记成完成；强制终止时阶段记录可能缺失，不能把缺失当成功。截图和编码尚未分别计时 |
| 静帧审阅 | `stills` 与 `screen --frames` 共用浏览器准备；后者加载原始 `scene.html`，根据真实场次起止批量截图并输出新一轮独立目录。检查截图前后输入身份；截图或素材就绪屏障异常返回非零。工作台重截同样调用 `vh stills` 并显示执行/完成/失败 | 不再把 HTML 副本放到 `out/` 导致相对素材路径改变，也不累计取整后的时长猜中点。输入核验遵循现有素材契约，不能证明所有动态依赖已覆盖。状态由本次后台命令的真实退出码决定，不以已有文件数量冒充完成；服务重启后不会保留该临时状态，静帧凭证仍写入项目。只隐藏常见字幕/进度层，自定义字幕可能仍在；截图生成不代表已观看或审片通过 |

Agent 的 `run` 已用 `pipefail`，`run_stage` 直接按子进程退出码和完整日志登记，相关失败路径有回归测试。外部终端或其他工具自己的 `command | tail` 退出码不由本项目控制；要得到前段退出状态，调用方仍须设置 `pipefail` 或直接运行 `vh`。

## 合成基准

执行 `node scripts/benchmark-plan-inputs.mjs`。脚本在临时根创建 128 MiB 合成素材、热缓存后交替运行；“之前”模拟计划原先多做一次的完整 `currentArtifactInputs`，其余使用相同代码和设置；全部计划 JSON 的 SHA-256 相同。以下为一次实测，受机器负载与文件缓存影响：

| 指标 | 原路径 | 新路径 |
|---|---:|---:|
| 只读计划，5 次交替 | 96 / 94 / 94 / 95 / 94 ms，中位 94 ms | 47 / 47 / 47 / 48 / 47 ms，中位 47 ms |
| 同一完整快照期间零延时定时器等待，3 次交替 | 主线程直接观察 49 / 48 / 47 ms | 后台观察 1 / 2 / 1 ms |
| 同一完整快照本身完成时间 | 49 / 48 / 48 ms | 67 / 67 / 68 ms |

两种快照 JSON 的 SHA-256 相同。定时器只是衡量事件循环阻塞，不是 HTTP 端到端延迟；为避免项目模块缓存而每次启动新线程，合成样本中单次快照反而多耗约 19 ms。后台观察并不使素材哈希消失，也不证明出片渲染变快。未对真实长片做优化前后基准。
