# 解释完整性修复 · 2026-11-04

## 范围与根因

修共用生成和验收流程，不修改或重做 `projects/llm-2026-11-04/`，不追溯迁移已有项目。

原来的主要缺陷不是没有“讲清楚”的提示，而是过早按栏目填短句、限时删除必要过程，同一作者带着完整背景填写通过理由；校验器只验证字段/引文/版本，不能确认引文构成推断。因此增加正则或登记表不能充当语义修复。

## 新契约 v3

新建项目以及原本没有审稿要求、首次提交的新脚本启用 v3。已有 required 的 v1/v2 项目保持原契约，包括原有解析行为，不自动改稿、补审、重测或恢复媒体。

自动制作仍调用 `review_content`，但 v3 接口只要求 `{signature}`，不接受作者决定的 verdict。手工路径：

```bash
node vh.mjs content-review --dir <项目>                 # 只读，不调用模型
node vh.mjs content-review --independent --dir <项目>   # 两次独立模型请求，会产生用量
```

需要更多输出/推理空间时，可显式使用 `--max-output-tokens N`（256–65536），或与作者循环共用 `VH_AGENT_MAX_OUTPUT_TOKENS`。默认仍为 6000；不因截断自动涨额或重试。后续真实样片曾在第一阶段把 6000 token 全部用于推理，没有给出审稿 JSON，因此新增这一显式配置入口及回归测试；未取得完整结果仍不放行。

`--independent` 在制作写锁内执行，沿用用户当前所选渠道和模型，不自动换模型。两阶段分别建立新 provider pool 和新消息，沿用既有超时、同渠道重试和用量/耗时登记，不复用作者的历史消息、推理或上下文折叠锚点：

1. **只听旁白复原**：输入只有编号旁白、受众已知/未知，逐场复原实际听懂什么、哪里缺前提。不提供标题、作者审稿理由、方案或来源。
2. **对照依据**：另一个新上下文读取当前任务、方案、完整原文/调研材料、claims、第一次复原结果和上次通过稿的必要解释。文章改编查主旨/关键说明丢失；自主调研查资料是否足够、是否硬拼因果；混合输入区分补充与原意。

盲听有缺口，执行器强制保持 revise，不能在第二阶段用资料解释后改成 pass。返修原因含场号和具体缺口。作者须改正文/依据后重新审稿；未改输入重复调用自动工具复用当前结果，不反复花费。手工 `--independent` 是显式重新审稿。

引文与逐场覆盖仍做机器核对，但不要求简单事实硬拼“三句推导”，也不靠关键词是否命中来决定审哪些判断。每场登记理解所必需的实际旁白原句，作为后续压缩的复核基线；返修不会清掉最后通过稿的基线。文件写入受控但不是恶意进程的安全沙箱，回执没有密码学签名。

真实样片还暴露了模型改写或拼接引文导致整份候选丢失的问题。新审稿请求采用场号与本场从 1 开始的句号索引，执行器据索引取真实原句；越界拒绝，不做模糊匹配。独立候选保留在 `out/.vh-content-review-attempts/`，校验失败注明原因，但候选绝不等同于有效审稿或发布通过。原有严格引文校验仍用于旧接口及解析后的记录。

截断、无效 JSON、缺场、请求失败或审稿期间输入变化，不会新登记 pass。`--record` 对 v3 拒绝，不能由作者伪造独立来源字段放行；v1/v2 仍可使用旧接口。

## 依据与版本绑定

- 原文/调研资料放 `research/`，支持递归的 `.md`、`.txt`、`.json`；根目录 `原文.md`/`原文.txt` 也会读取。
- claims 引用的项目内文本路径，即使不在 research，也读取完整上下文；不只把作者挑选的 quote 交给审稿。
- 新项目的 `fetch_url` 自动把完整清洗正文存入 `out/.vh-content-sources/`，而不是只保留返回给作者的前 24000 字符。抓取不是外部核证；HTML 清洗不能保证得到真正文章，审稿仍须核对。
- 自动任务和用户后续补充另行保存在同一私有目录，区分用户输入与外部抓取。手工路径须自行保留真实原文与要求，不可用自写解释冒充来源。
- 所有上述输入正文、路径和 SHA-256 加入 v3 签名。方案、脚本、claims、任务或来源改变，旧记录失效；画面改变不影响内容审稿。
- 本轮支持资料上限 512KiB / 80 个文本文件，超过则停止并要求整理必要来源，不静默截断后标通过。非文本材料列入 omitted，若是必要依据，审稿应返修而非假装已读。项目外路径、目录穿越或符号链接拒绝。

## 生成与限时处理

方案阶段先形成可连续读懂的讲述底稿，再规划场景；按内容实际需要讲出具体对象、必要背景、行动/机制、结果与判断依据。不是每段机械填相同五项。脚本编号行不是字幕上限，不用短碎句配额代替完整表达。

`trim` 保留时长计算和显式引用分析，取消“低密度=水”“零引用=链条不断”“只能场内压缩”的结论。排序使用引用和时长代价，不估算教学价值。候选须先做内容取舍，保住必要解释；装不下时缩支线/讨论拆集，或由用户放宽时长，不靠加速或裁尾。

正常调研的新网页/新范围读取不再因累计七次失去工具；重复/无效读取才触发收窄，仍保留步数和停滞边界。写脚本阶段允许继续抓取补证据。
