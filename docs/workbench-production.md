# 网页自动制作：前后端闭环

## 使用方式

首页粘贴文章或输入选题，选画幅和交付内容，直接点「开始做视频」。无需先执行 CLI 命令。项目页普通生成、改片、继续也使用网页默认自动策略；曾明确关闭的项目保留关闭，只读审阅和单项编辑不扩大范围。

页面的「自动制作」区域用于查看和操作，不是第二道需要手动开启的门槛：

- 区分后续任务的默认策略与当前/最近执行实际使用的策略；
- 显示当前阶段、已用修复轮次/上限及失败卡点；
- 列出机器检查结果，区分渲染前检查与最终成片检查；
- 区分「上次检查通过但未复核」与「在显示时间核验过当前版本」；
- 提供只读核验、取消、继续原任务与高级设置；设置不启动任务，继续由用户主动触发；
- 运行、取消未确认或仍有工具进程时禁止并行继续/改策略；
- 断连时保留上次信息并标明非实时，不自动重新提交任务。

高级设置允许显式关闭自动模式或调整 0–5 轮修复预算；默认开启、默认 2 轮。它只影响以后启动的执行，不热切换正在跑的任务。核验不是重新制作，不执行模型、TTS 或渲染；没有质量回执时不会靠核验按钮凭空造出通过结果。

## 后端接口

| 接口 | 行为 | 保护 |
|---|---|---|
| `GET /_api/production?p=<项目>` | 轻量读取策略、任务、修复进度、最近质检摘要 | 不读整份检查点、不返回原文/完整日志/凭证、不派发任务、不做全量媒体哈希 |
| 同接口 `&verify=1` | 对已有质量回执做当前输入/媒体版本核验 | worker 线程执行、同项目请求合并、最多两项目并发、30 秒超时；制作中拒绝核验变化中的媒体 |
| `POST /_api/production/settings?p=<项目>` | 保存 `{enabled,maxRepairs}`，返回新视图 | 校验布尔值与 0–5 整数、运行/取消中 409、共享制作锁、修改前备份，不启动任务 |
| `POST /_api/chat/cancel` | 请求取消并返回真实 cancelled/cancelling | 等待登记进程退出；未确认前保留屏障 |
| `POST /_api/chat/resume` | 由用户主动继续同一任务 | 保留任务身份/检查点/修复预算，进程未退出时拒绝重复派发 |

所有项目接口对非法项目返回 404，不回退到其它项目。写接口沿用本机同源保护。后台异常不会在页面上被解释为已通过、已取消或已保存。

## 状态来源与性能

`lib/agent.mjs` 将实际修复进度写入本次 task/attempt 的 `automationProgress`。前端不解析日志猜轮次，也不从文件存在推断已经修好。项目卡片可使用 `automationSummary`，无需对每个项目另跑重型验证。

`lib/production-view.mjs` 提供受限摘要；`lib/production-view-worker.mjs` 承担强版本核验。普通轮询跳过 taskStatus 中完整交付媒体检查，不新增周期性大视频 SHA 扫描。已有其它状态轮询路径的同步扫描仍属于后续性能工作，并未声称全局都已异步化。

强核验结果最多短暂保留 60 秒；回执变化、文件身份变化或新制作任务会使缓存失效。这里不用文件系统事件判断新鲜度：macOS 可能把核验前刚完成的写入事件延迟合并，造成“刚通过就过期”的误报。界面只用轻量 stat 身份决定是否继续展示便利结果；真正的核验及所有打包关口仍必须校验字节 SHA-256，时间戳不能代替内容证明。拿不到身份时宁可显示未复核，不缓存成持续绿色。

质量回执与当前版本仍由原严格合同核验；UI 缓存不是打包凭证，不跳过正式交付的强检查。机器通过不等于事实、导演、美术、听感或人工审片通过，也不授权对外发布。

## 代码位置

- 后端与状态：`lib/server.mjs`、`lib/production-view.mjs`、`lib/production-view-worker.mjs`、`lib/task-status.mjs`、`lib/agent.mjs`。
- 网页：`www/player.html`、`www/panel.js`、`www/panel.css`、`www/production-panel.mjs`、`www/index.html`。
- 验证：`test/production-view.test.mjs`、`test/production-progress.test.mjs`、网页面板测试以及原有提交、取消、恢复和播放回归。

新后端接口须由更新后的工作台服务提供。不要为加载更新强行中断正在制作的进程；新生成的 worker 会加载当前执行逻辑，但旧服务进程不会被代码文件自动热替换。旧服务页面会显示需在任务结束后重启，而不是提示用户执行启用命令。

## 已知边界

- 浏览器轮询仍是同步读取轻量状态；强哈希已移到显式核验 worker，但大项目其它状态轮询路径的同步扫描仍可进一步优化。
- UI 不解析日志猜测修复结论；若执行器未写入 `automationProgress`（例如旧 worker），只显示无记录，不回溯伪造轮次。
- 自动策略只约束由 harness 发起的任务；直接绕过 harness 运行作者脚本不在保护范围。
- 机器检查、版本核验和面板状态都不代替原文事实核验、逐段听感、审美判断或人工发布决定。
