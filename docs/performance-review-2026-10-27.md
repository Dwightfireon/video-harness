# 性能专项 Review · 2026-10-27

## 结论

可以继续优化，但必须区分**制作总时间**与**一次渲染时间**。本轮会话中后期改稿、英文发音排查和重出片反复发生，不能把 44–79 分钟都归因于编码器。五分钟 30fps 本身就有 9,000 张画面；完整导出不是一个几百毫秒的网页截图操作。

本次覆盖制作 Agent、输入与缓存身份、build/measure/render/voice、普通/严格质检、封面与打包、工作台轮询。以下代码问题、合成实测与待验证推测分开记录；未使用用户视频，也未调用付费模型。

## 下次正式制作如何定位慢点

```sh
node vh.mjs plan --srt --dir <项目>
node vh.mjs performance --dir <项目>
node vh.mjs performance --json --dir <项目>
```

记录会分别列出 `command`、`step`、`check` 的执行次数、失败次数、合计和最近耗时。**command包含其子步骤，不能相加**。日志没有覆盖 OpenCode 本身的模型等待、外部ASR或人工审阅；没有记录时明确缺测，不编总时间归因。

建议顺序：先减少后期返工 → 用一支真实片的分阶段记录确认主耗时 → 迁移重轮询 → 再做TTS惰性加载和分段依赖重构。持久质检缓存和渲染并发调整必须单独验证正确性，不能靠关闭检查提速。
