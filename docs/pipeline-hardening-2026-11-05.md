# 通用流程加固 · 2026-11-05

范围：共享 harness、生成模板和回归测试；未恢复或修改已删除工程，未启动独立模型审稿。以下区分正确性修复、减少重复工作和未实施的优化，不承诺整片制作提速比例。

## 1. 配音异常路径

旧并发循环先写缓存再重新读取，导致 `--no-cache` 恒定读不到、缓存写入失败也无法继续。旧 `gather` 任一句失败会丢掉本批成功结果，重复文本也重复请求。本轮针对实际生成代码补正常/异常执行测试；成功句可以保存为缓存，但任一句失败仍不能生成有效测量或混流结果。

当前 patch 标记为 v3，仅接受完整字节识别的已知 cache-v2 Kokoro 模板，并核对写入前的原内容、拒绝符号链接、保留备份。旧 edge-tts 或未知自定义脚本不原地自动迁移；现有旧工程不会因为本轮修改自动获得新循环。缓存键、音色、语速、转码与槽位规则不靠降低质量改变。

正常缓存可写时，只保留已验证的文件路径，逐句读取；`--no-cache` 跳过旧缓存，但可以读取本次新写入的 WAV。仅缓存写失败时保留必要波形作为回退。已处理的 MP3 和当前句波形及时释放，不为提速常驻全片解码音频。实际循环探针覆盖冷缓存、热缓存与强制刷新，16 句均为路径引用，输出边界仅当前句的 SoundFile 数组存活；这不是整片峰值 RSS 基准。

同负载离线 A/B 使用 fake edge_tts 和真实 NumPy / SoundFile / FFmpeg，比较完整生成脚本。最终版本在并发 4 下：

| 负载 | v2 请求 | v3 请求 | WAV/时间轴 |
|---|---:|---:|---|
| 8 句且均不重复 | 8 | 8 | 一致 |
| 12 句、6 句唯一 | 12 | 6 | 一致 |

两种负载在 v2/v3、并发 1/4 下的逐句 WAV 汇总哈希与去除引擎版本身份后的时间轴均相同。时间含模拟等待，仅作执行观察，未经多轮交替统计；最终那轮与全量测试并行，非重复负载还有耗时上升，不据此宣称普遍更快。确定收益是重复负载少 6 次合成请求，以及失败续跑不重请求已缓存的成功句。

原始数据：`diagnostics/watch-2026-11-05/edge-loop-benchmark.json`（内存收敛前）与 `edge-loop-benchmark-final.json`（最终版本）；v2 副本：同目录 `edge-v2-baseline.py`。复跑命令（使用已有 TTS Python）：

```sh
~/.local/share/opencode/video-tts/venv/bin/python -B test/voice-edge-loop.test.py --benchmark-v2 diagnostics/watch-2026-11-05/edge-v2-baseline.py
```

## 2. 真实抓取结果代替固定 8 次提示

新增 `lib/research-attempts.mjs`，接入内置 Agent 的 `fetch_url`：

- 开始联网前写 `started`，结束后写 `fetched` / `unavailable` 及固定失败分类；写入同步落盘，进程中断未结束者保留 unknown 含义，不谎报为失败或成功。
- `out/.vh-research-attempts.jsonl` 是追加事件，不受工作台账去重、裁剪影响；不从抓取材料的文件数推测次数。
- `assertion` 为可选的具体断言原句；提供时按同一断言跨 URL 统计，同时保护重复失败的同一 URL。连续两次取不到正文，执行端拒绝该范围的新请求，新断言/其他可用来源不受全项目配额限制。
- 为避免恢复后反复发送，两次仍在执行或结果未落盘也停止该范围，拒绝原因明确区分真实失败与 unknown。
- 成功取得正文重置对应连续失败，不代表验证了事实；剥除脚本和样式后正文过短仍记为抓取失败。
- 日志仅保存 URL/断言的 SHA-256、事件身份、时间和结果分类，不保存凭证、查询参数或正文。损坏、过大或不安全的记录不被默默当成零次，也不自动覆盖；只拒绝无法安全记账的抓取，仍可整理已有资料。
- 只读任务不写入记录；外部会话的 websearch/browser 不经过这个执行端，因此不声称对它们强制生效。未填 `assertion` 只能按 URL 防重复失败；改写同一断言的语义归并没有实现。

撤销旧 `VERIFY_BUDGET=8`、以文件大小判断原文身份以及 `max(worklog, raw文件数)` 的伪计数；原文通道仍保留，不把抓取失败升级成 verified。

一次尝试指一次工具调用，内部既有的连接重试不是独立断言尝试。没有回填历史次数，没有按此日志补签任何事实或发布通过。

## 3. 对比度截图的坐标与清理

`lib/contrast-rendered.mjs` 保留文字并集裁剪、网格/环带采样与 3 / 4.5 阈值：

- 裁剪截图失败后，回退截图使用视口原点，不再沿用裁剪偏移。
- 按 Playwright 实际视口裁剪坐标处理滚动；截图像素与 CSS 像素分开换算，覆盖 DPR 1、1.5、2。
- clip 计算、截图或像素读取失败时仍移除隐藏文字样式；透明分组的清理也有失败路径测试。

这是异常路径正确性修复，不是放宽布局或对比度检查。未据此认定历史某场裁切属于误报。

## 4. 增量重做审计

既有按场缓存、媒体输入身份和发布文案隔离机制继续沿用，不另外建缓存。专项验证覆盖局部重渲、编码/素材变化失效、坏缓存回退、`go --srt` 仅补字幕且不重新配音/混流等情况。

审计发现两项缺口：

1. frame 风格封面仅绑定 HTML，遗漏本地图片/字体的内容身份。本轮补素材依赖，不扩大到 editorial 独立封面。
2. 旧 CLI 删除不完整帧后宣称“只补剩余帧”，但标准 worker 仍截图整个所选范围。已删除这段无收益的预处理和错误承诺；**未实现逐帧断点跳过**，不能只凭 mtime 和 JPEG 尾标记认证帧来自当前源码/渲染器。已有验证过的按场复用不受影响。

旁白改一句仍可能改变后续时间边界、共享字幕和转场，因此不能承诺只重渲该句所在的一场。
