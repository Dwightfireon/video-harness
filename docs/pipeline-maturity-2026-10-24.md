# 全管道打磨与成熟度 · 2026-10-24

## 结论

目前是有真实媒体校验、断点恢复和安全复用保护的**本地制作工作台**，不是任意文章无人值守、稳定产出可发布视频的成熟产品。本轮优先避免“交付错版本、公开内部资料、重复制作”，而不是增加特效或宣称一键出片。

后续进展：已实现显式 [无人值守制作模式](unattended-production.md)、主要 CLI 共享制作锁和登记进程取消回收；自动模式严格检查与有限修复，最终全量 949 项通过。下文保留第一轮全管道审查时的缺口与 880 项验证记录；最新边界和验收以无人值守文档为准，不把历史待办误当作尚未实现，也不把自动模式扩大成普通模式全局保证。

覆盖输入/脚本阶段、构建、配音测量、渲染、混流、验证、打包及状态观察。未调用真实付费模型，未重渲或改写既有用户视频，也未自动重启制作进程。Motion 样片见 [前轮报告](motion-polish.md)，不能拿它代替现有视频验收。

## 已落地的改进

| 环节 | 原风险/浪费 | 当前行为与证据 |
|---|---|---|
| 执行计划 | 必须开跑才知道哪些步骤重做 | `plan`、`go --dry-run`、`render --dry-run` 只读输出执行/复用原因、下一步与资源预算；不执行项目 timeline JS、模型或制作程序 |
| 证据表阶段 | 半份 JSON 一存在便可能进入分场；提示批量上限与工具不一致 | 未闭合/非法 claims 留在 `draft_claims`，支持读半稿后追加/补丁；提示统一 3000 字符。只证明结构，不证明来源支持断言 |
| 配音测量 | 显式相同参数重复测量，改稿后可能丢原音色 | 沿用 timing/既有测量参数，相同显式参数可复用；真实变更后重新测量 |
| 字幕 | `go --srt` 为补文本重做混流 | `subtitles` 单独导出；有效视频仅补 SRT，不执行 TTS/混流；相同内容不改写，覆盖前备份旧字幕 |
| 渲染资源 | CPU 核数减一，无内存约束或磁盘预检 | 默认最多 4 路，CPU/可用内存约束；显式 `--jobs`/环境变量有界；目标卷低于 512 MiB 余量时阻断 |
| 渲染恢复 | 强制整片参数被提前跳过，损坏媒体或编码变更未派发 | 检查内部 `extra:['--all']`、媒体过期及编码设置；按输出名选择基线，不再仅凭场景不变跳过 |
| 局部渲染 | 只渲一场却把其它改动也登记成已完成 | 手动范围须覆盖全部改场、共享输入/时间轴/编码与缓存均允许增量；拒绝冲突范围与未知来源旧帧认证 |
| 本地素材 | 原路径换图片，旧成片仍可能算当前版 | `assets/` 全树及部分静态本地引用按分块 SHA-256 进入构建/媒体输入签名；不以大小/mtime 代替字节身份 |
| 公开交付 | 内部方案/证据泄露，旧字幕/静帧混入，同目录残留旧文件 | 公开白名单、新目录、同卷独占暂存、复制前后及发布前指纹核验；manifest 记录 SHA-256；失败只清本次暂存 |
| 人工清单 | 空审查文件也能被认为没有未勾项 | 要求至少存在清单项；仍不等于可信人工审片回执 |
| 环境诊断 | `doctor` 可能通过 npx 下载，假内核目录被当可用 | 不下载，检查真实可执行内核/本机 Chrome 回退，外部命令有限超时，磁盘检查项目卷 |
| 状态观察 | 运行中轮询也做无用完整交付检查，写状态有半份窗口 | 运行任务跳过该交付检查；状态临时文件 + rename。尚未实现全局异步检查或并发事务 |

核心模块：`lib/pipeline-plan.mjs`、`lib/render-budget.mjs`、`lib/subtitle-export.mjs`、`lib/asset-inputs.mjs`、`lib/public-package.mjs`；CLI 接入位于 `vh.mjs`。

## 使用方式

在仓库目录执行，将 `<项目>` 替换为实际项目路径：

```bash
node vh.mjs plan --dir <项目> --srt
node vh.mjs go --dir <项目> --dry-run --json
node vh.mjs doctor --dir <项目>
node vh.mjs subtitles --dir <项目>
node vh.mjs render --dir <项目> --all --jobs 2
node vh.mjs pack --dir <项目> --out dist/新的交付目录
```

`plan` 的 `ok` 仅表示没有已识别的计划阻塞，不等于可发布、依赖已安装或费用获批。标准时间轴按纯数据校验，非标准格式标为未知，不执行自定义校验器。它可能运行媒体探针及同步哈希，不是零开销查询。上游实际执行后仍重新判定。

并发命令行优先于 `VH_RENDER_JOBS`，请求范围 1–32，实际受 CPU/内存限制；不是跨项目队列。帧空间仅粗估，不是磁盘预留或制作耗时保证；未知容量会警告，复杂画面/编码临时空间仍可能超出估计。

## 兼容性与保守降级

1. **旧帧不认证新整片。** 正式 CLI 暂拒绝 `--encode-only` 及任意 `--from/--to`；尚未实现逐帧来源凭证。改用安全 `--scenes` 或 `--all`；取样预览用 `stills --at`。已知非法请求在制作/缓存清理前拒绝。直接运行工程 renderer 不属于 harness 的版本认证路径。
2. **增量要求严格。** 手动局部不能漏场或与 `--all` 混用；长转场、共享输入变化、素材变化、编码变化或缓存不全时自动整片回退，显式局部则拒绝。`go` 默认清帧，频繁迭代可 `--keep-frames`；仅 MP4 分段不足以安全增量。
3. **旧素材凭证会失效。** 素材参与签名后，旧产物可能需要 build/render/voice。未使用文件或注释字面量也可能引发保守失效；不擅自替用户重做。
4. **独立字幕取自当前 HTML。** 不执行作者 JS，仅接受 JSON/受限旧版纯数据字幕。它不证明 HTML 已是最新脚本，正式打包仍验证媒体与当前输入；旧字幕缺失/无效会省略并提示。
5. **公开包不是工程备份。** 默认含有声视频、可选静音母版、公开脚本、当前有效 SRT，以及发布包目标的发布文案；另有交付说明和 manifest。默认排除内部方案、claims、原文、审查材料、`references/publish.md`。公开稿的语义与隐私仍需核对。
6. **封面/静帧不凭存在就携带。** 封面未绑定版本，默认省略并提示；`--with-stills` 须有新版 `stills` 登记的输入签名和逐文件 SHA/大小，只复制清单文件。旧工程须重新截图；按时间截图不等于逐场交付回执。
7. **输出必须新目录。** 即使空目录也不覆盖，默认名含高精度时间与随机后缀。暂存核验后 rename 不是跨进程锁、恶意并发防护或断电持久性保证。
8. **force 不洗白产物。** `pack --force` 可覆盖原有质量/人工门槛并留下提示，但不能绕过过期媒体、错误文件指纹、无音轨或发布文案必填/版本检查；不代表人看过。历史未关联文案仍保留既有警告兼容策略，不伪造历史凭证。
