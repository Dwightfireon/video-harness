# 无人值守制作：执行、质检与有限修复

这轮的目标是**不需要盯着阶段推进，也不需要发现普通版式错误后反复点继续**。无人值守不是“任何错误都无限重试”，也不是程序替人勾审阅或自动发布。

## 使用

**网页不需要手动启用。** 首页粘贴文章/输入选题，选择画幅和交付内容，点「开始做视频」即可。项目页的普通生成、改片和继续任务也默认自动推进、严格质检和有限修复。新建网页项目在派发前保存策略；旧项目在启动新执行时使用网页默认值，不擅自改写旧项目配置。

只读审阅、只改文案或指定单项编辑不扩大成全片制作；用户曾明确关闭项目自动策略的，仍尊重关闭设置。已运行的任务不会被网页刷新热切换或重复派发。旧工作台派发的新 worker 也会加载当前网页默认策略，无需为了启用功能中断正在跑的任务。

以下命令仅供**独立 CLI 使用或高级配置**，不是网页生成的前置步骤。已有 CLI 项目可开启一次；这个设置本身不调用模型：

```bash
node vh.mjs automation --dir <项目> --enable
node vh.mjs plan --dir <项目> --srt
```

之后独立 CLI 启动的新制作任务也会使用自动策略。也可只为一次 CLI 任务启用：

```bash
node vh.mjs ask "根据材料完成视频，自动修复可处理的问题" --dir <项目> --unattended
```

`ask` 会沿用当前渠道和本机凭证，正常产生渠道用量；开启配置不会替你派发任务，不自动换渠道。已经运行的进程不热更新，应等待其结束，不能重复启动。

作者文件已经齐备、只需本地出片时：

```bash
node vh.mjs go --dir <项目> --unattended
node vh.mjs quality --dir <项目> --json
```

`go` 仍不调用写作模型，不能凭空生成脚本或代替 agent 改稿。仅一次 `--unattended` 不改项目设置。关闭项目默认策略用 `automation --disable`，调整修复预算用 `automation --max-repairs 0..5`（默认 2）；运行中不改策略。修改配置前保留备份。

## 自动推进与修复

- **制作阶段有结构化回执**：固定 `run_stage` 的退出码、阶段和日志路径由 wrapper 直接给定，人类日志只作诊断；构建成功后附带的非阻塞结构警告不会反过来宣告“失败”并消耗修复额度。通用 shell `run` 仍会识别复合命令里的失败行。
- **修复是一轮事务**：一轮内可以连续打多处短补丁；修完调用 `finish_repair` 提交复检，不会每改一个文件就结束整轮修复。未提交前不重跑重型阶段，输入未变不能提交为完成。
- Agent 新建方案/脚本时先分批写作，全文完成后用 `finish_draft({path,base_hash})` 提交。文件存在不再表示草稿完成；状态保存在 `out/.vh-author-drafts/`，恢复不会跳过后续批次。提交核验版本和结构，不代表事实或人工审稿通过。
- 旧项目初稿会核对方案分场表，缺 S4–S8 等内容先续写；初始化示例及未组装的分场草稿不会因数量相等就被当作已完成画面。已提交或已有渲染的后续删场不按旧方案强行补回。场景保存必须声明真实 `@layout` 版式名，缺声明在写作阶段就拒绝。
- **用错工具不是空转**：模型把 shell 命令塞进 `run_stage` 的 stage 字段时，本地直接拒绝并给出可照做的用法（改用 `run` / `read_file`），不计偏离轮次、不写 blocker。旧实现只回"未知制作阶段"并把它记成阶段失败，同时关掉强制动手，模型只能反复读文件直到被轮次上限打死。
- **轮次上限只数"没有推进"的轮次**：某一小步骤里只要有真实产出推进（作者文件或产物变化），"连续未完成"计数就清零；上限防的是原地打转，不是"读得久"。
- **遗弃的元数据门可安全恢复**：强杀执行器会留下 `.transaction` 门，使项目永久报 `metadata-transaction`、无法继续或取消。当门为空、确实老于事务上限、且不存在仍活跃的 owner／participant／child 时才清理；任一条件不满足都保持阻断，不猜。
- **新要求默认算要求**：判断"用户这轮提没提要求"不用编辑动词词表，而是默认任何新发言都算，只有封闭的一小组纯"继续/重试"才豁免；明确要求先讨论则不改稿。落实与否按模式契约核对真实文件基线，所以只改 `发布文案.md` 不能满足视频修改要求，也不会反过来把补文案任务卡住。
- 对已准备好的输入，程序直接执行 build → 必要 measure → render → voice → validate，不花模型请求让它重复下命令。
- 渲染前执行严格机器关口：纯数据结构、实测时间轴、素材、构建基线，以及真实浏览器里的抽样文字可读性、溢出/越界与字幕实显。未安装检查器、检查抛错、无采样或失败均不能算通过。
- 严格前置检查通过后，才跳过旧 renderer 等待人工 Markdown 清单的步骤；不修改任何人工审阅勾选，也不把它写成“人已看过”。普通模式保留既有行为。
- 内容/版式类失败在**同一次任务**进入短补丁修复，再按真实输入判断哪些阶段要重跑。不能因为写了一个文件就说修好，须复测。
- 每任务默认最多两轮自动修复，计数写入检查点，恢复不清零；相同输入同一错误不原样重跑。没有产出仍受阶段/总步数预算约束。
- 额度耗尽的旧暂停若实际缺少上游稿件，继续时先补缺稿而不是立即秒退；作者输入确已改变时允许重新核验，但已用修复次数保留，失败不额外赠送修复轮次。环境/未知故障不因改文案而自动解锁。
- 环境、磁盘、检查器及原因不明的失败停止并保留现场，不让模型靠删除内容、提高时长或降低检查阈值“修复”。网络/额度仍服从现有有限重试策略，不无限重启任务。
- 已有结果未知的工具副作用，仍先核对，不因自动模式就盲目重放。

首页和“指挥”把具体暂停原因放在前面，“尚无成片”只作独立产物状态；继续运行后不显示上一轮的旧错误。`build` 对明确的主体字段只做带备份的格式规范化，不替用户选主体、不修改旁白、不改全局 skill；多主体的开场引入仍由严格检查和内容修复负责。

## 最终质量回执

位置：`out/.vh-production-quality.json`。必须是当前输入与实际媒体的回执，不能仅凭文件存在或历史绿色状态认定完成。

最终检查复测结构与浏览器项目，并增加：

1. 当前版本的真实视频/音轨与媒体指纹合同；
2. 当前 SRT；缺失时独立导出，不因此重做 TTS/混流；
3. ffmpeg 完整解码，不仅探测片头元数据；
4. 首条音轨整体全静音与严重近满幅采样检测。

普通停顿与黑背景不是自动错误。音频检测不是语音识别，不证明发音、内容、情绪、音画逐句同步或听感。浏览器是抽样检查，不是逐帧审美评审。事实、导演能力与语义正确性没有被这些检查替代。

启用了项目默认自动策略时，公开打包还要求当前最终机器质量回执；`pack --force` 不能跳过。不会自动对外发布。

## 防止并写与取消

主要 CLI 制作入口与 ask 整任务共享项目制作锁，子阶段带委托身份重入；不同项目各自独立。重型制作工具改为异步派发并登记进程，父进程死亡而已登记子进程组仍存活时，不能把锁当成过期抢占。

锁目录为项目根下 `.vh-production.lock/`。只保存委托 token 摘要，不记录正文/密钥。元数据损坏或写锁事务中途崩溃会保守阻断；不要看到“忙”就直接删锁。它不是 OS 沙箱，绕过 harness 直接运行作者脚本或故意脱离进程组的后代不在完整保证内。

取消采用“请求停止 → 等待 → 必要时强制结束 → 确认退出”的生命周期；取消待退出期间禁止重复派发。未确认退出时保留登记，不用删除文件来假装取消成功。

## 尚未承诺

- 任意新题材都能自动达到手工样片的导演和美术水平；
- 事实来源的语义核验、ASR 逐句配音校对、完整主观听感评估；
- 跨项目 GPU/TTS 队列、硬费用上限、自动安装依赖、异常断电后的全部自动修复；
- 动态/远程/传递素材依赖全部锁定，或恶意进程对文件的瞬时改动都可检测；
- 完全无人干预地恢复未知副作用、损坏锁或额度不足。

所以当前交付是**能自行推进、有限自修、严格报告成功或失败的自动制作模式**，不是“永远成功”开关。本轮验证只用隔离工程、模拟模型响应、真实本地浏览器和短合成媒体，未运行用户现有项目或真实收费模型。

网页默认接入后的全量回归：**976 项通过，0 失败、0 跳过**，约 24.1 秒，日志 `sh_16e4af607001NuOcwTiNEB7qwj.out`。新增覆盖页面状态/设置/强核验接口、真实页面提交 → 实际 worker 修复 → 轮次显示、桌面与 390px 布局、取消失败与断连不假报；仍使用本地模拟渠道，不扣真实额度。

验证涵盖：

- 真实 CLI 有效成片只补字幕，经过真实浏览器、完整解码与音频检测；最终 agent 确定性关口不再请求模型；
- 不可读文字即使带 force 也不派发 renderer；严格检查通过才传旧人工等待 override；
- 模拟模型实际写入短补丁，同一任务自动复测，达到修复上限停止；恢复不清零，无环境故障改稿；
- 两个 CLI 竞争、委托重入、父死子组活、组长死后代活、坏锁/权限错误保守阻断；
- 真实 build/ask 的 TERM → 强制回收，HTTP 取消及重启后的取消屏障；未停止不能恢复或并写；
- 正常失败退出不留下假运行标记，取消未完成则保留登记；恢复测试等待实际可继续，而不只等待提前写入的 paused 状态；
- 现有网页提交、播放、配置、检查点恢复、公开交付和普通模式回归。

这不是任意新文章、真实 TTS 服务或收费模型的端到端视听质量认证；没有凭测试数量推算成功率或成熟度百分比。
