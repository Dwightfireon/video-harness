# 内容优先：系统优化方案与验收

## 目标与范围

用户要求从系统整体提速：内容质量优先，形式次要，不需要制作工具承担默认的检查、审核与发布审批。目标是减少首个可交付版本之前的流程和模型往返，不降低编码画质，不冒充事实核证、看帧、试听或人工批准。

不修改已发布视频，不批量迁移项目，不删除原稿、依据或缓存，不调用付费模型制作或审稿，不实际投稿。

## 当前问题

1. `build` 默认执行大量讲述、风格和静态画面诊断，浏览器版式和字幕另起会话；这些提示还会诱发模型反复修稿。
2. 自动推进与完整视觉审核耦合，前置和最终质检重复检查相同 HTML。
3. Agent、CLI 任务模板、阶段提示存在冲突：两版试稿、强制样片、反复审核，以及失败后建议 `render --all`。
4. 关键来源登记被独立的 claims 文书阶段绑住；文件存在性与内容质量混为一谈。
5. 普通 `pack` 把建议性静态版式检查、Markdown 勾选和指纹审阅 JSON 叠成发布门槛；工作台把可选人工审阅显示为未完成制作。

## 统一决策

用一个工作流策略供 CLI、Agent、生产质量、打包与展示共用：

| 项目 | 默认 content-first | 主动选择 audited |
|---|---|---|
| 写作 | 理解来源、连贯讲述、保留必要解释 | 相同 |
| 资料 | 保存原文，关键出处随方案/脚本；新增重要事实定向核对 | 另要求结构化 claims |
| 形式诊断 | 不自动运行 | 构建时运行 |
| 视觉阈值审核 | 手动运行，不阻塞默认制作 | 要求实际采样通过 |
| 生产保护 | 结构、资源、运行、实测、字幕、版本、媒体完整性 | 相同 |
| 人工发布记录 | 可选；未执行仍未执行 | 显式发布验收时要求 |
| 交付 | 首个技术完整版本立即给路径，用户看后再改 | 不虚构审阅结论 |

模式保存在 `PROJECT.json.workflow.profile`；没有配置时采用默认，不写回或重做历史产物。历史 `contentReview.required=true` 独立保留；切换工作流不启用付费审稿，也不关闭旧合同。

## 实施顺序

1. 建立小型统一策略模块和可测试的默认/显式选择。
2. 将技术检查与视觉审核分开；省去默认无用扫描，检查范围写入回执，不把未运行标为通过。
3. 对齐 Agent 的任务、阶段、恢复和收尾提示；取消独立文书/审美返工的默认关键路径，保留完整提交及冲突保护。
4. 普通打包不再要求人工清单；显式审阅打包保留真实记录核验。界面区分“已交付”和“可选审阅”。
5. 针对核心成功/失败路径回归，运行全套测试；以相同输入测量诊断范围和实际耗时，不把合成基准说成整片提速。

## 验收标准

- 新项目与继续任务的默认路径不要求两版试稿、形式总分、独立 claims 文书或人工审阅签字。
- 普通 `pack` 可交付有效媒体；显式审校/发布验收仍拒绝缺失、过期和失败记录。
- 关闭可选审核不放行损坏媒体、旧版本配音、截断字幕、缺失资源或错误缓存。
- 审核没有运行时，回执与界面明确显示未运行/可选，不伪造 pass。
- 自动推进不等于自动审核，更不等于自动发布。
- 发布授权、浏览器沙箱、写锁、版本边界与文件保护不变。

## 验证结果

### 已实施

- `lib/workflow-policy.mjs` 统一 authoring / build / render / quality / package / workbench 策略；`workflow` CLI 只在显式保存时备份配置，不修改模型审稿授权。
- 默认 build 不运行大组词面、版式和讲述形式诊断，不加载完整 UI snapshot 来判断测量状态。字幕实显、运行/资源有效性仍检查。
- 技术回执不运行对比度/布局策略扫描，明确记录 `not-run / ok:null / required:false`；完整审校不能借技术回执通过。技术模式仍保留逐句首中尾字幕探针和最终媒体核验。
- 最终阶段可复用同 profile、相同输入和素材字节绑定的渲染前浏览器证据，记录复用来源；最终媒体、SRT、解码、基础音频与稳定性仍独立核对。手动 `quality` 默认重新完整检查。
- 标准时间轴工程即使非自动制作也使用统一的结构、构建、运行与字幕技术保护；未知旧自定义工程保留兼容运行检查。已知 renderer 的重复审核仅按完整哈希识别后略过，未知自定义不自动 force。
- Agent 默认去掉独立 claims 阶段，关键出处留在方案/脚本；必需模型审稿合同仍要求原有依据。旧检查点历史不改写，发送投影与尾注附当前政策。取消强制试版/创作配额/全片重渲纠偏建议，并在成功回答提供真实成片路径。
- 普通 pack 无人工 Markdown 清单与 JSON 审阅双重等待，仍验证媒体、配音身份、当前版本、文案、公开白名单与复制后字节。保留兼容 manifest.status，增加 deliveryReady 与 review.required，未审仍 releaseReady=false。显式 reviewed / audited 保留真实记录核验。
- 工作台把“视频已交付”与“人工审阅可选”分开；只读任务不因缺成片被迫进入制作，暂停提示优先给合法工具与目标，保留恢复、写入冲突和预算保护。

### 同输入构建基准

命令：`node scripts/benchmark-content-first.mjs --dir projects/ai-token`。

仅复制作者、生成器与时间轴文件到本轮临时目录，源工程没有改动；同一修订的默认 build 与主动 `build --audit` 各执行两次，交错顺序。

| 模式 | 两次耗时 | 平均 |
|---|---|---|
| 内容优先 | 1307 / 1021 ms | 1164 ms |
| 完整形式诊断 | 2966 / 2542 ms | 2754 ms |

此构建样本少耗时 **57.7%**。两边都检查 88 句 / 264 个字幕首中尾采样，生成 `scene.html` 字节相同。原始记录：`diagnostics/content-first-benchmark-2026-11-06.json`。

这不是旧版全流程基准，也不覆盖模型写作/等待、TTS、视频截图编码、混流与人工审阅；不能把 57.7% 当成整片提速。现有 performance 日志确有连续三次因版式阻断的记录，但缺少可比制作边界，不计算其节省时间。

### 回归与限制

最终执行 `npm test`：**1560 项，1559 通过，0 失败，1 跳过**，约 194 秒。跳过的是显式环境开关控制的旧渲染器稀疏帧性能基准，不是必要技术断言。完整日志：`diagnostics/content-first-tests-final-2026-11-06.log`。

回归实际覆盖默认导出、主动审校、历史合同、读写范围、字幕截断/隐藏、源稿与字幕错配、坏资源/运行、损坏媒体、配音身份、错误缓存、并发修改、复制完整性及桌面/手机展示。首轮失败中，旧预期改为显式 audited/主动 audit；缺字幕的管线隔离夹具补入真实 DOM 字幕，而不是绕过新保护；实际修正发布收尾转发 reviewed、恢复提示的合法动作前置和技术/视觉未执行项的故障分类。

未新做一支真实内容视频，未调用付费模型或重新合成真实项目配音，未试听/发布；现有成片和旧回执未重做。旧任务的真实失败、未知故障或修复预算不自动清零；需要按原有恢复保护继续。
