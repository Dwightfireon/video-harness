# 默认不限视频时长 · 2026-11-04

用户明确要求：内容需要多长就做多长，避免为满足时长上限牺牲解释质量。

## 行为

- CLI 与网页的新项目持久化 `durationLimit: null`，不默认设置 480 秒上限或 420 秒目标，不强迫固定场数。
- `durationPrompt` 明确按受众和问题保留必要背景、过程、判断依据与限定，删重复/无关支线，不注水。
- 用户可用 `node vh.mjs duration --max N --dir <项目>` 显式限时，或用 `duration --unlimited` 取消；两种选项不可混用。
- 不再以 900 秒作为内容天花板。用户明确指定的上限仍须为正有限、可安全表示的秒数；目标不能超过上限。不限时长项目只写 `--target` 会拒绝，不能暗中补一个上限。
- 已有项目不批量迁移、不重做视频。原有显式上限保留，直到用户主动取消；制作 Agent 不能自行添加、放宽或移除时长策略。

## 没有取消的边界

配音测量、字幕与时间轴一致性、实际媒体检查、输入指纹、磁盘/内存/并发预算和内容/视觉/音频审阅全部保留。

实现时发现旧代码把“必须有有效配音测量”放在 `if (durationLimit)` 下。现在将测量要求与时长上限分开：新项目和主动设置过时长策略的项目，即使 `durationLimit:null`，正式渲染也必须有有效配音实测；无显式策略的历史手写工程保留旧契约，不追溯强加迁移。

## 当前样片

时长与资源预算是不同维度。不限时长不代表不限资源、取消质量检查，也不承诺长视频能在固定制作时间内完成。
