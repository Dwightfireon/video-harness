# 产品成熟度与本轮改进

## 判断

已有完整的本地制作链、断点恢复和真实媒体校验；仍是面向熟练操作者的制作工作台，不能据此宣称任意选题一键出片的视听质量稳定。成熟产品需要让用户清楚知道：正在做什么、哪些结果属于当前版本、失败后如何继续、交付前还有什么未经确认。

2026-10-23 的 Motion 专项检查、已修正确性问题、旧工程升级方式与剩余验收标准见 [Motion 打磨与产品差距](motion-maturity-2026-10-23.md)。核心短板是动作没有随讲述推进，以及连续审阅尚未绑定最终版本；不是特效种类不够。

同日第二轮已补最小的字幕锚定编排、安全取景和可操作的同内容对照，见 [Motion 高级感与准确度](motion-polish.md)。这些能力帮助控制动作，不代表既有成片已自动改好，也不取代题材美术、事实核对和连续视听审阅。

2026-10-24 已进一步打磨整条管道：只读计划、字幕独立导出、有界渲染并发与磁盘预检、素材字节失效、局部范围保护和公开白名单打包。已修问题、保守降级及后续验收见 [全管道成熟度报告](pipeline-maturity-2026-10-24.md)。目前更适合称为“受控本地制作工作台”，仍不是无需人工照看的成熟自动出片产品。

后续已新增 [无人值守制作模式](unattended-production.md)：网页生成/改片/继续默认接入，独立 CLI 可显式启用；程序推进确定性阶段、严格质量回执与有限自修，主要 CLI 入口共享项目锁，取消后等待并核实登记进程退出。网页接入后全量 **951 项通过**。它减少盯阶段和普通报错后手动续跑，但不承诺任意选题的事实、导演与听感自动达标，也不自动发布。

## 本轮优先级

| 优先级 | 现场差距 | 本轮实现与验收 |
|---|---|---|
| P0 | 脚本改变后，旧发布文案仍可能通过完整性检查 | 关联脚本/明确要求与文案内容的版本凭证；已关联的旧稿变更后阻断发布包；历史文案显示未关联，不擅自制造历史凭证 |
| P0 | 阶段藏在日志，原始命令和过期项不能代替操作引导 | 项目阶段概览、实际执行阶段、下一步入口；不伪造百分比或预计剩余时间 |
| P1 | 刷新丢输入，断连后旧状态仍像实时状态 | 可选择的本机草稿保存、明确的读取失败/恢复提示，失败不清输入、不自动重复提交 |
| P1 | 交付目标只能在新建后选择 | 新建前选择仅视频/发布包，先保存配置再派发任务，非法配置不产生半成品项目 |
| P0 | 运行中也能从网页清缓存、删除项目，失败后卡片可能丢失或重复 | 运行中拒绝清理/删除；请求失败如实提示并保留卡片，不实际操作用户项目 |

不改用户既有视频、文案或项目设置；不自动重启正在工作的进程，不触发真实付费模型，不修改认证和渠道策略。

## 仍需后续完成

- **视听质量**：同内容关键样片与用户确认、逐段试听、字幕/视觉问题的审阅闭环。程序和截图存在不能证明美术质量。
- **人工审阅版本**：现有勾选只表示登记；需要另建绑定最终视频与文案的人工审阅回执，不能用机器确认代替人看过。
- **成本与资源**：已有帧空间估算、单次渲染并发约束，以及登记的顽固子进程取消回归；仍缺付费预算上限、完整阶段耗时/用量统计、跨项目队列和长时间压力测试。
- **安装与维护**：明确本机依赖、锁定可复现环境、升级/回滚与数据迁移、自动化发行验收。现有 package.json 不等于完整可分发安装包。
- **平台交付**：分平台长度/标签/封面规则、可视化导出及发布记录。自动对外发布须另行授权，不在本轮自动操作范围。
- **长期可靠性**：大项目/多项目性能、异常断电与磁盘不足故障注入、真实用户验收。单元测试数量不是成熟度分数。
- **版本与事务**：主要制作 CLI 与 ask 整任务已有共享锁，显式自动模式的严格质检失败不能算通过；仍须补齐动态/外部素材、工具与音频参数依赖，以及方案/脚本明确草稿提交。普通模式保留兼容行为，不应把它误认为自动模式的严格质量保证。原子写状态不等于断电持久性保证。
