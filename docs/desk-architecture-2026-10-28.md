# 发布台架构与分区修正 · 2026-10-28

> **后续更正**：本文记录首轮改造。其中“本发布台只能用旧分区”的判断已被后续官方客户端与真实接口核对推翻；现已接入新版 `human_type2`。当前用法见 `desk/README.md`，补齐记录见 `docs/desk-human-type2-2026-10-28.md`。下文保留首轮历史，不作为当前分区使用说明。

## 结论

原来已有 adapter、草稿、上传客户端分层，不需要重写。真正的耦合是表单规则与 payload 映射重复，IPC 承担业务判断，界面靠警告文本推导能否投稿。本轮只收敛发布台链路，不改视频引擎、全局 skill 或既有人工审阅规则。

## 当前边界

```text
UI ── preload/IPC ── service（预览、分区核对、提交用例）
 │                       ├─ projects → harness-adapter → lib/*
 │                       └─ publish（本地预检、上传、提交）→ bili（HTTP 协议）
 └─ publish-contract / partitions（前后端共享的纯规则）
```

- `desk/publish-contract.mjs`：标题、标签、版权、简介、素材校验与 payload 映射；旧导入入口保留兼容。
- `desk/partitions.mjs`：真实响应解析、离线参考、搜索别名、旧 tid 边界、内容建议。
- `desk/service.mjs`：统一预览与提交，投稿前重新取实时分区，单进程内拒绝并发提交；IPC 不再逐字段拼 payload。
- `desk/harness-adapter.mjs`：每份草稿只核验一次媒体，不跨请求缓存；静音母版用自己的时长，核验异常不当成“未过期”。
- `desk/draft.mjs`：结构化 `blockers`，不从中文提示反推权限。
- `desk/publish.mjs`：封面本地检查提前到上传前；进度通知和清理异常不会覆盖已确认的提交结果。
- `desk/bili.mjs`：超时覆盖响应体读取；保留 HTTP 状态，明确区分未提交、明确拒绝、结果未知与已提交。不自动重试投稿。

## 分区事实与建议分开

2026-10-28 只读查询本机账号的投稿接口，返回旧分区 `科技 → 计算机技术（231）`，描述包含人工智能、大数据、深度学习。脱敏科技分区节选位于 `test/fixtures/desk-partitions-tech.json`。

新版官方首页另有独立[人工智能频道](https://www.bilibili.com/c/ai/)。社区 API 文档将其标为 `tid_v2=1011`、`channelId=25`，不能把它当作旧投稿 `tid`。本轮没有验证新投稿协议或旧新分区的稿件映射，不据此声称能控制新版频道归属。

建议：本发布台里，Agent／大模型讲解、开发实操选 **科技 · 计算机技术（231）**；官方页面如果提供新版“人工智能”，AI／Agent 主题优先考虑它，一般编程/算法等选计算机相关分类。AI影像、AI音乐是另一类创作内容，不因视频用了 AI 制作就选择。

离线清单原来把 171 写成单机游戏、208 写成财经商业、父分类 188 写成软件应用等，已改为核对过的常用叶子分区。离线只可浏览，正式提交必须取得当前账号实时列表；遇到新版协议停止而不是猜映射。搜索 AI、Agent、人工智能、计算机科学均可命中 231，不篡改官方名称、不自动选择。
