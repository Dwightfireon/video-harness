# 执行器收尾：断线恢复与文案版本登记

## 两个真实事故

**一、任务明明做完了，却显示「制作失败。任务未完成，请查看日志后重试。」**

现象：8 分 44 秒的片子已交付，技术检查全过，工作台却标失败；「继续任务」按钮消失，用户不知道发生了什么。

链路（日志行号取自当次 `out/.vh-chat.log`）：

1. 第 98 行 `ECONNRESET`：模型请求中途断开。
2. opencode 自动重连，之后又跑了半小时，写脚本、渲染、配音、封面、交付包全部完成。
3. 执行器把「运行期间出现过一条 error 事件」永久记成失败：`if (failure) return { status: 'failed' }`。
4. 失败类型归到 `execution`，界面只显示通用文案；`delivered=true` 又让「继续任务」消失。

**二、用 opencode 补文案后，永远显示「历史文案尚未关联脚本版本」**

`confirmPublishRevision` 只在本地执行器 `lib/agent.mjs` 的受控写入钩子里调用。opencode 走原生工具，没有任何地方登记。

## 改了什么

### 1. 中途报错后恢复 → 按完成处理

`recoveredAfterError(events)`：错误事件之后，**有工具成功执行**且**又输出了回答**，才算恢复。只有顺序证据，不猜。

- 不能要求退出码为 0：真实事故里同一错误的余波让进程最终退出 1。
- 恢复后仍走 `settleTaskResult`，作者文件与交付物核验照旧；没改到文件依旧判 `incomplete`。
- 恢复会写成一条警告，不是悄悄抹掉。

### 2. 收尾非零但交付完整 → 不叫「制作失败」

同一套 `settleTaskResult` 判定：交付齐全就 `completed` + 警告；不齐全仍 `failed`。

### 3. 网络错误归类

`classifyEventError` 补上 `ECONNRESET`/`ECONNREFUSED`/`ENOTFOUND`/`EAI_AGAIN`/`EPIPE`/`socket hang up`，归到 `network`。原先落入 `execution`，提示是「任务未完成」，等于什么都没说。

### 4. 文案版本

新增 `settlePublishWrite(project, { baseline })`：

| 情况 | 结果 |
|---|---|
| 文案已是 current | 不动，保留原确认人与来源 |
| 本轮没改文案 | 不登记 |
| 脚本或要求在本轮变化 | 不登记，提示手动核对 |
| 文案缺项 / 占位符 | 不登记 |
| 改了且完整、输入未变 | 按 `by: 'agent'` 关联 |

执行器在开跑前记 `{sourceSignature, publishHash}`，收尾时调用。用户手动确认过的（`by: 'user'`）不会被自动流程覆盖。

### 5. 界面

- `taskNotices` 增加 `warnings`，只在结束后展示；不覆盖失败原因。
- 已交付但收尾异常：卡片显示「制作结果已交付；执行器收尾异常退出，详见日志。」
- `taskStatus` 只读转出 `warnings`，不参与状态判定。

## 边界

- 不改 `settleTaskResult` 的判定标准：能算完成的前提仍是作者文件改动 + 交付物核验。
- 不把「有输出」当「做对了」：恢复只影响**是否判失败**，不影响交付核验。
- 警告不是审阅：恢复与自动登记都明确写「不等于人工审阅」。
- 不动本地执行器 `lib/agent.mjs` 的即时登记路径。

## 验证

- 新增 6 条执行器用例：中途恢复但没改文件→`incomplete`；恢复且改到文件→`completed` + 警告；错误后无成功动作→`failed`；完整文案→`current`/`agent`；不完整文案→不登记；已手动确认→不被改写。
- 新增界面用例：已交付 + 收尾异常不显示「任务未完成」，恢复警告可见；`taskNotices` 的警告过滤与运行中不展示。
- 相关回归 130 项通过、0 失败；全量 1808 项中 1807 通过、0 失败、1 项既有 skip（real-media fixture）。

## 界面文案

卡片状态分三种，避免把「做完了但收尾脏」说成失败：

| 情形 | 卡片状态 |
|---|---|
| 正常完成 | 制作结束 · 待查看 |
| 已交付，收尾异常 | 制作结束 · 已交付（收尾异常），红色不启用 |
| 确实失败 | 制作失败 |

恢复警告只写人话（「运行中曾出现网络连接中断，之后已恢复并继续，未影响最终结果；错误原文见日志」），不把 `ECONNRESET` 之类原始串塞进卡片，也不和失败原因混在一起。
