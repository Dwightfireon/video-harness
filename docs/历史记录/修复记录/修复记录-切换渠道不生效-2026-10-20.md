# 修复记录 · 切渠道后"看起来没生效"（2026-10-20）

用户反馈：任务中断后点「继续任务」、并切换了渠道，两件事"都没起作用"，界面一直显示 CommandCode。

## 结论

**渠道切换与「继续任务」其实一直是有效的**，但有三处让它们"看不出来"，加上一次真实的状态污染：

### 1. 界面从不显示"这次用的渠道"（主因）

切换后没有任何地方显示当前用的是哪个渠道。唯一出现渠道名的地方是**失败信息**，而失败信息里的渠道属于**上一次执行**——看起来就像"切换没生效"。

已修：任务状态新增 `usedProvider`（上次用的）、`selectedProvider`（当前选的）、`channelMismatch`（两者不同且未在运行时为真），三个字段在首页卡片与播放器都显示。切了渠道但没重新执行时，会直接提示"点「继续任务」后才会用新渠道"。

### 2. 请求失败时渠道不落盘（真实缺陷）

`lib/agent.mjs` 里渠道只在 `onSuccess` 回调中写入 `.vh-state.json`——那是**请求成功后**才触发。额度不足（HTTP 402）、证书错误等失败场景下，请求直接失败，state 里的渠道停在"上一次成功"的那个。

已修：执行一开始就记录所用渠道与模型，不再等请求成功。

### 3. 首页「继续任务」清空 Map 却留下旧 DOM

`www/index.html` 的继续按钮里 `cards.clear()` 清空了 Map，但旧卡片节点仍留在 DOM 里。Map 与 DOM 失去对应关系，后续 `load()` 会再造一份，出现重复卡片与点不动的旧按钮。

已修：改为只把目标卡片的签名置空（强制重建那一张），不再 `cards.clear()`；`load()` 替换节点时显式 `remove()` 旧节点。

### 4. 一次真实的状态污染（我造成的）

排查过程中我在 12:59 与 13:02 两次把渠道切到 commandcode 并触发了「继续任务」，把项目推到了第 6、7 次执行，于是项目日志与 state 里都是 CommandCode 的额度不足。这两次不是用户的操作。用户随后切到 opencode-go 但没有再点继续，所以界面停在 commandcode 的结果上。

已在此说明，避免把测试动作当成用户行为。

## 顺带修掉的

- **日志污染**：`node:sqlite` 的 ExperimentalWarning 打进了项目聊天日志（agent 子进程的 stderr 就是日志文件）。已在加载时抑制该警告。
- **误导性日志行**：`模型：… / …（固定渠道，OpenDesign 可恢复故障最多重试一次）` 在换渠道后仍写 OpenDesign。改为按实际渠道显示。
- **opencode-go 凭证来源**：`auth.json` 里那份 key 已过期（HTTP 401），opencode 桌面版把有效凭证存在自己的 SQLite 库里。已改为从凭证库读当前 active 的那一份（`cred_15208b2e…`）。

## 关键教训

「渠道切换是否生效」这种问题，**界面必须能自证**。只让后端正确、前端不显示，用户就只能靠猜——这是真 bug，不是误解。
