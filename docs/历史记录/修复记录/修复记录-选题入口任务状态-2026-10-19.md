# 选题入口任务状态修复

## 本次故障证据

`projects/调研一下这个开源项目在视-1019/out/.vh-chat.log` 记录：19:04:35 以 `topic` 模式启动，约两秒后 CommandCode 返回额度不足（HTTP 400），模型调用失败，进程退出 1。不是根本没有派发，也未进入实际调研；没有已识别的备用渠道接替。

网页把进程创建当作「开工了」，没有可靠展示最终错误。检查与真实入口回归另外发现：首页第一次没有运行中的任务时提前返回，跳过下一轮轮询；项目内提交还存在 ES module 下给未声明变量赋值的问题。此前测试没有覆盖从「我只有一个想法」到后台退出再回传页面的完整链路，这是开发验证遗漏，不能只归因于渠道余额。

## 修复内容

- `lib/task-status.mjs`：项目级任务身份与持久结果；保留完整原始输入，分类展示失败原因；读取旧日志和旧材料；旧任务回调按身份过滤。
- `lib/server.mjs`：新建、提交、状态、取消、手动重试接入持久状态，移除全局聊天运行标记；捕获子进程启动失败。重试接口拒绝无效项目，不回退到默认项目。凭证检查明确只检查配置，不承诺余额。
- `vh.mjs`：CLI 写入启动与最终结果，保留失败及取消状态；修复 `ask` 选项被拼进用户指令的问题。网页原始输入通过任务文件传递，避免长文章塞进 argv。
- `www/index.html`：无任务时也继续轮询；卡片与首页横幅展示最终失败和手动重试，不再把派发成功当作制作成功。
- `www/player.html`、`www/panel.js`：展示失败、保留提交失败的输入、提供手动重试；修复提交时报未声明变量错误；等长日志尾部变化也更新。
- 工作台重启时发现原端口探测把浏览器已关闭的客户端连接误判为服务占用；`preview` 现仅检查 TCP LISTEN，不再因这些残留连接误换端口。

## 验证

`node --test test/topic-entry.test.mjs`：7/7 通过。

1. 无界面、静音浏览器点击选题入口 → HTTP API → 真实 CLI 子进程 → 本地模拟模型返回工具调用 → 项目中实际写入证明文件 → 模拟渠道额度失败 → 页面显示原因；刷新不重试，点击后新任务执行。
2. 没凭证时不假报开工，保留材料并显示原因。
3. 进程无法启动时留下失败结果。
4. 工作台提交失败不报未声明变量错误，保留输入。
5. 旧日志错误识别、项目状态隔离和旧任务回调过滤。
6. HTTP 层 A 运行不影响 B，重新创建服务后仍显示失败，无效项目不重试默认项目。
7. 日志尾部等长替换仍刷新。

`node --test test/*.test.mjs`：298 项，297 通过，1 失败，0 跳过。唯一失败仍为旧 film 集成测试依赖已不存在的 `projects/comet/gen.mjs`，未重建或删除用户项目来掩盖此失败。

## 边界

- 测试不调用付费模型，不重跑真实选题，不改渠道凭证，不自动弹出页面。
- 额度不足尚未解决；本次修复使失败可见、可追踪、可手动重试，未证明真实渠道已恢复，也未证明自动调研成片质量。
- 手动重试是带原始输入开启新任务，可看到已有项目文件与记忆；不是精确检查点续跑，可能重新执行步骤。
- 已有的「Agent 回答完成但缺产物」完成契约问题不在本次范围；UI 明示结束不代表发布验收通过。
- 原始输入、原项目、原片及字幕修正版均保留；未部署或发布。
