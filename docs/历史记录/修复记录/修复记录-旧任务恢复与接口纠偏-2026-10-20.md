# 旧任务恢复、场景空转与接口错误纠偏

## 本轮修复

- 恢复旧任务直接复用历史 system，因此历史提示可能没有新增分场工具说明。现将当前工具说明、最小引擎接口与下一场脚本文案放进请求尾部；不改写原 system、原文或历史工具结果。
- 场景编写阶段原来仍按通用 60 轮未推进后提醒，不能及时阻止“反复猜接口”。现在，连续四轮读取而没有产出后，下一轮定向调用 `write_scene` 保存当前一场，每场至多一次。仅全流程任务、有效且无基线冲突的脚本/草稿启用；单点编辑、用户新补充/插话及未知命令副作用不启用。接口明确不支持定向调用时，仅回退一次自动工具选择。
- HTTP 200 中的 API error 过去只给笼统类别。现在保存固定安全子类：上下文超限、工具生成/参数错误、消息配对错误、内容策略、输出额度参数限制、定向调用不支持、未知。原始响应、任意上游错误码、原稿及凭证不进入诊断。
- 明确上下文超限且能缩小时，同渠道将较早历史进一步折叠后纠偏一次；原文、用户补充、最新工具批次与配对、签名/加密内容仍保留。缩不动、第二次失败或未知错误不盲重试。
- 接口明确报告工具参数生成失败，或完整响应中的参数不是合法 JSON 时，整批工具不执行，要求一个更小的完整调用。再次失败则暂停；中间只读不能重置这个预算，真实产物推进或用户明确新指令才可重置。预算保存在检查点，不能靠恢复无限刷新。

## 验证

新文件 `test/api-scene-recovery.test.mjs` 的 11 个测试通过，覆盖：

- HTTP 200/400 分类与诊断脱敏；
- 上下文压缩纠偏、不可压缩及重复失败的停止边界；
- 原文/补充要求/工具配对不丢，完整历史不改；
- 未知、内容策略等错误不盲重试；
- 定向工具协议与不支持时的单次回退；
- 旧检查点恢复、四轮只读后调度、下一场切换；
- 用户新要求与草稿冲突保护；
- 工具参数纠偏、只读不刷新预算及跨恢复有界停止。

全量 `node --test test/*.test.mjs`：464 项，463 通过，1 失败。唯一失败仍为既有 `test/film-integration.test.mjs` 依赖缺失的 `projects/comet/gen.mjs`；未跳过或掩盖该失败。

## 用户任务与生效边界

本轮没有调用真实模型、没有重启或续跑用户任务，没有修改用户原稿、场景或检查点。用户自己启动的第六次执行仍使用启动时加载的代码；观察时十场草稿均已落盘，但这不等于成片验收通过。

新逻辑对下一次启动或恢复生效，不热替换正在运行的制作进程。历史那条 API error 的原始内容未保留，不能倒推其必定是上下文超限；新增诊断用于以后准确区分。
