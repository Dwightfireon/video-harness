# 请求诊断、上下文缩减与有限重试

> 后续纠正：下面最初版本把 192 KiB 当成硬预算，导致用户第 6 次执行在约 0.09 秒内被本地拦截，API 请求次数为 0。这是工作台引入的新缺陷，不是 OpenDesign 故障。当前已改成软目标，并增加完整历史工具轮次折叠；必要内容超目标也继续发送。详见 `修复记录-移除上下文硬中断-2026-10-19.md`，下文「超预算本地拒绝」等旧规则不再生效。

## 范围

针对「只剩网络失败、不知道责任在哪」「长任务反复发送臃肿历史」修复工作台自身的请求链路。不切换模型渠道，不改凭证，不自动重跑真实任务，不把模拟测试当成外部渠道稳定性证明。

## 改动

### 1. 安全诊断

- 保留实际 HTTP 状态、等待响应头／接收响应体／解析阶段、耗时、已接收字节及白名单底层错误码。
- 递归提取 `cause` 和 `AggregateError.errors` 中的安全错误码，例如 `ECONNRESET`、`UND_ERR_SOCKET`、`ENOTFOUND`。异常正文、URL、堆栈、请求头和响应正文不进入诊断记录。
- 区分本机计时器、HTTP 错误、HTTP 200 内的接口 error、协议解析、本机配置和传输错误。无足够证据则标记 `unclassified`，不假装已经定位到网络或上游。
- HTTP 200 内的接口 error 保留真实 HTTP 200，显式的 API 状态另记，不再伪造 HTTP 400/503。
- 诊断写入任务失败记录并在日志中展示。旧日志已抹掉的原因无法追溯恢复。

### 2. 请求上下文投影

- 完整模型消息与工具结果继续保存在原检查点；只为网络请求创建独立投影，不改写源记录。
- 较早的纯文本推理和已知明文 `reasoning_details` 不再反复发送；最近助手轮次，以及签名、加密和未知类型推理信息保留。
- 消息超过 192 KiB 时逐级节选旧工具长输出，保留状态线、头尾与「已省略不等于未执行」说明。通常保留最近六个助手轮次的完整工具输出，仍过大则继续节选较近输出，但最新轮次不节选。
- 原始要求、全部用户补充、系统约束、工具参数和调用／结果配对不删除。不可安全缩减的必要内容仍超预算时本地暂停，不把超大请求盲发出去。
- 这是 UTF-8 消息字节预算，不是模型 token 数，也不是另一次调用模型做摘要。
- 对当前真实检查点做过只读测量：消息约 683,326 字节缩为 153,135 字节（减少约 78%），当次检查点未变。后续任务进展会使数值变化。

### 3. 有限重试

- 仍仅使用选定的 OpenDesign，不调用 CommandCode。
- 超时、已识别临时传输错误、HTTP 500/502/503 可重试当前模型请求一次；整个逻辑请求最多两次访问，不因第二次换了错误类型再延长。
- 默认等 1 秒，尊重服务端更长的 `Retry-After`；要求等待超过 30 秒则暂停。等待期间可取消。
- 额度、认证、限流、证书、域名不存在、连接被拒绝、不明网络或协议错误不盲目重试。取消不重试。
- 重试使用同一份投影，完整流式响应结束前不执行工具。已完成工具不由请求重试器重放。
- 传输失败不意味着上游没计算，重调可能产生第二次模型计费；不承诺上游请求 exactly-once。

- 大历史按预算缩减、原文与补充要求不丢、工具配对不坏、最近结果不丢、原始记录不变；
- 签名／加密保留、超预算本地拒绝、重试投影一致、大检查点恢复不重放工具；
- 错误码白名单及嵌套原因、隐私保护、不同网络错误的重试策略、HTTP 状态与任务持久化；
- 真实本地流被切断后记录接收阶段，半截工具不能执行，同渠道重试只执行一次完整工具；
- 超长 Retry-After 暂停、配置与解析错误不误重试、HTTP 200 接口错误不伪造状态。
