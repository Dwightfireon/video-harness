# 中断任务继续执行

## 确认的问题

此前“生成”和“手动重试”都会调用 `beginTask`，生成新任务 ID、覆盖当前任务记录和日志；Agent 每次重建消息数组，只读简短记忆。进入“指挥”还默认选 article 模式。它是同目录的新一轮执行，不是真正的检查点续跑。

## 当前行为

- 中断后默认“继续原任务”；原任务 ID、完整原始要求、原模式保留。每次启动另记 `attemptId`，阻止上一次执行的退出回调覆盖本次状态。
- 新的任务执行过程持续保存完整消息、工具计划、工具结果、已应用补充指令和循环状态。重启工作台后仍可读出。
- 结果已记录的工具由执行器跳过；一批工具中尚未开始的项可接着执行。若用户恢复时有新要求，旧计划未开始项先标记未执行，接收新要求后重新规划。
- 工具执行中被杀、结果没存下时，不盲目重放：写文件先只读比对，内容一致则确认；不一致则不覆盖。未知命令保留未确认状态，同一命令自动重放被拦住。
- 长命令的子进程 PID 有记录；父进程死了、子进程还活着时禁止重复派发，可以等待或取消。
- 旧任务无检查点时明确“按文件接续”，只用保留的目标和现有材料／产物引导核对；检查点损坏则报错，不静默降级从头制作。
- 新一轮任务是单独确认入口，旧任务记录、日志与检查点保留。它仍使用当前项目；独立新项目从首页创建。
- 明确指定的无效／已移走项目返回 404，不能回退到另一个项目生成、继续或取消。
- 检查点位于 `out/.vh-tasks/<id>/checkpoint.json`，权限 600；工作台不提供私有状态目录的静态下载，不把渠道密钥写入检查点。

## 验证

新增 `test/task-resume.test.mjs`，13 项全部通过，覆盖：

1. 工具执行后请求失败，完整工具历史恢复，文件不重写，渠道密钥不进入检查点。
2. 同批工具部分完成时仅接续尚未开始的项，消息链配对。
3. 副作用未知的命令不自动重放，同命令再次请求也被拦住。
4. 写入结果未落盘时只读比对，保留用户后改内容。
5. 损坏检查点及改变原任务模式被拒绝。
6. 原任务 ID 保留，旧 attempt 回调失效。
7. 无检查点的旧任务带明确降级说明与文件清单。
8. 补充要求优先于未开始的旧工具计划，之后仍可执行新计划。
9. 补充要求在进程启动失败后保留，继续时不重复注入已应用要求。
10. 真实 CLI 子进程在模型请求中被 SIGKILL，工作台重建后恢复同一任务，不重复成功写入。
11. 工具运行中只杀父进程；子进程存活时禁止继续，结束后不重放未知命令。
12. 无界面浏览器点击主按钮留空继续、恢复 topic 模式；单独确认新任务才换 ID 并归档。
13. 私有状态不可下载，无效项目不能误操作默认项目。

原选题入口测试同步改为检查“同一任务 ID、不同执行 ID、保留工具结果与文件修改时间”。测试全部使用本地模拟模型，未调用付费服务。

全量测试：314 项，313 通过，1 项旧失败仍因 `projects/comet/gen.mjs` 缺失；未重建、恢复或删除用户项目来掩盖该失败。

## 明确限制

- 这是显式点击继续，不是无限自动重试或后台自动重启调度器。
- 不能追溯找回修复前已经丢失的完整对话；也不擅自恢复回收站项目。
- 检查点解决执行器的恢复和不盲目重放，不保证所有外部副作用 exactly-once。模型仍可能提出新的修改或等价的不同命令；原有工具权限边界问题不能由检查点替代解决。
- 完成契约、版本选择与发布安全仍是独立问题；恢复成功不等于视频已完成或通过视听验收。
- 工作目录不是 Git 仓库，本轮未发布、部署或提交代码。
