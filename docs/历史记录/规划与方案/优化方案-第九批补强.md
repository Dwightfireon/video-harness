## 二、最值得说的：`vh verify` 抓到两处真实算错

`vh concrete` 只能查"有没有换算"，查不出"换算算错了"。而**算错比不算更糟**——观众信了那个体感数字，其实是错的。

于是加了 `vh verify`，它做的事很简单：**把句子里的换算解析出来，真的算一遍。**

第一次跑就抓到：

```
第 5 场：说「3 年」，实际 2.8 年  ✓（在 25% 容差内）
第 9 场：说「一年半」，实际 2.8 年  ✗ 差 46%
   验算：3060 次 ÷ 每天 3 次 = 1020 天 ≈ 2.8 年
```

「一年半」是我上一批自己写错了。改成"飞近三年"后通过。

### 它自己也踩了一个 bug

第一次跑时报告 **16000 次被算成 5.5 年（说 14 年，差 156%）**。查下来是我的中文数字解析把「一万六千」切成了「六千」——`[零一二三四五六七八九十百千两]{1,8}` 碰到"一万六千"时先匹配到了"六千"。

修法：中文数字正则必须包含「万/亿」作为数字的一部分。

**如果没有 `verify`，这个 bug 会一直躺在那里，把所有"14 年"都误判成算错。**

## 四、顺手修的 3 个检查器 bug

| bug | 表现 | 根因 |
|---|---|---|
| **注释影响版式分类** | S5 明明是"事件表"，被判成"流程步骤" | 分类器把代码里的 `/* 属性 → 说明 */` 注释也算进去了 |
| **中文换算单位太窄** | "相当于三个埃菲尔铁塔"不算换算 | 单位表里只有时间单位（天/年/小时） |
| **英尺解析切错** | "三万七千英尺"算成 2.1 公里（实际 11.1） | 正则先匹配到"七千" |

## 七、仍然存在的局限（诚实记录）

1. **`verify` 只能验三类换算**：次数→年、英尺→公里、小时→天。"游泳池""埃菲尔铁塔"这类只能人核。
2. **`reflect` 判"回望"靠词表**：作者可以用"换句话说"开头却没真的回望。它只能查形式和指向，查不出"这句判断对不对"。
3. **`hook` 的 10 分制是启发式**：四项都满也可能不好看（比如四句都很硬、没有呼吸）。
4. **`arc` 的"回应冲突"靠关键词重叠**：重叠 2 个词就算接住，可能接得很浅。
