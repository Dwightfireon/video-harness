# 长视频可靠性优化实施记录

## 本轮结果

已实施核心闭环修复，未替用户续跑真实模型或视频制作任务。原稿、已有草稿、缓存和检查点未被本轮优化流程覆盖；现场期间其他执行产生的新修改保留。

### 1. 统一状态与完成标准

- `lib/artifact-status.mjs` 共用于状态快照和最终交付检查，CLI 成功渲染、混流后登记输入与媒体指纹。
- 缺基线、同长度旧画面、无真实音轨、损坏媒体、运行中被改输入，都不能用“文件存在”或“时长相同”认证通过。
- 精确匹配凭证允许相同内容重写，避免只因时间戳变化失效；重复有效测量不再抹掉渲染/配音基线。
- 默认整片交付必须为当前版本的 `out/video-voice.mp4`；单点编辑对话结束不等同整片交付。

### 2. 给已有十场项目提供修改路径

- 新增短片段编辑和按场读取/替换，完整文件 SHA-256 校验冲突，原字节备份和原子保存。
- 无须依赖旧初稿草稿清单继续有效，也不用整片重写。
- 明确修改要求持久化；宽泛脱敏先登记具体清单，再逐项编辑、核验。机械核验绑定当前作者版本，后续改动使旧核验失效。
- 新替换要求可取代对应旧要求；替换结果包含原词的正常改稿不误判。

### 3. 阶段推进与中断恢复

- 从待修改要求及实际产物推导小任务；固定阶段工具不走 shell 管道，保留完整日志与真实退出码。
- 每次执行的同一小步骤最多 12 轮未推进即暂停，明确恢复可获得新一轮机会，历史计数保留。
- 截断后定向小任务、缩小请求历史投影，不无限提高预算。输出预算支持显式配置。
- 请求/工具批次以及最终回复期间收到新插话，都不能被旧写入或旧“完成”跨过。
- 只在选定渠道进行有证据、有限的临时故障重试，不切渠道、不重放已完成工具；与上下文/工具回退共用请求次数上限。

### 4. 退出码和执行范围

- 通用 shell 开启 pipefail，前段失败不再被 tail 隐藏。
- 受限编辑模式拒绝通过任意解释器或嵌套项目 status 执行脚本；写文件拒绝符号链接路径。
- 标准生成器的作者长注释不再挤掉布局元数据；测试不再依赖缺失的用户演示项目。
- **不是 OS 沙箱**：article/topic/普通 edit 的通用 run、固定阶段启动的工程脚本仍是可信代码执行入口。

## 验证

最终命令：`node --test test/*.test.mjs`

**629 项通过，0 失败，0 跳过。**

其中包括：

- 片段冲突、原子备份、按场保留、无效代码拒绝。
- 同渠道临时断线、取消等待、永久错误、显式预算。
- 真实 ffmpeg 媒体、音轨、时长和内容指纹检查。
- 十场已有工程的截断 → 短补丁/单场脱敏 → 核验 → 实际 CLI 阶段 → 完成检查。
- 最终回复期间插话、运行中改输入、受限模式绕过、恢复后计数、管道吞错回归。

十场集成测试使用模拟模型、合成色块视频和正弦音轨替身验证控制链路，**不等于真实模型创作、浏览器渲染画面和 Kokoro 旁白的端到端质量验收**。脱敏词表机械检查也不能证明全部敏感语义均已消除。
