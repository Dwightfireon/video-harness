# 成熟度缺口分析（第四批）

分析：2026-10-18　依据：10 天内 35 个真实 bug 的分布 + 当前代码/测试盘点
原则：只列**能落成命令或测试**的缺口。

---

## 一、真实数据（先看分布，再谈缺口）

| 类别 | 数量 | 谁发现的 |
|---|---|---|
| 内容/版式（挤压、抄旁白、广告场豁免） | 8 | 6 自动（layout/screen）+ 2 人工 |
| agent/指挥（空响应、越界写、无记忆、无插话） | 6 | 4 自动（tests）+ 2 人工 |
| **页面/UI（textarea 抢键、标签串页、iframe 缩放、状态不刷新、转圈）** | **7** | **0 自动，全部人工** |
| 工程（timing 过期、闸门、端口、码率、存储） | 9 | 5 自动 + 4 人工 |
| 内容可信（claims 没人核） | 1 | 0（补了 vh claims） |

**结论：页面层是唯一"零自动防护"的区域，且 7 个 UI bug 全部靠你肉眼发现。**

## 二、四个缺口（按"会不会反复坑人"排序）

### 缺口 1：**页面没有自动化测试**（最痛，7 个 bug 全在这）
`www/` 865 行、6 类交互（播放/拖拽/切标签/上传/插话/重载），**零测试**。
每个 UI bug 都表现为"你觉得不对 → 我看代码 → 找到 → 修"，一轮 20 分钟起。

**可做**：`test/ui.test.mjs`（Playwright 起服务、点真实控件）
- 输入框能打空格/中文/方向键（今天这 bug）
- 切 5 个标签，只有目标 tab 可见（串页 bug）
- 播放后 currentTime 连续前进、`<video>` 元素不被重建（转圈 bug）
- iframe 按 16:9 完整显示（缩放 bug）
- 运行中发指令 → 队列 +1，不报错（插话）

### 缺口 2：**没有"改前/改后"的可视对比**（改稿靠记忆）
`vh diff` 只报"改了几行"，看不见"画面变成什么样"。
你今天说"再压短一点"时，只能等它跑完再看。

**可做**：`vh compare` —— 改稿前后各抽 N 帧并排成图（一张 PNG），一眼看出哪几场变了。

### 缺口 3：**竖屏成片缺失**（小红书/抖音发不了）
`vh cover` 只给竖屏封面，成片仍是 16:9 裁切。
平台清单里写着"竖屏要重排"，但工具没有。

**可做**：`vh portrait` —— 按 9:16 重排（不是裁切）：字号放大、行宽收窄、每屏信息量减半。
技术上：换 `PRESET`（引擎已支持）+ 场景用相对坐标。

### 缺口 4：**成本与时长不可见**（跑 20 分钟心里没数）
agent 跑了多少 token、花了多少钱、还要多久——都没有。

**可做**：`vh cost` —— 从日志统计本轮 token/调用数/耗时，页面横幅显示"预计还要 X 分钟"。

## 三、排期（这批全做）

| # | 项 | 验收 |
|---|---|---|
| 1 | `test/ui.test.mjs`（5 类交互） | 5 个今天修过的 UI bug 变成回归；故意改坏能红 |
| 2 | `vh compare` | 改稿前后出对比图；单测覆盖"无变化/有变化" |
| 3 | `vh portrait` | 真实项目出 1080×1920 成片，`screen/layout` 仍过 |
| 4 | `vh cost` | 输出 token/耗时；页面横幅显示进度与预估 |
