# 产品打磨计划（缺口分析 → 开发排期）

分析时间：2026-10-16　分析对象：`video_generation/` 全套 harness（2800 行）
分析依据：实际代码盘点 + 今天一天真实踩到的 15 个 bug + 用户三次反馈（讲不清楚 / 画面不高级 / 视频太短）

---

## 一、当前能力盘点（事实，不是印象）

| 层面 | 已具备 | 证据 |
|---|---|---|
| 制作流水线 | 19 个命令：new/status/build/measure/render/voice/stills/go/preview/enhance/jitter/key/clarity/clean/rm/pack/prune/stop/ask | `vh.mjs` 839 行 |
| 网页工作台 | 索引页（新建+卡片+占地）+ 5 标签播放器（脚本对照/分镜/成片/发布/指挥） | `www/` 774 行 |
| 内容闸门 | 解释质量评估器（术语必解释、依赖闭合、受众基线） | `lib/clarity.mjs` 261 行 |
| 画面手法 | 字符场/粒子/地平线/环绕/镜头表 + 抖动校验 | `assets/fx-block.html` |
| agent 循环 | 自研（读/写/列目录/跑白名单命令/抓网页），模型 deepseek-v4.1-flash | `lib/agent.mjs` 297 行 |
| 交付收拾 | pack / prune / rm / 占地显示 | `vh.mjs` |

**一句话结论**：**"能不能做出来"已经解决；"做得对不对、好不好、稳不稳"没有防线。**

## 二、缺口分析（按严重度排序）

### A. 内容深度——最高优先级，直接对应"视频太短、没讲明白"

| 缺什么 | 现状证据 | 后果 |
|---|---|---|
| **没有信息量/时长预算** | 上一版 6 场 121 秒，每场 3 句短句；没有任何机制约束"每场该讲多少" | 片子像提纲念一遍，观众没得到机制 |
| **没有"展开度"检查** | `clarity` 只查术语与依赖，不查"有没有走查例子/反例/边界" | 讲了结论、没讲过程 |
| **没有审稿落盘** | skill 有 `review.md` 三关，harness 没把它做成可勾选文件 | 每次靠人肉回忆该审什么 |
| **改错了层级没人拦** | 用户说"没讲明白"时，要自己判断是改措辞/改结构/换选题 | 改 5 轮可能都改错层 |

**要做**：`vh depth`（信息量体检：每场字数/机制展开/例子/反例/边界）+ 每场目标时长预算 + `审查.md` 三关模板自动生成 + 反馈分层问句。

### B. 流程可见性——直接对应"不知道下一步做什么"

| 缺什么 | 现状 |
|---|---|
| 阶段状态机 | 有 `status` 的过期判定，但没有"我进行到第几步/还差什么"的**项目进度视图** |
| 单项目总览页 | 工作台 5 个标签是**分散视图**，不是流程 |
| 中断点提示 | agent 停下来问问题时（如"繁简/要不要点名"），页面只显示日志，没有"待你决定"的显式卡片 |
| 成本可见 | agent 循环没有 token/耗时统计 |

**要做**：项目**阶段条**（素材→判断→方案→脚本→画面→出片→发布→清理）+ 待决策卡片 + 每步"继续"按钮 + 本轮耗时/调用统计。

### C. 工程可靠性——今天 15 个 bug 都出在这里

| 缺口 | 证据 |
|---|---|
| **零测试** | 没有任何 harness 自己的测试；skill 有 selftest，harness 全靠手测 |
| **状态分散无 schema** | `out/.vh-state.json` + `timing.json` + `PROJECT.json` + `.vh-chat.log`，字段随意增删、无版本号 |
| **正则解析 scene.html** | 场景区间/SUBS/DURATION 全靠正则（今天踩过 parser 的 `$`/`\Z` 两个坑） |
| **内存单例** | `chatProc`/`stillsBusy` 在 server 内存里：重启即丢、多项目并行会互相顶掉 |
| **空 catch 吞错** | 12 处，失败静默 |
| **长任务无进度/超时/重试** | agent 跑 252 秒期间页面只能等；渲染失败无恢复路径 |
| **无版本回滚** | 改了 `脚本.md`/`scenes.src.js` 无法一键回到上一版（内容创作必须有 diff/undo） |
| **端口冲突无兜底** | 只有"检测+复用 8144"，没有自动换端口 |

**要做**：harness 自测套件 + 状态文件加 schema 版本与迁移 + 解析改从生成器元数据取（不啃 HTML）+ 长任务进度/超时/重试 + 项目快照与回滚（`vh snap` / `vh undo`）+ 错误不吞。

### D. 画面与发布——"不高级"与"发不出去"

| 缺口 | 说明 |
|---|---|
| **镜头编排没落地** | `cameraShot` 写好了却没用；promo-film 的"一镜到底"未实现 |
| **真实素材接入缺失** | guizang 的核心是"真实组件/截图+标注"，我们全是重画示意 |
| **视觉多样性检查** | 相邻场是否同构图、手法是否重复，没有自动检查 |
| **发布物料不全** | 缺封面（3:4 / 4:3 / 16:9）、竖屏 9:16 重排、多平台版本清单 |
| **无素材溯源台账** | 用到的图/引用没有统一记录 |

**要做**：`vh cover`（封面三比例）+ `vh portrait`（竖屏重排）+ 视觉多样性检查 + 镜头编排模板 + 素材台账。

## 三、开发排期建议

### 第一期：内容深度 + 流程可见（解决"讲不明白""不知道要干嘛"）
1. `vh depth`：每场字数/机制展开/例子/反例/边界体检；缺项给**具体补写建议**（不是打分）
2. 时长预算：`方案.md` 写目标时长 → 脚本每场有目标句数与字数下限，`build` 时核对
3. `审查.md` 三关模板自动生成（开场审稿 / 概念台阶审稿 / 事实与承诺审稿），带勾选
4. 反馈分层：`vh ask` 收到"没讲明白"时先问一句「改措辞 / 改结构 / 换选题」
5. 项目**阶段条**（工作台顶部）+ **待决策卡片**（agent 停下来问的问题集中显示）

### 第二期：发布链路（"发不出去"）
6. `vh cover`：三比例封面（复用片内真实静帧 + 封面文案.md）
7. `vh portrait`：9:16 重排（不是裁切——重排文案与构图）
8. 平台清单：B站/小红书/YouTube 各自要什么（画幅/时长/封面/文案），`vh publish` 一次列全
9. 素材台账：`素材.md`（来源/许可/用途）

### 第三期：工程可靠性（让它能长期用）
10. harness 自测：状态机、解析、增量渲染守卫、删除/清理、路径安全（正反例）
11. 状态 schema + 迁移；解析改从生成器元数据取
12. 长任务：进度事件、超时、重试、失败后可续跑
13. `vh snap` / `vh undo`：项目快照与回滚（内容创作刚需）
14. 错误不吞：所有 catch 要么记录要么上报

### 第四期：画面再上一档（"不够高级"）
15. 镜头编排（一镜到底 + 推拉摇）落到模板
16. 真实素材接入（截图 + 标注，替代重画示意）
17. 视觉多样性检查（相邻场同构警告、手法重复警告）

---

## 四、判断标准（每期做完怎么算过）

- 第一期：拿同一份素材重做一支，**时长 ≥ 3.5 分钟**且 `vh depth` 零缺项；用户看一遍说"讲明白了"
- 第二期：**一条命令产出可直接投稿的全套物料**（成片 + 封面 + 竖屏 + 标题简介）
- 第三期：跑通自测套件；**连续做 3 支片子不出现"必须手动查代码才能定位"的问题**
- 第四期：相邻两支片子的画面手法不重复，且至少一场用真实素材 + 标注
