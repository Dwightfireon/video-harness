## 二、四个真缺口（按"会不会直接坑到用户"排序）

### 缺口 1：**事实登记了，但没人核**（最严重）

`claims.json` 里每条断言都写了来源和口径，但**六个检查器没有一个读它**：

```
grep claims lib/clarity.mjs lib/depth.mjs lib/screen-check.mjs lib/layout-check.mjs lib/score.mjs
→ 无结果
```

后果：脚本里写"27%"、claims 里登记"73%"，机器不会发现；claims 里登记的断言，脚本里没引用，也没人发现。
**这是"内容可信"的根**，而现在它是一张没人看的表。

**可做的**：`vh claims` ——
- 抽脚本里所有数字（含"约/倍/成/百分点"），逐条查 claims 是否登记
- 未登记 → 报「这个数字没有出处」
- claims 里登记但脚本没用到 → 报「登记了但没用上」
- 检查 claims 每条是否有 `url/kind/scope`（缺字段 → 报）

### 缺口 2：**布局靠手算坐标**（今天踩了两次）

今天两次文本挤压（`wrap` 高 108 装 38px 标题、`kicker` 硬编码 y 撞 footer），根因都是
**场景代码手写 `abs(el, x, y, w, h)`**。检查器只能事后抓，修一次要 4 轮。

**可做的**：`VH_UI.stack(root, {x, y, w, itemH, gap, items})` ——
声明式排布：给一组"标题 + 说明"，自动算每个元素的高度与间距，**不可能挤压**。
场景里改用它，`vh layout` 的数字类错误从源头消失。

### 缺口 3：**发布物料只有成片**（你发了 5 支片子，全是手工截图）

`vh pack` 只会带上"如果已存在"的 `out/cover.png`，**没有生成能力**；
竖屏 9:16、平台清单都没有。你每次发布都要自己截封面。

**可做的**：
- `vh cover`：按 `发布文案.md` 的封面文案，生成 **16:9 / 4:3 / 3:4** 三张（从成片抽帧 + 叠字，确定性渲染）
- `references/publish.md`：B 站 / 小红书 / YouTube 各自要什么（画幅、时长、封面比例、文案位）

### 缺口 4：**流程摩擦**（你今天踩到的）

| 摩擦 | 现在要做的 |
|---|---|
| 改稿后 `timing.json` 过期，`voice` 报错 | 手动 `measure` |
| 渲染闸门要 `审查.md`，没填就拒绝渲染 | 手动 `review-init` + 勾选 |
| 不知道环境缺什么 | 自己去试 |

**可做的**：
- `vh go` 检测到 timing 过期 → **自动** `build --estimate` + `measure`（并在输出里说明）
- `vh doctor`：一次检查 node / ffmpeg / playwright / TTS / 项目完整性 / 产物过期
- `vh status` 增加「下一步命令」的可复制行
