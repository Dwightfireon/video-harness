# 任务反复中断：修复实施记录

## 修复目标

上一轮定位到的最新根因是：核验阶段只靠模型自觉执行，模型持续查内部证据、重复登记清单，12 轮后主动暂停；点击继续只重复同样的循环。本轮按这个根因改代码，并补上遗漏的用户插话。

本轮没有启动真实模型或视频制作，没有改动任何正在运行任务的现场，没有重启工作台。

## 改动

### 1. 核验由程序直接完成

公开交付文件（`脚本.md`、`scenes.src.js`、`发布文案.md`）已经不含已登记禁止词时，执行器不再发模型请求等它“想起来核验”，而是直接做机械核验、记录结果并进入下一阶段。

机械核验只证明登记词无残留，不证明语义与画面正确；该边界仍写进结果和界面提示。

### 2. 脱敏范围统一

- 脱敏约束公开发布内容；`方案.md`、`claims.json` 是内部证据，不为脱敏反复搜索或改写。
- 脱敏任务中读取内部证据会被拒绝，并说明原因；公开脚本仍保留登记词时不会误判已清。
- 公开范围核验之后补写内部证据不会让已完成核验失效；公开文件再改仍会失效。
- 单独登记语义要求（例如“保留重点、不放小游戏”）时，机械核验后标为**待人工复核**，不冒充机器已证明内容取舍正确。

### 3. 确定性阶段不再被模型拖住

build / measure / render / voice / validate 连续两轮没有执行规定动作时，执行器按固定参数代跑一次：

- 用同一 `run_stage`、固定 argv，不走 shell 管道。
- 成功会真实推进产物，并继续下一阶段。
- 失败保留完整日志和真实退出码；**同一阶段失败后不原样重跑**，停在准确报错，等修文件。
- 不把“代跑成功”当作内容或画面验收。

### 4. 插话不再丢失

“保留重点 和精华 至于什么小游戏 没必要放进去”这类要求现在会进入检查点，形成可追踪的编辑要求，而不是只留在聊天记录里。

### 5. 其他一致性修复

- 单次执行耗尽步数时统一记为 `paused`，不再落到不可恢复的 `incomplete` 分支。
- 程序代跑和拒绝动作前会补齐工具结果，检查点不会留下孤立的工具调用。
- 阶段限流只降级为提示/代跑，不再把合法的编辑、修复命令一并拦死。

- “不放小游戏”会形成可追踪要求，并标记语义待人工复核。
- 确定性阶段偏离时快速代跑或停在真实失败，不再无意义耗尽轮次。
