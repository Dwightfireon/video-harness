# 第六批缺口分析：harness + 画面

分析：2026-10-18　依据：5 支片子的实际画面 + 39 命令 / 76 测试盘点
原则：只列能落成命令、测试或模板的缺口。

---

## 一、画面层：**能力有，但没人用**（最核心）

引擎里已经有 21 个视觉助手，实际使用情况：

| 助手 | 能力 | 实际用了 |
|---|---|---|
| `oneTake`（一镜到底 + 镜头表） | 推拉摇、文案交接、越界钳制 | **1 次（我手写演示）** |
| `stack`（声明式排布） | 自动算高度，不可能挤压 | **1 次（我手写演示）** |
| `windowMock + codeLine` | 重画窗口/终端/文件树 | 2 次 |
| `glyphField / streaks / horizon` | 字符场 / 粒子 / 地平线 | 5 次（只当背景） |
| `beats`（文案交接） | 按时间淡入淡出 | 1 次 |

**agent 提示里只提了 1 次这些助手。** 结果就是：**每支片子都是"标题 + 列表 + 条形"**——能力在仓库里躺着。

这是画面不高级的**第一原因**，不是审美问题，是"工具没被用"。

**可做**：
- `vh scene --new <配方>`：从模板库生成一场可运行场景（不是空文件）
- 5 个**可直接用**的版式配方（每条含代码骨架 + 使用条件）：
  1. `hero-statement` 大字 + 一句
  2. `compare-bars` 条形对比 + 来源
  3. `process-steps` 三步流程 + 箭头
  4. `window-walkthrough` 窗口 + 代码行（真实界面感）
  5. `one-take-layers` 一镜到底（同一主体多层推进）
- agent 提示里**每个配方给一行调用示例**，而不是只报名字

## 二、画面层：**版式重复没人查**

5 支片子里有 3 支是「标题 + 若干行列表」占了 60% 以上场次。观众会觉得"平"。
现有检查器：`screen`（具体对象）、`layout`（挤压/越界）、`pacing`（长停）——**都不查"版式是否雷同"**。

**可做**：`vh variety`
- 按场景代码特征归类版式（有 windowMock / 有条形 / 有列表 / 大字 / 一镜到底）
- 相邻场版式相同 → 提示
- 全片只用 2 种版式 → 警告
- 输出一张"版式分布"表

## 三、harness：**要求清单只有"抽"，没有"改"**

`vh brief` 能抽 must/mustNot，但：
- 用户中途改主意（"算了还是详细点"）→ 旧要求不会被撤
- 要求冲突（"只给链接" + "加上价格"）→ 不提示

**可做**：`vh brief --amend "<新指令>"` 合并/撤销；冲突检测。

## 四、harness：**交付物没有保护**

昨天 `dist/` 被清空，5 个交付包没了，**没有回收站、没有二次确认**。
（`vh rm` 项目有 `.vh-trash`，`dist --purge` 却是直接删。）

**可做**：
- `dist --purge` 改走回收站
- `dist --prune` 前打印清单 + 要求 `--yes`
- `vh doctor` 提示"dist 有 N 个包、共 X MB"

## 五、画面：**竖屏只是"能出"，没"重排"**

`vh portrait` 能出 1080×1920，但场景坐标按 1920 宽写 → 右边被裁。
`--check` 能报溢出，但**没有重排能力**。

**可做**：让新场景默认用**相对坐标**（按 `window.W` 算），这样横竖屏都能用。模板库直接给这种写法。

| # | 项 | 验收 |
