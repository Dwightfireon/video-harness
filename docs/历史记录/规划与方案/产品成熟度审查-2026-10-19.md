# 产品成熟度审查：以当前代码与真实制作记录为准

日期：2026-10-19。范围：当前工作区的 harness、工作台、已接入的 article-video 管线，以及《人间词话》项目记录。

本轮只分析：新增本报告，未修改产品源码，未重新生成用户视频，未调用付费模型。复现使用隔离临时目录、模拟模型响应；临时夹具已清理。全量测试在独立临时目录内重跑。

## 1. 结论与适用范围

当前是**已经能完成真实长片制作、但仍需要技术人员介入保障交付的本地工作台**。不能再说“尚未有内置 Agent 跑通的长片”，也不能把一支长片产出等同于稳定量产。

本报告把“成熟产品”限定为：个人创作者在受支持的材料、题材和运行环境内，能完成导入、确定要求、审稿、预览、定点修改、导出和再次编辑；失败可解释、可恢复，原始资产不会被默认清理掉。

暂不把账号、计费、团队协作、云渲染、多租户、全平台运行当作必须补齐的缺口。也不要求完全无人审阅。支持边界需要在评测后确立，不能先宣称任意题材通用。

### 成熟度不是一个完成百分比

现有证据不足以计算“一键成功率”“画面及格率”或“距离成熟还差多少百分比”。可以确认的，是下文的具体行为、风险和缺少的证据。

## 2. 证据口径

| 等级 | 含义 | 本报告中的例子 |
|---|---|---|
| A：本轮复现 | 当前代码在隔离夹具中确实出现该行为 | 无视频却 completed、无视频仍打包、换 CRF 被跳过 |
| B：真实记录 | 当前项目文件保留了事件或检查结果，本轮读取核对 | 成片后末次模型请求失败、字幕修复后的243点检查 |
| C：代码风险 | 路径可从代码确认，但本轮未触发破坏性或完整现场测试 | 清理默认删源文件、多项目共享状态、导出仍选旧文件名 |
| D：证据不足 | 尚不能判断能力是否稳定，不判定为已失败 | 跨题材审美稳定性、人工节省时间、冷启动成功率 |

单元测试和模拟模型测试不证明真实模型每次能完成任务；DOM检查不等于编码像素审查；媒体时钟读数接近不等于语音逐字对齐；来源字段不齐不等于事实内容错误。

## 4. 已复现的交付正确性缺陷

### F01：制作任务仍可能在缺关键产物时返回成功【A / P0】

证据：`lib/agent.mjs:317–325、478–487、527–544`。

复现：article模式，明确要求交付配音视频；模拟模型连续回答“没有生成文件，未完成”。系统催促两次后仍返回 `completed / ok:true`，视频不存在，只给“还没有配音成片”警告。

影响：成功状态不能作为后续导出、清理和用户提醒的依据。不能只修模型调用异常退出码；必须定义每类任务的完成条件。

验收：制作任务缺必需产物只能进入未完成/受阻；修改文案任务则不能被错误要求重做全片。产物已生成但最后总结请求失败，应显示“草稿已生成，任务异常结束，可审阅或续跑”。

### F02：打包的“发布门槛”不验证必需交付物【A / P0】

证据：`vh.mjs:2118–2213`。

复现：只有PROJECT.json和写着“需改、未试听、不可发布”的审查文件，没有视频；不加force运行pack，退出0，包内只有交付说明。

准确区分：允许归档不完整工程本身没有问题；问题是当前命令以“发布门槛”呈现，却没有相应保证。

验收：明确区分草稿归档与发布交付。发布交付必须验证选定版本的成片存在、可解码、有必需音轨/字幕、无阻塞审查；草稿包明确标未审，不得混同。

### F03：写权限只约束部分工具，不能形成任务范围隔离【A / P0】

证据：`lib/agent.mjs:83–108、132–170`。

复现：edit-visual模式通过write_file改脚本被拒；通过允许的Node命令写同一个临时脚本却成功。未操作用户脚本。

影响：不是必须有恶意才会发生；模型临时改用命令写文件，就能绕过“只改画面”的承诺。

验收：所有执行路径使用统一的任务权限。优先结构化工具、明确命令及参数；确需运行作者代码时在隔离工作副本中运行，审核改动后提交。仅扩充字符串黑名单不能提供同等保证。

### F04：输入依赖覆盖不完整，模板变化可能不触发更新【A / P1】

证据：`lib/state.mjs:211–229`。生成戳只记录脚本与scenes源码；`vh.mjs`中的genStamp写入也没有模板指纹。

复现：生成戳与画面基线匹配后，只改engine.tpl.html；snapshot不报告scene或render过期。

边界：本次字幕迁移器会额外使genStamp失效，因此不能说“刚修字幕也必然未生效”。缺陷是**通用模板/主题修改**仍缺完整依赖关系。

验收：脚本、场景、模板、引用素材、生成器、渲染参数、音频参数按各自产物建立指纹与失效规则；同路径素材替换也须测试。不要要求任何微小变化都重做整片。

### F05：编码参数变化可能被“画面没变”跳过【A / P1】

证据：`vh.mjs:464–524`。

复现：夹具已有匹配场景的渲染基线，旧参数CRF18；请求CRF21，仍直接“跳过渲染”。未调用真实编码器，此测试验证的是跳过条件错误。

验收：画面没变、编码参数变了时复用帧重新编码；仅音频参数变化时无需重渲画面。缓存键须覆盖实际影响结果的参数。

### F06：文件不存在与“未过期”的判断没有完全对齐【A / P1】

证据：`lib/state.mjs:217–239`。

复现：保留匹配当前HTML的render状态，删除本轮创建的临时video.mp4；snapshot返回无视频，仍没有stale.render。

这不表示全部状态都显示最新；时间轴等其他项仍可能有警告。本轮验证的是render状态漏报，不是每次go都必然漏渲染。

影响：依赖stale字段决定是否渲染的上层流程可能跳过必需步骤。应区分missing、stale、invalid、current，而不只比较状态记录。

验收：删除或损坏产物后能被发现并重建，不能凭“曾经成功的记账”继续报最新。

## 5. 与当前修正版直接相关的产品缺口

### F07：没有贯穿预览、审阅、导出的明确版本身份【B+C / P0】

现在项目同时保留旧 `out/video-voice.mp4` 与新 `out/video-sync-fixed-voice.mp4`。状态里的subtitleRepair记录了修正版路径，但pack仍硬编码拷贝旧的video-voice.mp4，网页主要按文件名和修改时间展示。

这是可以从文件和代码确认的路径问题，**本轮没有对真实项目执行打包，也不声称用户已经导错片**。

同样，publish-done的out清理白名单只保留标准文件名，不包含修正版和其审阅证据。不能让“新文件产生了”替代“当前交付版本被正式选定了”。

验收：有唯一选定的当前版本，绑定脚本、时间轴、音频、视频、字幕和审查。预览、下载、打包必须指向同一版本；旧版可查看、可恢复，但不能靠mtime推断哪个已通过审阅。

### F08：清理策略仍可能删除不可再生资产【C / P0】

证据：`vh.mjs:1056–1095、2269–2297`。

- 单项目prune默认把materials列入删除目标。
- publish-done默认删源文件，且内部强制打包。
- 上述行为未在本轮执行，不能把此前目录变化归因于这些路径。

验收：默认只清可再生缓存；原文、素材、场景输入、用户录音、审阅证据默认保留。永久删除需明确列出对象并确认。归档先验证可恢复性，不只是确认pack退出0。

## 6. 生产质量缺口：不是再加几种动画

### 6.1 创作规则没有形成稳定、可控的制作策略【B+C / P1】

本片方案自定390秒预算，实测584.40秒，约超50%；这是Agent自定预算的失控证据，不等于违反用户明确时长要求。当前也不能仅凭时长长就判断内容差。

系统提示仍有互相牵制的倾向：允许直接说明目标，又要求先抛误解；深度检查建议较多场次、较长句子，其他检查偏好短句。`lib/depth.mjs:86–126`把句数、字数、词表作为展开线索。

缺的是：根据视频类型选择策略，先确定保留/删减什么，再编排口播、字幕与镜头，而不是不断追逐检查器的关键词。

验收：支持的类型有明确目标和示例；时长预算超出时提出可比较的删减方案或请求确认。讲解完整句、字幕显示单元、镜头单元不被强制绑成同一个长度。

### 6.2 画面创作有工具，但没有可靠的视觉反馈环【C+D / P1】

`lib/agent.mjs:109–199`的内置工具仅向模型返回文本。它能执行截图命令，却没有正式的图像输入/视觉审阅通道。

因此可以确认“缺少视觉反馈路径”，不能据此判定每段画面都不好。对于文学解说，引文本身可以是合理主体；不能把“文字多”自动等同于失败，也不能强制装入不相关照片。

需要形成内容到画面的中间计划：对象、变化、触发句、素材、证据或示意性质、观察目的。现有自由JS场景可以保留，但不应让所有常规修改都必须由模型重新拼代码。

验收：关键样片有明确确认环节，必要时由人确认；检查画面是否在解释关系，而非单看像素变化率或版式数。跨文章审美稳定性留到真实评测，不凭一支样片许诺。

### 6.3 音画质量应拆成四类，不能统称“同步通过”【B+C+D / P1】

1. 文本完整性：字幕是否漏字、截断、越界。已补针对性防线。
2. 播放时间一致性：预览是否跟随媒体时钟。已补针对性修复和有限测试。
3. 语音与字幕内容一致性：有没有漏读、错读、替换专名，句子对应的录音是否正确。尚无自动闭环。
4. 镜头与讲述语义一致性：旁白讲第二个例子时，画面是否仍停在第一个例子。尚需分镜与过程审阅。

完整解码不验证3和4；词级强制对齐也不能自动验证事实和审美。短期不必先做逐字字幕；应先保证逐句内容、起止和段落对应正确。

### 6.4 新字幕检查仍有边界【C / P1】

`lib/subtitle-review.mjs`检查实际textContent、CSS可见状态和边界，每句三个时刻。它不能保证中间所有帧都正常，也未检测任意遮挡、低对比或声音内容。报告没有输入指纹，必须防止被后续改稿当成仍然有效的结论。

验收：自动审查结果绑定当前产物；补充发生在动作和字幕切换附近的采样、遮挡/低对比反例。无需在每次草稿修改都执行昂贵的全片逐像素审片。

### 6.5 事实记录与发布契约没有统一【A+C / P1】

当前真实项目有14条claims，本轮harness检查14条均报字段问题；匹配的数字断言数量为0。原因包括生成记录使用claim等字段，检查器期望assertion/scope等字段；数字匹配只覆盖部分书写方式。

**这14处不是14个事实错误。** 本地材料也不应被强迫造一个URL。真正需要支持的是本地材料类型、路径/内容指纹、摘录和位置，以及事实/转引/解释/推算的区别。

验收：生成、检查、审查UI和发布使用同一带版本格式；支持本地与网页来源。关键断言与脚本句子能对应，改稿后相关核证自动待复核；未核事实不被字段齐全洗成verified。

## 7. 任务、工作台、环境与资产缺口

### 7.1 故障轮替不等于任务续跑【B+C / P1】

轮替在同一次运行内保留上下文并重试当前请求。完整对话与执行步骤没有作为可恢复检查点保存；当前摘要最多8轮，进入模型时还截短。CLI每次ask会重写日志。

应先做好单任务：工具成功后有可恢复记录、外部请求失败不抹掉已完成阶段、取消有明确子进程边界、恢复不重复危险步骤。无需现在上多Agent或复杂分布式队列。

### 7.2 项目边界与本地服务安全需要补齐【C / P0/P1】

无效p参数会回退默认项目；清理/删除也共用这项解析。全局chatProc参与不同项目的存活与状态判断。生成页面、上传素材与工作台同源，静态服务面覆盖根目录。上传未设明确体积上限。

这是代码风险，本轮未执行删除接口或恶意页面。优先修错误项目拒绝、项目级任务隔离、静态文件白名单和不可信场景隔离；不需要把本地单人产品扩成企业权限系统。

### 7.3 UI缺的主要是“决策与状态”，不是更多按钮【C+D / P1】

现在能看脚本、分镜和成片，但首页把“检测到凭证”称为“可以全自动”；这未验证端点、TTS、浏览器或质量。缺少统一呈现：当前版本、已完成阶段、阻塞、待用户确认、修改影响范围。

验收：用户能在不读日志的情况下回答“现在看到哪版、哪里没过、下一步做什么”。一次反馈能定位到时间点/句子/画面，并能看改前改后。是否省心必须做真实用户任务测试，不凭界面控件数量判断。

### 7.4 安装与依赖尚不自包含【A/C/D / P1】

package.json没有声明当前实际使用的Playwright依赖，依赖可能从父目录解析；新项目又复制外部skill工具。上一轮修字幕实际遇到浏览器可执行文件缺失。

doctor可以给提示，但其部分判断仅检查目录/可解析性；不能等同于跑通真实渲染与TTS。没有本轮冷机测试，不能声称新机器一定不能安装，也不能声称已验证一键安装。

验收：先明确支持的本机环境；依赖版本与工具来源可追溯；干净环境按文档能跑最小视频。只读体检不应因执行npx而意外下载依赖。

### 7.5 素材接入已有，但不是完整资产管理【C / P1/P2】

assets模块已有收集、尺寸、引用检查，不应说“没有素材能力”。缺的是来源/使用许可、内容指纹、替换影响、有效引用关系、归档恢复。多尺寸入口也存在，但portrait.inspect当前实现仍主要扫描字面量坐标，不能证明响应式计算布局可靠。

先保留稳定横屏范围。竖屏/方屏达到同等质量需要独立验收，不能靠尺寸切换承诺自动重排。

## 8. 根本结构问题与建议边界

当前主要是自由制作Agent调用大量CLI，再靠多个文件和检查器追认结果。这样适合试验，难点是：任务、内容、媒体和审查没有共同的版本身份，检查范围也不总被上层准确理解。

应补齐最小共同契约，而不是立即重写整个渲染器：

| 对象 | 最少应明确的内容 |
|---|---|
| 制作要求 | 目标受众、内容范围、时长约束、画幅、不可改要求；默认值和用户确认分开 |
| 内容版本 | 脚本句子/分镜的稳定身份、来源引用、待核项 |
| 产物版本 | 当前视频/音频/字幕路径、输入指纹、生成参数、可用/过期/损坏状态 |
| 任务记录 | 阶段、成功的工具结果、错误、重试/取消/续跑位置 |
| 审查记录 | 检查范围、当前输入指纹、观察证据、未验证项、阻塞与人工确认 |

这些信息可以先用经过校验、原子写入的本地文件实现，不预设必须引入数据库。现有确定性渲染、增量逻辑、TTS缓存、镜头助手和大部分CLI继续复用。

## 9. 开发优先级与每批验收

### 第一批：交付不会误导用户【P0】

范围：F01/F02/F03/F07/F08，以及错误项目操作保护。

必过场景：
1. 制作任务没有视频不能报完成。
2. 有视频但末次总结请求失败，保留并说明可用产物。
3. 发布导出缺成片/有阻塞/审阅过期，明确拒绝；草稿归档仍可用但不标可发布。
4. 同时有旧片和修正版时，选哪版，预览/下载/打包就对应哪版。
5. 只改画面的任务不能通过其他工具改稿。
6. 清缓存不删除原文、素材和审阅证据；误传项目ID不操作默认项目。

### 第二批：修改与故障恢复可信【P1】

范围：完整依赖、产物存在/有效性检查、状态原子写、任务检查点、参数缓存键、claims格式统一、独立测试夹具。

必过场景：模板变化、素材原路径替换、CRF/FPS变化、删除成片、配音参数变化、重启、请求失败和用户取消。各场景都验证该重做的重做、不该重做的不重做。

### 第三批：降低创作返工【P1】

范围：类型化制作要求、时长预算与删减选择、内容到分镜的中间计划、关键样片确认、音画/来源审阅、时间点反馈。

先对一条受支持的主流程做深：文章解说、横屏、有人工审稿。不要同时承诺任意选题自调研、长短片、多画幅均已稳定。

### 第四批：面向非技术创作者验证【P1/P2】

范围：干净环境安装、阶段式工作台、可定位错误、版本比较、恢复与归档、更多格式。

验收依真实用户完成任务和真实文章集；不是控件齐全或文档写完。后续是否要云端、团队、计费，由实际使用需求决定。

## 10. 应如何衡量，才不再自我感觉良好

先建一个小型固定评测集，覆盖文学解释、机制说明、操作演示、数据比较，以及材料不足/冲突的负例；具体篇数按成本预算决定。生产质量测试与工程反例测试分开。

每篇都走用户真实入口，记录默认模型、输入、参数、版本；继续使用既定DeepSeek，不通过偷偷换模型改变评测条件。模型调用真实费用须另行确认，不在本轮分析里消耗。

| 问题 | 要记录什么 | 避免的误判 |
|---|---|---|
| 能否稳定出草稿 | 有效产物、失败阶段、重试和恢复结果 | 把文件存在当成功 |
| 是否符合要求 | 时长/范围/不可改要求及确认记录 | 把Agent自定预算当用户要求 |
| 是否能看懂 | 目标观众复述核心关系、指出困惑 | 用句数和关键词代替理解 |
| 画面是否有效 | 各关键段提供的额外解释、错误与遮挡 | 用像素变化量代替画面叙事 |
| 音画是否可靠 | 截字、漏读/错读、段落对应、触发时刻 | 用17ms时钟读数证明词级对齐 |
| 是否真正省工 | 人工介入次数、耗时、修改范围 | 人工救场后仍算一键成功 |
| 成本是否可控 | 实际返回的usage、重试数、等待时间；拿不到就标未知 | 编造费用或只数日志行 |

验收阈值应先由试跑建立基线，再与目标用户一起确定。逻辑性安全要求可以立即零容忍；审美、理解率、制作耗时不能凭空设一个漂亮百分比。

## 11. 本轮不下的结论

- 不声称现有画面普遍优秀或普遍不合格；缺跨题材、目标观众与人工视听评测。
- 不把当前14条claims格式疑点说成14个事实错误。
- 不把旧目录缺失归因于某个清理命令；没有因果证据。
- 不把修复后的243点采样说成整片每帧验收。
- 不把291项测试中的290通过换算成产品成功率。
- 不给无依据的开发天数、上线日期或成熟度百分比。

**下一步建议：先确认第一批交付安全与版本契约，再开发。继续增加动效、模板和检查命令，不是当前最高收益的工作。**
