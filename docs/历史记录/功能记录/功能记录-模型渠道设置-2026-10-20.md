# 功能记录 · 网页选择 provider 与模型（2026-10-20）

用户需求：不用每次口头交代"换个模型"，在页面上自己选；并把现有渠道预先保存好。

## 交付

### 设置页

`www/settings.html`，地址 `http://127.0.0.1:8144/settings`。首页与播放器右上角都有「模型：opendesign / deepseek-v4.1-flash」入口。

页面内容：

- **当前使用的渠道**：显示渠道名、地址、模型。
- **可用渠道**：每个渠道一张卡片，含接口地址、密钥状态（已配置 / 缺少密钥，并标明密钥来自哪里）、模型下拉、「用这个渠道」按钮、可改的接口地址。
- **填 API key**：选渠道 → 粘贴 key → 保存；或删除该渠道在页面保存的密钥。

### 命令行等价入口

```bash
node vh.mjs provider                                        # 看当前设置与各渠道状态
node vh.mjs provider --use commandcode                      # 切渠道
node vh.mjs provider --use commandcode --model <模型名>      # 同时换模型
node vh.mjs provider --seed                                 # 把本机现有渠道预先保存
```

### 现有渠道已预先保存好

`~/.config/video-harness/providers.json`（权限 600，项目外）：

| 渠道 | 模型 | 密钥来源 |
|---|---|---|
| OpenDesign | `deepseek-v4.1-flash` | harness 凭证文件（已有） |
| CommandCode | `deepseek/deepseek-v4.1-flash` | opencode 凭证（已有） |
| 9Router（本机路由） | `cmc/deepseek/deepseek-v4-flash` | 缺密钥 |

**密钥没有复制**：仍留在各自原来的位置，页面只是引用来源。设置页新填的才写进该文件。

## 行为约定

- 切换只影响**之后启动**的任务；正在跑的不受影响。
- 切换后**仍不自动切换渠道**：失败时不会悄悄换到另一个渠道重试，暂停后由你决定用哪个继续。
- 缺凭证时不会回退到别的渠道（沿用既有约定）。
- 密钥永不回显：任何读接口只返回 `hasKey` 与 `keySource`。

## 实现要点

### 新增 `lib/provider-settings.mjs`

- `readSettings` / `writeSettings`：本机私有文件读写，权限 600，目录 700。
- `listProviders`：合并 opencode 配置里的 base 与模型清单、现有凭证来源、当前选择。
- `setSelection` / `setProviderKey` / `setProviderBase`：校验后才写。
- `seedExisting`：把现有渠道的默认模型固化进设置文件，密钥不复制。
- `currentSelection`：agent 侧读取当前选择。

### `lib/agent.mjs`

- `buildCandidates` 改为按设置选择渠道与模型，支持设置页里配置的渠道（带自己的 base 与 key）。
- `pickProvider` 尊重设置；渠道的固定别名仍是默认，用户显式自选的模型才覆盖（`modelExplicit`）。
- 显式注入 `providers` 的调用（测试、CLI）不再读本机设置，测试结果不随使用者环境变化。

### `lib/provider-pool.mjs`

- 支持用户自选模型（`validModelName` 校验模型名字符集）。
- 折叠锚点跨轮保存，前缀缓存命中更稳定。

### `lib/server.mjs`

- `GET /_api/providers`、`POST /_api/provider/select`、`POST /_api/provider/key`、`POST /_api/provider/base`。
- `home` 可注入，测试不会写进运行者的真实配置。
- `GET /settings` 返回设置页。

## 过程中发现并修掉的真实缺陷

1. **测试污染真实配置**：接口最初用进程默认 HOME，测试把假密钥写进了 `~/.config/video-harness/providers.json`。已改为注入 `home`，并加了断言"真实配置不能被测试改动"；已清理被写入的假密钥。
2. **`readSettings` 漏掉 `bases` 字段**：自定义地址存进去但读不出来。
3. **模型取成 `"0"`**：`seedExisting` 把模型清单当对象处理，实际是数组。
4. **切换时静默改模型**：`<select>` 没有匹配项时浏览器默认选第一项，导致点"用这个渠道"会把模型换成别的。已让当前模型固定排在选项首位，并以前端数据而非 DOM 选中值为准。
5. **并发改动引入的 ReferenceError**：`lib/request-context.mjs` 引用了未声明的 `stableAnchor`，会让每次模型请求直接抛错。已补上参数与跨轮传递。
6. **超预算的那一轮没被折叠**：单条 `write_file` 参数可达数百 KB，留在保留区等于没裁剪（实测投影 752KB，超预算 4 倍）。已改为整轮不拆、按预算最大化保留区。
7. **加密推理可能被折叠掉**：渠道要求把加密块原样回传，丢了会报 `invalid_messages`。已加保护：切点不能越过带签名/加密推理的消息。

## 限制

- 9Router 是本机路由（`http://localhost:20128/v1`），当前未运行且无密钥；页面上可选，但实际调用会失败。
- 切换不影响正在执行的任务——这是有意的，避免中途换模型导致同一支片前后不一致。
- 只改了"用哪个渠道/模型"；重试策略、失败处理、上下文裁剪逻辑未因本功能改变。
- 未在真实付费模型上验证新选中的渠道（会花钱），只验证到"请求会用所选的 base 与模型名"这一层。
