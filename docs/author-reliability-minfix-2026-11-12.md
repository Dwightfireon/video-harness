# 作者可靠性最小修复：使用与边界

不增加生成阶段、模型调用或制作门禁。Research Pack 仍默认关闭；既有制作命令、媒体缓存和直接检查命令不变。

## 1. 研究摘录

`lib/research-pack.mjs` 只输出原始 `pages[].body` 的连续切片，不推测重复数字，也不删除 LaTeX、链接或排版残留。每条包含记录 SHA-256、原正文 SHA-256、原始 pageIndex 和 UTF-16 字符偏移 `[start,end)`，可用 `body.slice(start,end)` 验证。

这保证的是相对于**本地抓取正文**的逐字完整性，不是网页抓取本身无误，更不是来源事实正确。`2,0502,050`、`52%52\%` 等原文疑似重复也保留，必须另行解释，不能再冒充“清洗后的直接引文”。不安全的截取会跳过并说明；预算仍可省略条目，不需要全文进上下文。

## 2. 可选核心事实锚

在现有 `方案.md` 中添加 `evidence-anchors` JSON 围栏；不另建 claims 文件，不要求每句登记。单个数组最多 16 项。

下面是**格式模板，不是核实过的证据**；将路径、SHA-256 和逐字引文替换为真实原始材料：

````markdown
```evidence-anchors
[
  {
    "id": "independent-steps",
    "source": {
      "path": "research/原文.md",
      "sha256": "替换成原文文件的64位小写SHA-256",
      "quote": "替换成原文内逐字存在的完整证据，保留公式和前提"
    },
    "supports": "作者解释：r是固定单步成功概率，H步在独立假设下全部成功的概率为r^H",
    "conditions": ["独立步骤", "r固定", "示意算例不当实测"],
    "scenes": [3]
  }
]
```
````

获取本地文件哈希：`shasum -a 256 <项目>/research/原文.md`。`supports`、`conditions` 是**作者解释**，不是原文引文，也没有被程序证明成立。

实际 OpenCode runner 在观察到成功的方案/脚本写入或相关 shell 工具事件时，验证文件哈希与引文成员关系，把首次有效 ID 存入既有 `out/.vh-runner.json.authorEvidence`；后续同 ID 的来源、可支持判断和条件不能覆盖它，场号允许随分场调整。`write` 事件有方案全文时优先使用提交快照，不读后来已覆盖的文件；shell/edit 没有全文快照时只能绑定当时看到的磁盘版本，**无法保证还原已错过的首次稿**。没有观察到的写入不会凭空生成历史回执。

`node vh.mjs clarity --dir <项目>` 在现有 `审查-解释.md` 展示原文、作者判断、条件、指定场的编号旁白及最后一场编号旁白。首次绑定未登记时明确说明只对照当前方案，不冒充历史固定依据。

- 可确定：哈希变化、引文不在文件、越界/缺失来源、首次定义被改/删、所指场不存在。
- 必须待核：否定/补集、联合事件、分母与范围、等价公式、变量偷换、相关与因果、操作建议是否被证据支持。
- 正确和错误的自然语言版本均不会自动获语义 pass；写作 Agent 仍需对照原文读正文与结尾。来源表正确不代表正文正确。
- 无锚旧项目为 `not-configured`，不是通过；不强制补锚，不改 Agent/提示词，不自动付费审稿或返修。
- 不防范主动篡改本地会话 JSON，也不能单靠哈希证明文件确实是外部原文而非摘要。应绑定保留的原始材料。

## 3. 可复用作者检查入口

```bash
node vh.mjs author-check --kind script --dir <项目>       # 共享脚本检查器，保留其非零失败状态
node vh.mjs author-check --kind script --show --dir <项目> # 只查看当前版本完整结果，不重新执行
node vh.mjs author-check --kind clarity --dir <项目>      # 现有解释检查器的完整报告
node vh.mjs author-check --kind clarity --show --json --dir <项目>
```

支持 `--terms "…"`、`--skill <共享skill目录>`。入口不执行任意 shell，也不调用模型。缓存为独立的 `out/.vh-author-check.json`，单槽保存最近一组检查；切换 kind 会失效，不碰媒体缓存。失败原样失败，待核原样待核，`exitCode=0` 仍不代表事实/语义正确。

指纹包括稿件/方案、`PROJECT.json`/`vh.config.json`、顶层 `research/*.md` 的名称和内容、锚引用文件及冻结锚、检查器与直接相关本地模块、Node 版本/路径/选项。执行前后不一致不缓存；损坏回执不复用；未知共享检查器版本照常执行但**不缓存**。越界软链接、不明 preload 或磁盘代码已不同于本进程加载代码时也关闭复用。当前共享检查器仅已核对的 `dc6b7f7e…bcbc` 版本可复用；升级后需要重新核对读取依赖，不能只更新哈希白名单。

`--show` 对过期/未知结果报错，不偷偷执行，也不把旧结果展示为当前。缓存命中重放 stdout/stderr，不保证重建已删掉的 `审查-解释.md`。完整结果可先保存再检索，无需为不同 grep 重跑检查器。若自己使用 shell 管道，仍应启用 `pipefail` 并检查退出状态，任意 shell 的内部逻辑不在本入口控制范围内。

**采用限制**：旧的 `check-script.mjs` 和 `vh clarity` 仍按旧路径执行，不会被透明拦截，也没有自动改写历史 Agent 指令。节省检查执行需要显式使用新入口；重复调用入口本身不减少模型工具轮次。

## 4. 工具输出状态

OpenCode runner 对显式失败/非零工具元数据记录失败；shell 输出出现 Python traceback 但外层为 0 时标为**不确定**，不再把该事件当作错误恢复成功证据。引用报错文本也可能命中，所以不是强制失败门禁。未检测出的任意子进程失败仍不能自动保证，任务完成与其他必要检查沿用原机制。
